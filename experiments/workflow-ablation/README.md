# 工作流消融：先验证量尺，再测模型

> 核实时间：2026-10-10 UTC。评级：🧪 试用。
> **[经验：本地实测]** 此目录只完成离线夹具验证；真实模型试验 **not_run**。
> 新写的标准库 Python 示例，沿用仓库 LICENSE；没有复制外部项目代码、用户数据或原实验日志。

## 这包能回答什么

**[经验：实验设计]** 比较固定任务下 A 无额外项目指令、B 短而有用的测试指令、C 与 B **逐字相同的有用内容**加固定无关文字。A→B 是添加这份短指令包的效果（内容和长度一起改变）；若要单独识别有用内容，需要额外的等长中性条件；B→C 是在保留有用内容前提下添加这份 padding 的效果，不能直接叫“所有长指令的效果”。padding 仍有语义、位置及分词影响；要推广需增加多种中性 padding 和位置对照。

此处只有一个容易饱和的区间归并 bug。它用于验证量尺、发现“已有测试全绿但修复错误”，**不能估计真实项目效率、长程恢复可靠性或历史 E1–E3 的可复现性**。适合先检查评估流程；不适合拿一次通过宣传模型或工作流收益。

## 文件边界

- `agent-input/baseline/`：精确的故意缺陷源代码和 4 个现有测试，每轮从这里新复制
- `agent-input/task.md`：所有条件相同的症状提示及行为契约；没有参考修复
- `conditions/neutral.md`：0 字节；`short.md`：测试命令与回归测试约定；`padded.md`：短版原文 + 80 行无关档案文字
- `evaluator/`：独立维护的固定验收、参考 patch、自检；**不发给被测 agent**
- `PROTOCOL.md`：运行前冻结的设计、计费口径与分析边界
- `results/`：空原始记录模板、JSON Schema、离线验证记录；没有模型实测数据
- `manifest.json`：固定输入及评估文件的 SHA-256；修改后应更换实验版本，不静默替换

**[经验：安全边界]** 目录分开不是权限隔离。同一文件系统上的 agent 可能读到 evaluator、参考答案、其他条件或上级仓库指令；这会污染实验。真实运行只将选定输入复制到独立的受限环境，并在 agent 停止后将候选源码交给可信评估环境。禁止把整个知识库当作被测项目挂载。`python -I` 只是降低 Python 环境污染，**不是沙箱**；评分会执行候选 Python，不能在有凭据或私人文件的环境里执行不可信产物。这里没有实现容器、网络封禁、资源沙箱或抗恶意作弊。它是可信、合作式夹具，不是对抗式安全裁判；任意候选代码可通过 os._exit、猴子补丁等影响同进程检查，不能把通过当成抗作弊证明。

## 离线复现（仓库根目录，Python 3.11+）

```bash
python3 experiments/workflow-ablation/evaluator/selftest.py
python3 experiments/workflow-ablation/evaluator/grade.py experiments/workflow-ablation/agent-input/baseline
```

第二条命令**预期退出 1**：public 4 个测试通过，held_out 套件（7 个测试方法）未通过；这证明 false-green 基线被识别，而不是安装故障。第一条命令预期退出 0：在临时副本精确应用参考 patch，固定两套检查全过；原始缺陷源代码保持不变。具体记录见 [离线验证](results/offline-verification.md)。

评估一个已完成的候选目录：

```bash
python3 experiments/workflow-ablation/evaluator/grade.py /path/to/candidate --timeout 10
```

候选目录必须含 `intervals.py`。评分始终从 evaluator 侧加载固定 public 测试，候选改弱自己的测试不能改变它。held-out 覆盖嵌套、后续相邻归并、负数/重复/同起点、输入不变/迭代器、反向区间异常、超大端点，以及小域 3,616 个有序输入组合的独立集合 oracle。测试方法数不是独立任务数。没有结果、零测试、skipped、语法错误、超时都不能算成功。

## 真实模型试验怎么接入

本包不包含 CLI/API runner，不调用模型、不安装包、不读取账号配置。运行前先完成 [预注册](PROTOCOL.md)，并自行确认调用和费用授权。

1. 新建隔离环境，只复制 `agent-input/baseline/` **内容**为项目根；确认没有继承用户级/父级指令、记忆、技能或先前会话。系统默认提示无法移除时完整记录版本、保持各组一致
2. 将 `agent-input/task.md` 与当轮 `conditions/{neutral,short,padded}.md` 直接拼接，作为唯一用户提示；不额外创建 AGENTS.md/CLAUDE.md。条件是显式提示内容，**不测自动发现/加载指令文件**
3. 保留提示、版本、工具设置、实际执行命令、完整公开可记录轨迹和最终 diff；不记录隐藏思维链、密钥或私人配置
4. agent 停止后冻结候选哈希，在 evaluator 独立环境评分。保存命令、退出码和评分 JSON；debug 时可直接运行 `evaluator/checks.py <candidate> held_out` 获取失败详情。不要把 held-out 失败反馈给同一轮 agent 再修
5. 独立审查新测试：在最终修复上通过，在新的原始缺陷副本上失败，并确认失败为目标行为断言，而非导入/环境失败。记录新增测试数量、准确命令与退出码。不要在原工作树上 stash/revert
6. 每轮完整填一条原始记录，包括失败、超时、超预算与人工介入；保留原始输出。模板里的 null 表示未测量，不能当作 0

**已知限制**：评分没有自动验证新测试质量、编辑范围或过程日志，需要独立审查；没有检测所有作弊；超时只终止当前检查进程，不能替代进程树/内存/网络资源沙箱；有限 oracle 不证明任意整数输入上的数学正确性。参考 patch 只证明本任务有解，不是唯一可接受实现。公开夹具容易被训练或提示污染，正式效果评估应另建从真实失败采样的未见任务。

## P7 窄提示夹具（narrow-exit-contract-v1）

**[经验：实验准备，2026-10-21]** 本项落实[已批准预注册](../../templates/long-task/README.md#3-首项对照窄提示改变退出契约时保相邻行为)，独立于上面的区间题与历史先导。默认先核量尺，再派发真实两轮；目前模型运行 **not_run**，不能据正确参考候选通过宣称提示有收益。此包只检验合成退出契约，不代表真实异步框架。

### 输入和评估分开

- R1 项目根只复制 `agent-input/stream_driver.py` 与 `agent-input/public_tests.py`；唯一需求为 `agent-input/narrow-r1.md`。这是未实现的公开起点，不是参考解。
- R2 每对从同一份 **真实 R1 产物**复制两份（包括实现、模型新增测试、原公开测试与其真实结果），保留失败旧债。输入为共同 R1 与 R2 需求、同一公开结果，再接 `conditions/narrow-a.md` 或 `conditions/narrow-b.md`。A 后缀为空，B 仅多预注册的一句。没有前轮聊天、参考修法或额外工具。
- `evaluator/narrow_*.py`、`evaluator/checks.py`、manifest 和本说明只供准备／评估者；不复制整个仓库、不向模型暴露其他条件、参考候选或留出检查。公开目录分离不等于权限隔离；沿用本页的可信合作式候选限制，不宣称沙箱。
- `narrow-manifest.json` 冻结输入和评估文件 SHA-256。改任一字节须重冻并重新自检，运行开始后不可静默换判据。它不覆盖未来 R1 产物：另存每对 R1 全部文件哈希、公开结果哈希和 A/B 父指纹；人工不能拿参考候选替补失败 R1。

### 独立评分与离线核量尺

```bash
python3 -B experiments/workflow-ablation/evaluator/narrow_selftest.py
python3 -B experiments/workflow-ablation/evaluator/narrow_grade.py CANDIDATE --round r1
python3 -B experiments/workflow-ablation/evaluator/narrow_grade.py CANDIDATE --round r2
```

`CANDIDATE` 是冻结后的候选目录，内含 `stream_driver.py`。评分加载评估侧的固定公开测试，不使用候选自行修改的检查；R2 同时重评原 R1 的正常路径与异常检查。R1 的 Cancel 普通异常检查不计入 R2 继承，因为这正是本轮改变的契约。返回 list、事件顺序、取消前缀、取消后零 next、正常提前返回排空、异常原实例、close 恰好一次均由源事件与独立前缀切片判定；参考实现不参与 oracle 计算。source 的 close 不抛异常，source 不产生 Cancel；不测 close 异常优先级和 handler 捕捉后自行恢复异常。

自检涵盖两轮正确候选、未实现起点之外的错误候选（取消后排空、正常返回不排空、重复／漏 close、吞异常、逆序）、缺文件、语法错误、零测试退出、超时和哈希一致性。正确候选仅为可解性见证，错误候选说明量尺能发现这些缺陷，不是模型成绩。每套件方法数固定，skipped、零测试、错误和超时不得通过。缺文件记 not_scoreable，未知指纹／退出码保留 null，不当作 0。评分仅对子进程设超时，不保证清理候选自行派生的进程，不执行不可信或恶意代码。

### 派发前冻结与收口

1. 由独立审查者审核上述量尺与范围，复跑自检；本夹具自检不自动纳入原 `check_offline.py`，交付时须单独运行，同时跑完整原离线入口。
2. 固定 3 对、顺序 **AB、BA、AB**。每对先独立生成一次 R1，随后按该对顺序执行 A/B 的 R2；共 3 次 R1 与 6 次 R2。固定实际模型、客户端版本及可控的工具、反馈与预算；首次运行前记录每次最大时长与工具／轮数上限，不留“按需要继续”。单次真实作业不得超过现行两小时上限；模型、输入或停止预算未定不得派发。effort等设置不支持或不可观测时如实标记，保持可控配置一致，不猜值或声称隐藏配置完全相同，解释结果时保留该限制。
3. 停止条件是模型最终答复、预先冻结的时限／预算到达或工具失败导致无法继续。全部失败、超时、中断和重试保留；不能只换掉失败对，不给同轮反馈留出错误后再修。R1 失败可继承时原样分叉；缺失／无法读取产物则该对 not_scoreable，保留在全部运行分母，不造出两份参考产物。
4. 每轮停止即冻结代码、测试、diff、输入／产物哈希及公开结果，再独立评分。原 `results/run.template.json` 的字段可复用，但 `task_id` 改为本实验 ID，另明确 round、pair、真实 R1 父指纹和失败／人工介入；原区间题 schema 不冒称已适配本题。
5. 用评分 JSON 的相同 inherited_r1 检查 ID 对照 R1 与 R2：通过→失败为新回归，失败→失败保旧债，缺评分记未知；不要用总体通过数互相抵消。取消后多读或正常返回丢尾部为关键失败。人工修改代码／补事实单列，不能归模型成功。
6. 必要行为全部通过是主要二元结果。完成声明需独立人工从最终答复编码；无输出不当成功，声明分母为零不算比例。所有运行包括失败／超时／不可评分，时间与人工数据未知保 null。至少 2 对失败→通过、其余无反向退步、无新增关键失败且人工补救未增加，才按原预注册考虑调整所测范围的建议；否则如实报差异或未测得差异，不外推模型排名。
