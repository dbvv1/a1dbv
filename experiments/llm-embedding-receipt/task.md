# 把已有存储修复接到当前版本：任务模板

这是从 LLM #224／#1513 的实际接收整理的模板，不是原始生成 prompt。适合已经有真实问题、现成候选和可运行消费者的整合任务；不是要求再造问题或重复投稿。交接仍用项目已有记录，或[通用交接模板](../../templates/generic/.claude/skills/handoff/SKILL.md)。

复制下文并填好真实输入；没有候选或安全的测试数据时，只做定位，不把任务记为实现完成。

```text
目标：接回 <真实 issue/任务> 的已有候选 <固定 head/补丁>，整合到
<当前 main commit>，验明 <实际消费者需要的可观察变化>。

开始前：
- 核原任务、当前 PR 状态/政策及写者；已合并、取消或同题在制先接原结果。
- 在独立目录保全候选与基线。先看原检查适用的源码、依赖和环境，
  再用 apply --check／实际 diff 判断差量，不靠换 SHA 宣称旧结果有效。
- 列出主干新能力及兼容约束；旧补丁中的同名函数不能直接覆盖它们。

先固定契约：
- 哪些字段应改变，哪些必须保留；省略选项究竟是“保留”还是“清除”。
- 唯一标识与缓存键的边界：同 ID 改内容、同内容新 ID、不同集合/模型。
- 新 payload 类型、错误路径、密钥传递等主干接口是否仍需保留。
- 未获产品决定的语义单独记为候选；测试符合候选不代表默认已获认可。

实施与接收：
1. 非作者先用合成输入运行原版实际 CLI／客户端，在真实临时存储中
   保存红灯与通过的负控。每步重新打开存储；别只看 exit code。
2. 实现者独占指定源码，适配候选并补回归；保留主干接口，不顺手扩展缓存。
3. 固定最终源码 tree/文件 hash，停止写入。非作者用同一脚本、新的临时存储
   验候选：字段更新、向量/hash 不变、不重算、其他记录/模型不受影响。
4. 直接失败路径与项目测试、格式、类型、构建按实际规则跑。
   环境缺依赖可按授权修复，再跑受影响检查；不能删失败例、撤代理或换入口
   绕过明确拒绝。单测、stub 和消费者各自说明范围。
5. 交回固定输入、命令/退出值、实际读回、差量、失败与未验项。
   若有发布授权，扫描目标内容并核远端精确版本；否则保全，不外发补丁。

验收：
- 真实数据效果与约定一致，且不变量/负控通过。
- 改变调用总数须解释对应哪条输入；不把次数直接当成本、速度或模型效果。
- 检查失败、能力阻塞、语义待决定、未运行分开写；不能称全部完成。
- 不触碰真实用户数据、真实 provider 账号或生产数据库；不以本模板新增权限。
```

本例的适用边界和实际结果见 [README](README.md)。若要采用“省略即保留”而不是本例候选的清除语义，先改任务契约与测试，不照抄其结果。
