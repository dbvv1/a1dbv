## 为什么正式卡仍 blocked

Click 正式对照因实际读权限不限目标目录而无效。独立目录、浅克隆、空上下文、事后未发现越界都不能替代边界。本次在准备提示与环境接口时就保留阻塞，禁止先运行再补隔离声明。

方向会话在**已有且获准的**独立系统/容器环境验证下列项目，回传脱敏配置与逐项探测结果；本卡不授权安装虚拟化组件、修改用户电脑安全设置或账户凭据。若现有条件做不到，保持 blocked，返回具体哪项失败，不降格后冒充正式试验。

1. 每臂仅暴露该臂独立固定源码、相同 fixture/项目指令、必要工具、依赖和自己的输出目录。两份新环境不得共享 Git 对象、可写缓存、用户 home、会话历史或浏览器 profile；不得挂宿主盘/a1dbv/另一臂/旧补丁。只换 cwd 不算。记录有效挂载、身份/权限策略与工具可访问根，不公开私人路径。另核实际生效的项目/全局指令、插件、skills 与工具清单；两臂相同且无 a1dbv 方法指引/本轮设计上下文。公开仅必要清单与脱敏哈希，不公开私人指令正文；空 home 不能单独证明客户端未注入宿主配置。
2. 调度者在边界外布置**合成无敏感内容**的探测文件，使用与正式模型相同身份和所有文件访问通路核验拒绝读取；包括绝对路径、父目录、链接，以及启用的 shell/文件/MCP/浏览器 file 通路。不拿私人文件测试，不打开真实旧补丁。记录预期/实际/退出码；仅抽查 canary 仍须配合配置审查，不能声称穷尽安全证明。若任一工具能绕到边界外，先关闭该能力或保持 blocked，不能仅靠提示禁止。
