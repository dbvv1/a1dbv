# P79 读者场景题（v1，已独审冻结）

每次只提取一道题分发，页码映射仅供执行者使用。00–22不联网；25使用README规定的共同公开查证预算。


统一要求：对每题提出现在执行的决定；指出影响决定的关键条件和最小核查；写出会让你改变、停止或撤回这项决定的具体观察。缺资料可以明确假设，不必只有一种方案；请避免只列工具名或说“视情况而定”。

### A00-1
团队生成代码比以前快，但审查一批变更需要更久，维护者也越来越难解释实现。有同事主张进一步扩大自动合并，以免人工审查成为瓶颈。下一轮功能开发你会怎样安排 AI 与人的工作？说明你会用什么结果判断是否继续扩大范围。

### A00-2
开发者今年上半年试过编码 Agent，因为修好新问题后旧问题经常回来而停用。现在看到新一代产品的演示，想知道是否应恢复使用。现有项目运行正常，下月还要做一次业务规则变更。你会直接恢复、继续不用，还是怎样重新尝试？哪些观察足以改变你的决定？

### A00-3
一个小团队的演示版可以正常运行，绝大部分代码由 Agent 写成；开发者担心服务中断时自己无法修复客户问题。两周后希望交给首批使用者。你会怎样决定当前可交付范围与准备顺序？怎样判断应推迟或缩小交付，而不是继续增加功能？

### A01-1
开发者在两个 CLI 编码工具之间犹豫：一个初版更快，另一个生成的变更较容易审查。当前任务同时包含数据库迁移和界面调整；现有工具没有严重故障。如何选择下次实际工作的入口？哪些条件可能使你保留现状、分工使用或迁移？

### A01-2
一项修改可在普通仓库中完成，但最终验收必须读取公司 VPN 内的服务，并操作接在开发者电脑上的设备。开发者希望合上电脑后任务仍继续，因此考虑改用云端编码环境。你会如何分配执行与验收，迁移前核查什么，何时放弃该迁移？

### A01-3
当前 CLI 能完成单个任务，开发者主要不满多个会话和分支难以管理。他发现一个新桌面应用，宣传可以管理并行工作区，也支持同一个模型。是否应把项目迁过去？请给出一次足以判断的试用安排及撤回点。

### A02-1
同一项实现任务连续耗完两个订阅使用窗口仍未完成。记录显示普通输入与输出不多，但缓存输入很大；代码已有局部修改。下一次额度恢复后，你会怎样继续，并怎样判断应该改模型配置、改执行方式还是暂停？不能假设已知服务端如何把 token 换算为额度。

### A02-2
项目中途实际使用的模型和推理档位发生变化，随后花了若干轮修复。管理者把客户端累计 token 全部乘以 API 输出单价，宣布这次切换造成了相应现金损失。你会怎样报告本次代价、评估是否恢复原配置，并指出还需要什么证据？

### A02-3
团队准备把一个收费模型替换成更便宜的模型。主要工作是生成公司自定义 DSL，现有公开排行榜主要测常见编程语言。现有系统能自动检查语法，但语法正确的程序也可能表达错误业务规则。你会怎么决定是否替换，什么结果会使你恢复旧模型？

### A03-1
在一个已有大量历史对话的会话中，开发者只要求修复选中状态动画的瑕疵，不改变原本效果。自动压缩之后，Agent 做出另一种没有瑕疵但视觉概念不同的效果。下一次相似小修改你会怎样提供与保留上下文？什么证据说明你的办法无效？

### A03-2
开发者停用了几个不常用的 Skill，期望减小每次任务的上下文。但上下文统计仍显示这些 Skill，占用与之前相近。你会怎样判断接下来该改哪里？请说明保留、移除或重新组织配置的条件，以及如何判断改动真的有益。

### A03-3
团队为减少遗漏持续扩充项目规则和设计说明，但仍发生旧 bug 回归。下一项任务仅涉及一个模块，同时有一项近期临时约定不能丢。你会为这次任务怎样安排输入信息和后续会话？什么结果会让你撤回这个安排？

### A05-1
某个 Skill 已安装，在管理界面中显示启用；开发者用普通语言发出对应任务时，Agent 却走了通用工具路径。一次子任务又似乎知道这个 Skill。你会先改 Skill 文案、重装插件、换模型，还是采取别的步骤？请说明判定依据和停止条件。

### A05-2
一个 Skill 应查询已连接服务并列出结果。调用后返回“完成”，正文却只解释这个 Skill 的用途和步骤，没有目标查询结果；同一会话直接调用服务工具可以得到数据。你会怎样处理当前任务及这个 Skill，何时恢复使用它？

### A05-3
团队想把一个主会话中可用的 Skill 放到子 Agent 流程里。有人认为子 Agent 没有声明继承它，所以既不会读到，也不可能使用它。你会怎样设计迁移验收，确认它既能完成工作又符合团队要求？什么结果要求调整或停止迁移？

### A07-1
一个功能已按长篇规格完成大部分，剩下少数错误要反复提示，修复时还会重新引入此前解决的问题。明天只需交付其中一条完整用户路径。你现在怎样组织剩余工作，哪些检查决定继续修补、改变方案或撤回变更？

### A07-2
Agent 能快速给出大型变更，但开发者发现自己必须从零理解，审查耗时远超预期。下一项功能涉及三个紧密关联的模块。请设计下一轮工作方式，说明拆分或不拆分的理由，以及如何知道新方式只是增加步骤而没有收益。

### A07-3
开发者让 Agent 连续实现一项界面改进。它最初正确理解“保留原来效果，只修视觉瑕疵”，执行中发生上下文交接，最后测试通过但呈现了另一种效果。开发者准备加上“持续修改直到所有测试通过”的循环。你会采用该方案吗？请给出替代或有条件采用的完成判定与撤回点。



### B08-1
三个已完成的PR都修改同一服务的接口与对应调用方，分支各自测试通过。明天要合入。你可以让多个Agent同时处理，也可以顺序处理。请给出交付安排，说明开始任何修改前还需确认什么，以及哪些观察会让你改变安排。不要以“并行更快”或“有冲突就串行”代替具体决定。

### B08-2
主会话能读取一份临时工作树，派出的执行者却读不到；界面显示该目录已加入工作目录。任务是修两处独立错误，用户没有要求改变安全设置。你如何继续？给出定位与交付的最短合理路径，以及恢复委派前要见到的证据。

### B08-3
一个Agent完成隔离工作树里的改动并交回“测试通过”。随后主会话的pwd位于该工作树，而它刚被自动清理。还有两个任务未派发，计划中引用原主分支接口。你下一步做什么，怎样处理已完成结果与未执行计划，何时能恢复后续工作？

### B09-1
功能通过既有测试。第一轮评审发现会丢数据的错误，修复后第二轮指出新修复改变了取消操作的语义，第三轮只有命名建议。项目今晚交付，你有两小时。你怎样决定继续评审、修改或接收？请交代评审对象如何固定、什么算已关闭的问题、什么条件触发再审或暂停交付。

### B09-2
评审命令返回“Failed to start code review”；CI绿，Agent报告“没有发现问题”。仓库只有main，本次更改未提交，但有可读的工作区diff。如何解释当前状态，选择下一步评审方式，并决定何时可接收？不能依赖安装新产品解决。

### B09-3
补丁修好登录失效问题，所有测试通过。diff同时删掉了一个异常分支，并把失败登录测试的断言改成接受空用户；作者解释“这是更健壮的降级”。产品负责人尚未决定失效登录是否允许访客访问。今天应如何推进评审与交付，什么证据会改变你的决定？

### B14-1
同一团队要做两项工作：给稳定的导出功能加一种格式，规范与回归样例齐全；另一个是让搜索结果“更让用户信任”，团队对呈现和排序尚无共识。现在可用同一个强Agent。你会给两项任务相同自主范围吗？分别给出首步、人的介入点与扩大/收回范围的依据。

### B14-2
团队原有流程能稳定交付，新的端到端自动化方案展示了一个漂亮原型。业务负责人希望这周把整个产品交给它。你可以批准全量替换、局部试用或保留现状。请做决定，并指出你最需要哪几类信息，以及什么结果会使你反转这个决定。不要只回答“先做小实验”。

### B14-3
两种方案均做出同样功能。A生成代码快，但每次要你解释旧数据兼容问题；B较慢，会主动调查现存格式并报告未决事项。下一阶段要连续做五次需求修改，没有历史维护数据。你现在如何分配工作和验证投入？给出可推翻你选择的证据，不得把单次速度或谨慎措辞当质量结论。

### B15-1
喂宠提醒应用第一版正常。第二个需求是允许一项提醒临时跳过今天，但保留未来重复计划。现有用户已建立时区不同的提醒，部分设备离线。你如何让Agent实施这次修改，最少需观察哪些旧/新行为，什么结果会让你撤回实现？

### B15-2
客服面板功能无报错，但用户说“找不到下一步处理什么”。Agent提议改前端框架、重做颜色和增加统计图。你只有两天，不打算先迁移系统。怎样选择第一轮改进、衡量是否有效、决定是否保留？允许最后保留现状，但必须解释证据。

### B15-3
一次性脚本能把CSV导入数据库，试验数据全部成功。现在同事希望每晚导入真实客户数据，第二天可继续处理失败项。原脚本遇到网络超时会从头运行。你会如何改变任务要求与实现顺序？什么完成证据允许上线，什么情况必须撤回为人工运行？

### B20-1
长任务中会话压缩失败；两次resume都挂起，但工作区有改动和一份昨天的进度文件。最后一次测试是否完成不明。如何恢复到可继续修改的状态？列出新会话第一次写操作之前需要核实的内容，并说明何时停止尝试旧会话。

### B20-2
用户明确恢复一个之前暂停的目标。进程持续输出“仍暂停”，没有工具调用或产物变化。你负责运行监督，不能修改模型内部。怎样处理当前运行并设计下一次继续条件？请区分暂停、无进展和已完成，给出停止及重新启动的可观察依据。

### B20-3
Agent调用外部接口创建发布记录后超时，本地只收到“响应未完成”。重启时进度文件仍标记该步待做，外部服务支持按项目和版本查询记录，但不支持回滚。你如何继续、如何判定这一步的状态，什么条件下才允许再次创建？后面的通知步骤也尚未执行。

### B22-1
你比较旧配置A和新配置B。六个任务每种各试三次，B展示的最佳一次更快；A有18次完整记录，B只保存了每题最佳结果。团队今天想切换。请给当前决定、下一轮最小可解释比较、要记录的成本及质量边界，何种结果支持推广或撤回。

### B22-2
为挑选一个评审Skill，你用十个历史PR反复改提示词，最终漏报最少。终评仍用相同十个PR，同一个模型同时产出与打分。团队打算声称它提升了评审质量。你会怎样处理这个结论，并安排下一步验证？指出哪些结果支持保留，哪些足以停止投入。

### B22-3
产品目前无失败，新流程声称提高可维护性。当天功能验收和视觉检查两组都通过；新流程多花40%模型费用但少了30分钟人工检查。没有做后续需求修改。负责人问“到底值不值得”。请给一个现在能执行的决定和下一轮评估设计，区分已知与未知，说明何时推广/撤回。

### B25-1
你要管理约800册无ISBN的实体刊物：拍封面、记箱/架位置、加自定义字段；希望日后可搬家换工具。现在只考虑个人使用，不要求电子书阅读。请在给定联网预算内实际查找现成方案，给出一个首试方案及一个有意义的替代，说明依据、仍未解决的条件和停止搜索的理由。不要只列熟悉名字或写调研计划；如果预算内无法支持首试，给出可执行的暂缓与下一步。

### B25-2
一个小团队已用WordPress发布旅行优惠，并按出发城市选择Mailchimp受众，还需发布到一个尚未选定的社交平台。目标是减少重复编辑，不要求今天无人值守。现有少量Selenium脚本。请在给定联网预算内查证至少两条不同实现路线，选择先自动化哪一段及保留什么人工步骤，提交证据与停止/撤回条件。不得创建账户、接入真实名单或实际发送。

### B25-3
你想为技术调查找到不常出现在大搜索引擎首页的小站原文，但又不想因此漏掉重要技术事实。先在首次搜索前写下当前已知候选／来源（可为空），再在给定联网预算内找到可实际尝试的搜索方式，并用“无ISBN实体收藏的目录管理”做一个小型查证：展示一个检索前未列为候选的相关来源，以及它如何改变或不改变选择。最后决定是否把这种方式加入日常工作，写明证据不足与停止条件。不是寻找声称“完全无广告”的唯一赢家。
