# 长回合综合编码任务：短目标＋真实运行反馈，还是完整多步计划＋分工？

状态：2026-11-26 方向裁决启用为主试提案（替代过窄的 `platformdirs` 单步题）；尚未运行模型，待本机方向会话锁定具体公开开源任务 SHA 后启动。

**假设。** 对于必须跨越源码修改、重新构建并在真实界面／终端交互验收的长回合任务（而非单一单元测试即可判定的窄 bug），给强模型清晰目标、不可破坏边界与真实运行反馈入口后直接迭代，其首轮端到端通过率、返工轮次与总 token 消耗优于套用繁重的多步前置计划与多子 Agent 分工。

| 组别 | 给执行者的流程约束 | 两组固定 |
|---|---|---|
| **甲（轻基线）** | 一段短目标说明（要修/要做的结果＋必须保留的既有行为＋真实构建与运行验收命令），不要求先写多份计划文档或拆派子代理，按真实运行反馈直接迭代修正 | 同模型、同 effort、同速度档、同客户端版本、同仓库隔离克隆基线 SHA、同外部工具权限、同一真实构建与浏览器／CLI 验收命令；单臂上限 90 分钟 |
| **乙（完整流程）** | 沿仓库既有结构化长程流程（先书面探索／计划／规格对齐，或按分工派发只读调查／独立复核子代理后再实现与整体验收） | 同上；两组串行交错或独立克隆隔离执行，严禁参考另一臂结果或上游修复提交 |

## 选定公共任务与预检条件

1. **选题标准**：由本机方向会话从近期活跃开源项目中选取 1 项需跨越至少 2 个模块（如状态管理＋UI 交互或 CLI 配置＋真实构建产物）的未修／修复前固定 SHA 任务，必须满足：
   - 本机可从零冷启动构建并触发原缺陷（无人工登录或私有密钥阻塞）；
   - 存在明确且客观的端到端运行／交互验证方式（如真实浏览器操作断言、真机渲染输出或真实 CLI 端到端进程输出）；
   - 不与上游修复提交或任何解答混在同一检出中。
2. **精简预检**：仅验证一次“隔离检出干净、基础构建通过、原问题确实复现”即开跑；**不再在提案文档中为假设故障无限叠加额外前置防御脚本**。

## 评判与成本核算口径

由未参与生成的盲评人对照固定验收基线逐项打分（不看组别标签）：

- **真实交付门（必过）**：原缺陷真实修复、既有相关测试与构建全过、无新增控制台/运行时报错、原有关键兼容行为未破。
- **综合成本对照**：分别记录首次提交是否一次通过、最终达到可交付的总墙钟时间（含等待与人工介入次数）、总返工轮次，以及含缓存写入／子代理调用在内的实际用量与 API 估算费用（拿不到实扣记未知）。
- **结论边界**：单题配对结论仅用于校准本仓推荐工作流与 [07](../../docs/07-workflows.md)／[08](../../docs/08-multi-agent.md) 的按缺口启用边界，不把单题分数外推为所有团队和任务的最优默认值。
