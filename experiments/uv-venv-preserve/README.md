# uv 已有虚拟环境目录：保留选项不保留链接目标

🧪 **Agent 创建测试环境遇到已有非空目录时，先换一个属于本任务的新目录，不把 `--allow-existing` 当作“原文件不会变化”。** 本例 0.13.6 和 0.13.8 的该选项会沿已有 `bin/activate` 文件链接写入目录外目标；虚拟环境 Python 与仓库检查仍全部成功。链接目标与虚拟环境同属本次临时工作区，未越过平台允许写入的根；目标只在本次临时父目录里，内容为合成哨兵。

适用于目录来源或既有内容不明、希望保留原工作副本的测试环境准备。已核清内容且确实要覆盖生成文件时，可按该选项的原契约使用；这不是权限隔离、恶意目录防护或新的沙箱配置。新目录对照不修改旧目录，也不执行 `--clear` 删除。

## 实际结果

| uv | 默认已有非空目录 | `--allow-existing` | 新独立目录 |
|---|---|---|---|
| 0.13.6 | exit 2，哨兵未变 | exit 0，哨兵被覆盖，链接保留 | exit 0，旧哨兵未变 |
| 0.13.8 | exit 2，哨兵未变 | exit 0，哨兵被覆盖，链接保留 | exit 0，旧哨兵未变 |

独立复跑补核：默认允许已有空目录，本例拒绝的是非空目录；`--allow-existing` 保留不冲突的普通文件，不是清空全部内容。

两版的两条成功路径均真实运行新环境 Python，并执行本仓 `scripts/check_repo.py`，4/4 退出 0。新目录路线因此可完成本次仓库内容检查，同时保留原目录旁的测试数据；不能用“环境建成、检查成功”推断原内容未变。`venv_prefix_differs` 只核 Python 前缀不同，不代表安全隔离。运行环境是 Linux x86_64、CPython 3.12.14，无模型调用、无 Windows 验证。

## 复跑

在本仓根目录，先用已有可信安装的 uv，或从官方 PyPI 准备指定版本。脚本不安装软件、不联网；只在新临时目录内创建可丢弃合成内容，输出归一化结果：

```sh
python3 experiments/uv-venv-preserve/probe.py uv > /tmp/uv-venv-result.json
```

输出先写仓库外，完成后再复制结果回来，避免仓库检查扫描到重定向刚清空的 JSON。此探针刻意断言两版已观察到的覆盖行为，后续修复版行为不同会失败，不能将它作通用安全门禁。

首次运行使用默认 cache 位置不可写，在进入目标行为前失败；改为本任务临时 cache 后才得到表中结果。首次将报告直接重定向到仓库内，检查发现尚未写完的 JSON，修正报告输出位置后复跑通过。这两次失败不计为 uv 行为通过。
