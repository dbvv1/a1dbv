# 实际验收耗时太长：先隔离两个重阶段，再扩大并行

**🧪 本仓窄试可用：把现有离线检查分给两个固定版本副本，不改原测试与通过门槛。** 同一提交四轮全部通过20阶段、每轮475次测试执行；串行中位39.61秒，双worker中位21.36秒，含副本准备和清理，耗时约少46%。这改善的是一次仓库验收等待，不是dot整项任务的吞吐或模型质量。

## 解决哪一个真实卡点

本仓长任务在接收子代理改动后，仍须跑整合验收。现有 [`check_offline.py`](../../scripts/check_offline.py) 逐阶段串行；本轮测到 general 与 catalog-compare 两个互不重叠的测试组分别约18秒、16秒，占了主要等待。现有分组用于控制单阶段时限，尚未并行执行；本实验复用它，不再拆测试、加模型、建调度服务或改CI。

**读者可以照做：** 需要核已提交候选、检查主要使用临时文件且没有共享外部服务时，先试两个worker。每个worker用独立检出目录及TMPDIR，原套件在进程内仍按原顺序执行。协调者可继续独立工作，拿结果时核 `source_sha`、全部阶段和失败项；之后源代码又变了，旧结果不能转作新版本通过。

```bash
# 从仓库根目录运行；输出目录必须尚不存在。
python3 experiments/parallel-offline-validation/trial.py \
  --repo . --revision HEAD --jobs 2 --output ../offline-two-workers

# 对照：同一revision，串行阶段；准备与清理同样计时。
python3 experiments/parallel-offline-validation/trial.py \
  --repo . --revision HEAD --jobs 1 --output ../offline-one-worker

# 本实验自身的正常、失败、缺输入回归。
python3 -m unittest discover -s experiments/parallel-offline-validation -v
```

**只测已提交版本。** 脚本先解析指定commit，复制Git对象并固定检出，不复制源工作区的未提交或未跟踪文件。若任务交回的是未提交补丁，应继续使用原验收入口，不拿此试验的结果代替当前编辑树验收。

结果目录保留各阶段日志及 `result.json`。任何阶段失败，停止领取余下阶段，收齐已在执行阶段的结果，再整体失败；不会将未运行部分算通过。阶段超时沿用原120秒上限并终止所属进程组。CLI 收到 SIGINT／SIGTERM 时停止领新阶段，终止正在执行的阶段或 Git 准备命令所属进程组，等待 worker 退出后删除临时副本；分别以 130／143 退出，保留已有阶段日志，不把中断写成通过。输出含测试次数、未运行阶段和检出目录的已跟踪文件变动检查。

## 外部中断清理补验

**中断处理要覆盖准备命令和两个执行中的 worker，不能只处理阶段超时。** 2026-10-28 在 Linux／Python 3.12.14 上，用临时 Git 仓库中的合成检查启动两个阶段，各自再启动一个同进程组子进程；从外部向 CLI 发送真实信号。原代码取自 `ffc720bc`，信号后观察 0.5 秒再由测试端清理，未放任遗留进程。

| 路径 | 原代码观察 | 修复后回归 |
|---|---|---|
| SIGTERM | `Popen.returncode=-15`；2 个阶段、2 个子进程仍运行，临时副本遗留 | 入口退出 143；阶段及同组子进程停止，临时副本删除 |
| SIGINT | 入口仍在线程池等待；上述进程与副本仍在 | 入口退出 130；阶段及同组子进程停止，临时副本删除 |
| Git clone 准备期间 SIGTERM | 未作旧版对照 | 准备命令及同组子进程停止，临时副本删除 |

新增的 CLI 测试还核正常结束、阶段失败、超时后的清理，以及信号撞上结果写入时不会留下通过报告；原有失败停止领取、收齐在途结果、缺输入和套件摘要门槛保留。当前实验自身 **16 项回归通过**，中断用例设 5 秒测试超时，未测客户端终止云电脑或操作系统强杀。原四轮性能结果保持原样，不将本次清理修复包装为新加速结果。

## 何时不适用

- **共享HOME、固定端口、数据库、外部服务或会话状态的检查，不直接并行。** 本脚本只隔离检出目录与TMPDIR；两worker也不是最多两个OS进程，测试仍能启动子进程。对于这些共享资源，保持原生工具的分组或串行路径。
- 这是两次串行、两次双worker的本机观察，不是统计显著性结果。繁忙机器、内存紧张或更大的候选，收益可能下降；默认CI是否值得改还需独立决策。本次没有执行模型、浏览器、游戏引擎或hosted CI。
- 超时与 SIGINT／SIGTERM 清理只覆盖正在执行命令的所属进程组，不覆盖主动脱离进程组的后代、已结束阶段留下的后台进程或 SIGKILL／宿主消失。测试核的是进程停止；孤儿僵尸进程的最终回收仍由系统负责。实验不是安全沙箱或长期任务宿主。

## 与更强替代比较

**已有原生并行器就先用它；本仓是多入口unittest／shell检查，所以先复用阶段边界。** pytest-xdist提供按文件、scope和group分发及worker上限，比手写一个通用测试调度器更完整；本次没有将本仓迁移到pytest，也没有证明自写入口比xdist更快。pytest官方的并行flaky说明强调未隔离状态与测试顺序；本轮因此采用独立副本，而不是让两个检查器同时改一份工作区。中文社区的worktree原帖还提醒：未跟踪资料不会自动随新检出出现，因此本入口明确只核已提交树。
