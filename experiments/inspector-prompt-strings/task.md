# 可复制任务：把 prompt 字符串原样交到 MCP 服务

**用于有明确参数损坏问题的两个 CLI 入口；先验证真实 wire，再决定是否可发布。** 下面是本次试验之后整理的实施任务，不是已执行对话的逐字稿，也不保证运行环境能完成全部门禁。

```text
在独立云工作区处理公开问题：
https://github.com/modelcontextprotocol/inspector/issues/2859
最终让普通命名 prompt 参数的值，从 shell 处理后的 argv 到服务端保持原样。

先读最新 issue、项目指引与投稿政策，确认未被修复、没有同题在制写者。
本次实测基线是 4fe3d9cc5db17367e9e645ee05f707daf154267e；
若当前代码变了，重核相关差量，不直接把旧结果贴到新版本。
不代维护者 triage，不发外部 PR、diff 或评论。

保留的契约：
- one-shot CLI 和 mcpdo 的 --prompt-args 都只按第一个 = 拆分。
- key 必须非空且有 =；value 可以为空，不 trim、不 JSON 解码。
- 保留后续 =、空白与 argv 中实际存在的引号，重复 key 仍以后值为准。
- metadata、tool-arg 的 JSON 类型及非有限数拒绝不变。
- 不改变程序化 getPrompt 对已有 JsonValue 调用者的兼容转换。
- 不捆绑 tool-args-json 溢出或特殊参数键的既有问题；发现时保留控制结果。

主线保留共享决定和最终验收；需要分工时，只拆独立入口。
共享 parser 一位写者，两个入口各自明确写域和对应回归；
接回后核 diff、实际运行输出、受检版本及写者停止，再整合。
没有独立子任务就串行，不为角色数量拆工。

先跑原版，再用完全相同输入跑最终构建产物：
1.50、0.10、1e3、9007199254740993、1e400、-0、true、null、
带空格的 JSON 文本、字面引号、空字符串、空白、Unicode、a=b=c；
另测多参数／重复 key、缺 =、空 key，及 tool 数字／布尔仍为 JSON 类型。

真实消费者启动 built CLI 子进程和 stdio MCP 服务；
同时核服务端收到的参数和 CLI 输出，不能只 import runCli 或测 parser。
为每轮创建独立 HOME、配置和连接状态，服务只处理合成数据。
mcpdo 若列入已验证范围，必须另跑其真实连接／daemon 路径；
权限拒绝即停对应动作，不能用 mock 结果代替，也不更改权限绕过。

跑项目要求的检查。零测试、skip、失败、未运行分别记录；
失败时保留输出，在未改原版核同一路径，不直接归因环境或放宽门槛。
在最终固定树上让非作者做协议消费者和独立审查。
完整 gate 未过就保留候选和可恢复源码，不写成可发布修复。

交付：基线与候选版本／构建哈希、实际差量、同输入前后结果、
所跑检查与退出状态、剩余失败及恢复条件。
只发布经过扫描且获准的材料；原始本机路径／环境日志不公开。
不要把本模板冒充上游要求的“实际使用的生成 prompt”。
```

实际采用边界与失败见[结果](README.md)，该模板没有绕开项目门禁、贡献政策或读者门槛的权限。
