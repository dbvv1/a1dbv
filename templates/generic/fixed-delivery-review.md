# 固定交付的独立接收起点 🧪 试用

让原实现者保持唯一写者，按需让独立审查者检查固定产物。适合已有长任务交付、需要核重放或批量统计的项目；几行明确修改不必套此模板。无需安装新 Agent 平台，也不把源码审查和执行测试拆成多个重复审查。

## 交给审查者的输入

填好下段，连同现有 [code-reviewer](.claude/agents/code-reviewer.md) 正文交给新上下文；已有有效审查只交新增或修复差量。这里只提供任务输入，不要求修改目标仓库的 Agent 配置。

```text
审查对象：<仓库、完整固定 SHA、与基线的差量>
原需求：<任务／brief 的固定版本和验收目标>
唯一写者：<已有实现任务>；本次仅审查，不修改或发布产品。
执行位置：<隔离的检出目录>；测试允许写缓存／构建产物，不共享写者工作树。
现有审查：<已发现问题、修复范围、可复用检查；无则注明无>
正常消费：<安装、测试、最小一次运行的真实命令>
重放输入：<种子、完整命令序列或录制文件、版本、真实重放命令>
预期：<需求定义的终局／胜负条件、哈希来源和算法；哪些仅为作者实得>
异常消费：<已有失败样例与回归入口；没有样例则检查真实异常路径，不造产品故障>
批量证据：<每局状态、总数／失败数、统计口径、目标及实得偏差>
输出：通过／需修改／审查未完成；问题给文件行号、证据、最小复现。
缺输入只停依赖它的验证，其余继续；不从“零发现”推断测试通过。
```

## 接收顺序

1. 核固定提交确实可取、需求适用，检出到独立目录；保留原分支和其他写者成果。源码与依赖未变的已有检查可复用，不因 SHA 换名全部重跑。
2. 先读项目命令和依赖脚本，再按现有授权安装并运行最小测试／正常消费。每条运行记 UTC 起止、完整命令、退出码和日志位置；失败或中断保留原日志，从最后一个完成步骤恢复，不把等待算执行。
3. 有重放功能时，以同一固定版本、同一种子和同一完整输入分别运行两次，对照状态哈希与终局事实。仅同 seed 的两次随机机器人对局、stdout 文件哈希或自带 checker 的绿色摘要，不能替代输入回放与胜负断言。
4. 核异常、超时、未终局是否计入总样本；目标差距与异常分开报告。修复由唯一写者完成，审查者只复核受影响差量，不扩成全新审查。
5. 实际消费者回传：采用了哪项输入／检查、改变了哪个判断或实现、集成结果与返工，以及没验证的项。仅模板合入或范围同意不算采用。

## MOBA-Like 首轮接入

已公开的命令契约是 `npm ci`、`npm test`、`npm run sim -- --games <N> --seed <S>`。固定源码到达后先 1 局，再按 brief 跑 200 局；镜像对称另按多个种子累计至少 500 局。具体 replay 命令、输出字段和哈希算法等源码公布后再填，不能从 CLI 名字猜接口。

| 要核的事实 | 接收证据 |
|---|---|
| 同 seed＋同命令确定性 | 两次真实回放的输入、终局哈希及胜负；源码核哈希覆盖范围 |
| 终局有效 | 基地毁灭／终局条件的独立断言；超时与未终局单列 |
| 批量目标 | 0 异常与卡死、8–12 分钟中位数、高难对低难至少 80%；各自实得与样本定义 |
| 镜像对称 | 多种子至少 500 局、阵营口径；蓝方胜率的 95% 置信区间应覆盖 50%，200 局不充数 |
| 技能统计 | 每技能施放、命中、伤害及分母；不要只看总胜率 |

首轮独立审查已发现的快照引用泄露、死亡小兵清理、未知回放版本接受，应接原修复回归，不再造另一套模拟。无画面验证不涵盖浏览器或手感。

**核实与状态**：2026-10-25，依据 [MOBA-Like brief](https://github.com/dbvv1/MOBA-Like/blob/c66f250f817b1ad7357088cba12f6ad30c83b8c8/docs/brief.md)、[B 原任务](../../docs/collaboration/local-jobs/B-MOBA-SIMULATION-001.md)及 [A 接收约定](../../docs/collaboration/local-jobs/A-CROSS-MODULE-SELECTION-001.md)。初版接收起点形成时尚无固定源码；现既有 reviewer 已获 B 的真实采用反馈，新 JSON 接收器已由 A 消费真实报告。采用归属与运行范围见下节及 A 接收约定。


## 对真实批量 JSON 加一个接收检查

生产者 CLI 退出 0 不一定表示目标达标。MOBA 接收可用 [check_moba_batch.py](../../scripts/check_moba_batch.py)，只读纯 JSON，显式指定局数、种子和内容版本；不加载产品源码、不执行引擎，也不修改 B 的 CLI。

```bash
# 在已获准的产品检出中保存真实报告；同一 shell 内保留这个目录变量。
REPORT_DIR="$(mktemp -d)"
npm --silent run sim -- --games 200 --seed 1 --content-version 2 --json > "$REPORT_DIR/report.json" 2> "$REPORT_DIR/report.stderr"
printf '%s\n' "$?" > "$REPORT_DIR/sim-exit-code.txt"
# 同一 shell 切换到本知识库根目录后接收：0=适用检查通过，1=目标失败，2=无效输入。
python3 scripts/check_moba_batch.py "$REPORT_DIR/report.json" --games 200 --seed 1 --content-version 2
```

检查覆盖分母完整性、终局、异常、卡死、抽查回放和时长中位数；输出明确未查 500 局多种子对称、难度胜率、技能统计和独立引擎重放。少于 200 局只算所请求的小批次，不能代替完整基线。它核报告字段而非证明报告真实；仍保固定 SHA、原命令和日志，并读源码核字段定义。
