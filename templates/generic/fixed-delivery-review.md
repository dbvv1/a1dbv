# 固定交付的独立接收起点 🧪 试用

让原实现者保持唯一写者，按需让独立审查者检查固定产物。适合已有长任务交付、需要核重放或批量统计的项目；几行明确修改不必套此模板。无需安装新 Agent 平台，也不把源码审查和执行测试拆成多个重复审查。

## 交给审查者的输入

填好下段，交给能独立检查产物的新上下文；可按需加上 [code-reviewer](.claude/agents/code-reviewer.md) 正文。复制到其他项目时，保留两份文件的相对路径，或直接复制下段提示，不改目标仓库的 Agent 配置。已有有效审查只交新增或修复差量。

```text
审查对象：<仓库、完整固定 SHA、与基线的差量>
需求依据：<产物原任务与当前适用 brief 的固定版本；变更时说明哪些要求已替换>
结果分类：<硬安全／正确性断言；渐进校准指标；当前阶段合入条件>
唯一写者：<已有实现任务>；本次仅审查，不修改或发布产品。
执行位置：<隔离的检出目录>；测试允许写缓存／构建产物，不共享写者工作树。
现有审查：<已发现问题、修复范围、可复用检查；无则注明无>
正常消费：<安装、测试、最小一次运行的真实命令>
复用筛选测试核必跑清单；分片 CI 按同次运行的预期矩阵核环境、分片编号、实际产物与原测试任务结果。缺项记未验，不以合并报告通过代替。
需要重放时：<种子（若适用）、完整输入或录制文件、版本、真实重放命令>
预期：<需求确定的行为与产物；若核重放，说明终态与哈希覆盖范围>
异常消费：<已有失败样例与回归入口；没有样例则检查真实异常路径，不造产品故障>
需要批量时：<每项状态、总数／失败数、统计口径、目标及实得偏差>
输出：硬断言通过／失败／未验；校准已达／未达／未验；阶段可接收／需修改／证据不足。
问题给文件行号、证据、最小复现；校准未达不自动等于拒收，也不豁免新增异常。
缺输入或工具只停依赖它的验证，其余继续；逐项列未验检查、阻碍证据和恢复条件，不从“零发现”推断测试通过。
```

## 接收顺序

1. 核固定提交确实可取、当前需求适用，明确硬断言与校准目标，检出到独立目录；保留原分支和其他写者成果。源码与依赖未变的已有检查可复用，不因 SHA 换名全部重跑。
2. 先读项目命令和依赖脚本，再按现有授权安装并运行最小测试／正常消费。每条运行记 UTC 起止、完整命令、退出码和日志位置；失败或中断保留原日志，从最后一个完成步骤恢复，不把等待算执行。
3. 有重放功能时，以同一固定版本、同一完整输入及相同种子（若适用）分别运行两次，对照真实终态与状态哈希（若有）。重复随机输入、stdout 文件哈希或自带 checker 的绿色摘要，不能替代完整输入回放和产物断言。
4. 核异常、超时、未终局是否计入总样本；硬断言失败、校准差距与阶段接收决定分开报告。修复由唯一写者完成，审查者只复核受影响差量，不扩成全新审查。
5. 实际消费者回传：采用了哪项输入／检查、改变了哪个判断或实现、集成结果与返工，以及没验证的项。仅模板合入或范围同意不算采用。
