# 会话交接

优先更新任务已有的交接记录；没有时，单任务可用根目录 `PROGRESS.md`，并行任务使用 `tasks/<task-id>/PROGRESS.md`，不要互相覆盖。当前摘要可替换，历史验证证据保留或版本化。先确认记录对应当前任务，再写入：

```markdown
# 进度（更新于 <日期时间>）

## 目标
<一两句话，链接到 SPEC.md / Issue（如果有）>

## 身份与恢复检查
- task/run ID、spec 版本、最新约束和已被替换的要求
- 仓库/分支/base commit、当前 commit、未提交改动标识
- 待授权动作、未知结果的外部操作、待收集的 worker/job
- 恢复时先核对上述状态；未知的外部结果先查询，不盲目重放

## 验证完成的工作
- <做了什么> —— 证据：<验收 ID、适用版本、测试命令和结果/工件>

## 进行中
- <正在做什么，做到哪一步>

## 关键决策与原因
- <决策> —— <为什么；放弃了哪些方案>

## 已知问题和坑
- <新会话最容易再踩的坑>

## 下一步（按顺序）
1. ...

## 常用命令
- 构建 / 测试：`...`
```

要求：
- 只写**新会话需要、而且从代码和 git log 里看不出来**的信息。
- 已完成的项目必须附证据；没有验证过的写进“进行中”。
- 验证后代码变化时，不沿用旧通过结论；区分失败、未运行和阻塞。
- 记录授权范围，不保存凭据，不把交接文件当作新增授权。
- 写完后告知实际记录位置；用户选择清空上下文或换会话时，可先读该文件继续。不要为写交接强制结束正在推进的任务。
