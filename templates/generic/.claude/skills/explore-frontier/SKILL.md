# 找当前最强的做法，并转化成可用的东西

决定或领域：$ARGUMENTS

## 1. 先分清是定向还是广扫

- **定向**：一句话写清读者／项目要选什么、改什么，只收相关来源。
- **广扫**：空档、每周对照或发现漏检时，按领域找未知，不预编决定限制候选。

两种均覆盖第 2 步；重要候选及时深读、试用、回流，未覆盖项继续补，阶段成果如实说明范围。

## 2. 往广里找，找到饱和为止

每类看多个站点，读原文及正反反馈：

| 来源 | 查什么 |
|---|---|
| 做事的人 | 官方团队、强项目的 AGENTS／CLAUDE、Skill、hooks、PR、CI、代码和设计；作者博客、复盘、演讲及视频讲稿 |
| 头部 | GitHub topic／搜索按 star 和近期活跃度排序、trending、awesome、插件／Skill 市场；未覆盖头部候选收录或说明不收理由 |
| 技术社区 | HN、Lobsters、dev.to、Reddit、newsletter；掘金、知乎、少数派、linux.do、V2EX、B 站、公众号、即刻；读原帖与评论 |
| 真实用户 | issue、discussions、官方论坛、市场评价及社区抱怨／求助／对策 |
| 未知新事物 | 近 3 个月热度上升而项目尚未提及的工具、做法和讨论 |

每类换多组中英文和不同表述的检索词；有 API／RSS 就用（HN Algolia、GitHub 搜索 API、Discourse `.json`）。沿引用、评论中的替代／反例、作者其他文章及收录列表继续追。

新一轮大多已见过才算当前领域饱和；只扫一轮或每类一两个站仍未完成，高价值候选可先转化。读不到时用获准 API、RSS、`site:` 或转载索引找原帖；明确拦截不绕过，仍缺原文记原因并交可读环境，不当作没有内容。

收集阶段广收，逐项给原始链接、理由，核能打开且内容相符；深挖项再严格核实。批量收集可交子代理／低成本模型，给领域、来源类别和取法，主执行者选强候选。

每段结束沿原任务保全候选、来源和取法，续接复用。原产物附覆盖表：各类实际看了什么、几项、截止日期、不可读项及原因。

## 3. 转化

给一句推荐、可复制配置／片段及适用限制；真实任务比较按 [write-task-guide §2](../write-task-guide/SKILL.md#2-用当前最强的做法做一遍)，记录返工、漏检、token 或时长等可数变化。有效的依项目权限写入默认、模板或 Skill；未试标“未试用”并列社区评价。

## 4. 回看

定期对照外部热门讨论，记录漏检和发现时差，分清未看、未追到或不可读，将原因改进到来源与取法。
