# 找当前最强的做法，并转化成可用的东西

要做的决定或要扫的领域：$ARGUMENTS

## 1. 先分清是定向还是广扫
- **定向**：有具体决定。用一句话写清读者或这个项目读完后要选什么、改什么，来源围绕它找，与决定无关的不收。
- **广扫**：没有具体决定，目的是发现还不知道的东西（空档、每周对照、被指出漏了东西时）。按领域扫，读者值得知道的都收，不先编一个决定再去找。

两种都要走完第 2 步的每类来源，区别只在收什么。

## 2. 往广里找，找到饱和为止
资料分散在几类地方。每类都要看，每类不止看一个站：
- **做事的人自己的东西**：官方团队和推进快的高质量项目仓库里的 AGENTS.md／CLAUDE.md、Skill、hooks、PR 与 CI，作者的博客、复盘、演讲和视频讲稿。读代码和设计，不只读 README 和宣传文章。
- **头部覆盖**：GitHub topic 与搜索按 star 和近期活跃度排序的结果、trending、awesome 列表、插件与 Skill 市场。排在前面的逐个对照本项目是否已覆盖；没覆盖的要么收，要么写一句为什么不收。
- **技术社区**：HN、Lobsters、dev.to、Reddit 相关版块、newsletter；中文的掘金、知乎、少数派、linux.do、V2EX、B 站、公众号、即刻。读原帖和评论区，正反都看。
- **真实用户的反馈与问题**：工具仓库的 issue 和 discussions、官方论坛、插件市场评价，以及普通用户社区里的抱怨、求助和对策。官方文档里没写的限制和土办法常在这里。
- **没人点名的新东西**：近 3 个月热度上升、本项目还没提过的工具、做法和讨论。

怎么找：
- 每类来源用中英文、不同说法各换几组搜索词。平台有 API 或 RSS 的直接用，例如 HN 用 hn.algolia.com，GitHub 用搜索 API，Discourse 论坛加 `.json`。
- 顺藤追：找到一项，就继续追它引用的链接、评论区里提到的替代品和反对意见、作者的其他文章、收录它的列表。
- 饱和才停：新一轮找到的大多已经见过，才算扫完。一类来源只看了一两个站，或者一轮就停，都不算扫完。
- 读不到的渠道先换路：API、RSS、搜索引擎 `site:` 查询、转载索引找原帖。仍读不到就记下来，交给能读的环境，不当作“那里没有内容”。
- 收集阶段宁多勿少。每项给原始链接和一句理由，只核链接能打开、内容对得上；严格核实留给挑出来深挖的几项。大范围收集交给子代理或便宜的模型，给它领域、来源类别和取法，让它按上面的方法返回候选清单；你只挑最强的几个深挖。

交付附一张覆盖表：每类来源实际看了什么、得到几项、截止日期、哪些读不到及原因。

## 3. 转化
- 写成一句推荐、一份可复制的配置或片段、一句何时不适用。
- 需要证据时，在一个真实任务上和原做法比一次（做法见 write-task-guide 第 2 步），记一个能数的变化（返工、漏检、token、时长）。
- 有效的就成为项目默认（写进 AGENTS.md、模板或 Skill）；没试的写“未试用”和社区评价。

## 4. 回看
过一段时间对照外部热门讨论，看漏掉了什么、晚发现了多久。每个漏检查清楚是哪类来源没看、没追到还是读不到，把原因补进第 2 步的做法和要看的来源。
