# 找当前最强的做法，并转化成可用的东西

决定或领域：$ARGUMENTS

## 1. 先定评判尺与正交分支

- **定向**：开搜前用 4 行写清决定什么、硬约束、当前基线，并**先锁死自定评判尺**（禁止把单篇厂商文章自造的指标当主标尺，防议程植入）。
- **广扫**：空档、每周对照或查漏时按领域找未知，不预编决定限制候选。
- **必设反证分支**：与“官方／论文／开源实现”并行单列“社区失败复盘、回退原因与成本阈值”分支，防止早期正面命中引发确认偏差。

## 2. 正交检索、逐字台账与饱和停止

每类看多个站点，读原文及正反反馈：

| 来源 | 查什么 |
|---|---|
| 一手官方与源码 | 官方团队、工程博客、头部项目的规则／Skill／Hooks／CI 与核心源码；区分工程复盘与产品发布宣传 |
| 实证论文与基准 | 公开实验、样本量、消融对照、模型代际与预算开关；先读论文原文表格，不据摘要转述下结论 |
| 头部开源实现 | 按 star 与近期活跃度定位仓库核心实现（不只读 README）；星标不等于已审安全性或真实收益 |
| 社区反例与维护 | GitHub Issues/Discussions、HN、Lobsters、dev.to、Reddit、V2EX／中文原帖中的失败输入、冻结原因与隐藏成本 |

- **Search-as-Code 与 URL 归一**：长文、论文 HTML 或批量元数据优先用脚本在内存解析并只抽取关键表段（控制每页几 KB 内）；汇总去重前剥离 `utm_*`、`trk` 等追踪参数，筛选时严禁中途静默丢弃硬约束。访问明确拒绝时不绕过，如实记为“不可读”。
- **单文档逐字台账 + 6 级分级**：每条关键断言绑定 `{URL, 逐字核心摘录/原数, 信源分级}`，区分 `[一手官方/源码]`、`[实证论文]`、`[独立实测]`、`[开源README/未审计源码]`、`[社区反馈]` 与 `[厂商自测/转述未核]`（自测榜禁止与独立评测并列）。
- **三态精度与定量三核**：定量结论严格标为`精确值`（附口径）、`区间估算`（附推导）或`公开不可得`，不补造精度；同时核样本量 $N$、效应量与噪声方差、模型与预算对齐。
- **二轮改写与饱和停止**：首轮精读后用新术语和反例线索**改写 Query 做第二轮验证**，不做单轮早停；当核心条件均已入账且互补检索无推翻项时停止外扩。

## 3. 收敛裁决与转化

给出四态裁决（**采用 / 改造 / 放弃 / 暂不能决定**），单列未覆盖或不可读信源；对采纳项写出可复制配置与验证契约，按 [write-task-guide §2](../write-task-guide/SKILL.md#2-用当前最强的做法做一遍) 记录返工、漏检、token 或时长等实际变化；未实测标“未试用”。

## 4. 惯性隔离与回看

高风险选型在终稿前做一次**惯性偏见隔离核查**：遮去结论推导，逐条核对“主张 ↔ 源 URL 逐字摘录”是否成立；定期对照外部热门讨论记录漏检与发现时差，改进查询分支与来源。
