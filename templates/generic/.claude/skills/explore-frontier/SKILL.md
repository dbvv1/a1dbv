# 找当前最强的做法，并转化成可用的东西

要做的决定：$ARGUMENTS

## 1. 先写清要做的决定
用一句话写：读者或这个项目读完后要选什么、改什么。写不出决定，就先别找资料。

## 2. 去最强的东西实际所在的地方找
按决定选来源，不按固定栏目：
- **最强的人自己怎么做**：官方团队（Anthropic、OpenAI 等）和推进快的高质量项目，读它们仓库里的 AGENTS.md／CLAUDE.md、Skill、hooks、PR 与 CI 流程，不只读宣传文章。
- **工具生态**：GitHub 周榜与 topic、官方插件市场、热门 Skill 与 MCP 清单；看近期提交和 issue 里的真实问题。
- **真实使用反馈**：HN、Reddit、linux.do、V2EX 的原帖和高赞评论，正反都看。
- **使用中的问题**：Claude Code、Codex 等在真实任务里反复出现的失败，以及大家实际用的对策。

找到的东西按“能否改变这个决定”取舍；与决定无关的不收。大范围收集候选可以交给子代理或便宜的模型：给它决定和筛选标准，让它返回候选清单，每项附原始链接和一句理由（检索能力弱的模型给它具体来源和 `gh api`、`curl` 取法）；你只挑最强的几个深挖。

## 3. 转化
- 写成一句推荐、一份可复制的配置或片段、一句何时不适用。
- 需要证据时，在一个真实任务上和原做法比一次（做法见 write-task-guide 第 2 步），记一个能数的变化（返工、漏检、token、时长）。
- 有效的就成为项目默认（写进 AGENTS.md、模板或 Skill）；没试的写“未试用”和社区评价。

## 4. 回看
过一段时间对照外部热门讨论，看漏掉了什么、晚发现了多久；漏掉的来源补进下次要看的地方。
