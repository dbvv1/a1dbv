# 访谈式需求整理

用户想做：$ARGUMENTS

## 做法

1. 先快速阅读相关代码（或用 Explore 子 Agent），了解现状，**不要写代码**。
2. 用 AskUserQuestion 工具分轮采访用户，每轮 1–4 个问题。覆盖：
   - 目标与非目标（明确**不做什么**）
   - 用户可见的行为、关键交互、UI/UX
   - 边界情况、错误处理、数据量和性能
   - 与现有模块的接口、数据结构、兼容性和迁移
   - 验收方式：怎样证明它能工作
3. **不要问显而易见的问题**，重点挖用户可能没想到的难点和取舍。能从代码里查到答案的，就不要问用户。
4. 信息足够后，写出 `SPEC.md`，结构如下：

```markdown
# <功能名>
## 背景与目标
## 非目标（不做的事）
## 行为规格（按场景描述，含边界与错误）
## 涉及的文件与接口
## 方案要点与取舍
## 验收：端到端验证步骤（可执行的命令或操作）
每个场景有稳定 ID（如 AC-01），包含有意义的失败路径；标明必需、待决定、不适用及原因。验收数量从此清单计算，不由实现后的总结重新定义。
## 未决问题
```

5. 仅把影响范围或取舍的未决问题交给用户；已经明确的要求不反复确认。验收修改保留差异和理由，不能为通过而删条件。需要新鲜上下文时可交接给新会话，但不是所有任务的强制步骤。
