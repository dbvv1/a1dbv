# 从真实任务写出照着就能做成的答案

读者问题：$ARGUMENTS

## 1. 先拿到一个真实任务

写清读者、任务及预期成果。选两个正在发生或刚发生的同类真实任务（本项目／开源 issue 或改动）：自己做一个，另一个留给第 4 步；不用演示任务替代。

## 2. 用当前最强的做法做一遍

按 [explore-frontier](../explore-frontier/SKILL.md) 找强实践。在真实任务做完，记录配置、命令、提示词、省事处、卡点和修法、相对原做法减少的返工。做不出可用结果的不推荐，说明不适用条件或删去。

## 3. 写成读者能直接照做的页

按任务给推荐 → 版本／权限／环境前提 → 可复制的第一步（取自实做）→ 成功判据。情况不同只写改变选择的分支，可用表或“如果……就……”。不适用条件保留会导致选错的事实；末尾给原文链接和实做提交。一页一问题，相近问题合并，按 Diátaxis how-to 写操作，不铺概念与历史。

## 4. 让没读过的人照着做，按卡点改页面

把全文和预留真实任务给未参与写作的代理，只许照该页做；普通能力模型更接近读者。由读者以外的人按任务验收核实际测试、运行和产物，不采信自报。

记录卡住、误做和另查资料的位置；页面缺信息／顺序错就修，再换新读者实做；模型能力问题不补进页面。同一卡点换读者仍不通，回第 2 步换做法或写不适用。做通才算可照做，核心推荐未经真实采用仍标待验证。

## 5. 保持新鲜

版本、价格或默认行为变化时，重做受影响的第 2 步并替换旧文，不追加更新日志。
