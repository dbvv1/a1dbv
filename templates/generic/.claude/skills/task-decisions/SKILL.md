# 任务决策：只补当前缺口

用途：把当前任务变成一个可执行选择，而不是执行一遍知识库。仅在用户显式调用或指定读取时使用；读相关小节即可。普通明确修改、纯文案和已有可靠流程的重复任务不需此 Skill。

先读当前需求、项目指令与必要事实；已有信息不再向用户追问。交回简短结论：**当前选择 → 理由／缺口 → 怎样验收 → 何时撤回**，然后在授权内推进。无需为此新建 Spec、任务表或评测框架。

## 1. 直接做、先澄清，还是先做样品？

- **默认**：目标、授权、关键契约和运行反馈齐备，就让 Agent 完成一轮端到端结果并自验；大小不决定是否逐步审批。
- **改变条件**：不能猜的业务、兼容或交付约束先查现有依据，只问答案会改变实现的问题；决定记入已有任务或短规格。体验要看过才能选时，先做可撤回样品；还不会评价时先补参考与评价依据，不连续生成变体。
- **撤回点**：只能编译而观察不到目标行为、反复修改不收敛、恢复范围不清时，缩窄受影响动作并补反馈。不要连带收回已清楚部分的实现；样品通过也不代表完整交付。

## 2. 沿用工具与模型，还是升级？

- **默认**：保留已能达标的入口、有效配置与原生工具。没有既有配置时，先核账号／客户端可用选项，选适合当前任务且可验收的起点；本包不固定型号或全局设置。
- **改变条件**：先分清需求、环境、输入、检查与推理缺口。缺页面或性能反馈先补观察；确是推理／检查深度不足，或已有明确更高质量目标时，为相应角色比较更强配置，不必先失败。只缺会话整理不连带换执行循环；当前入口不能满足目标，或同题比较显示质量、后续修改或总投入有明确收益时，再考虑迁移。
- **撤回点**：必要依赖不可达、审批／恢复失效、漏改或兼容破坏时退回可用路径；质量未改善，或费用、等待、人工核查与返工抵消收益时退回仍可用的已验证配置。不靠关闭保护换成功，不假定旧型号仍可用。
- 预算高先查重复上下文、无益委派和缓存；速度档不补推理缺口，低单价不等于整项便宜。

## 3. 加上下文、Skill 或插件？

- **默认**：按任务定位原文和现成实现，复用已有资料／生成器；项目根指令只保留命令、不可猜的约束与完成标准。
- **改变条件**：大批量定位才考虑摘要委派，编辑前核可回查原文；缺领域判断时补理由、适用范围与反例的窄 Skill；可机械检查的规则交现有测试／lint。确需共同分发多个组件时才评估插件及其实际权限、Hook、脚本和外发路径。
- **撤回点**：只是增加阅读和步骤而不改善结果就缩减；升级模型先审旧规则，但删后漏约束或停在半成品就补回具体缺口。必要信息不能为追求“最短”而删掉。
- 同任务历史占空间才压缩，保目标、约束、决定与未完成检查；丢了依据就取回原文，不按固定时长清空。加载失败与加载后无收益分别诊断，不把漏触发修成全任务强制加载。

## 4. 串行、原生委派，还是显式并行？

- **默认**：沿用原生按需协调，不为固定人数或角色表拆任务。
- **改变条件**：能扩大独立证据覆盖、减轻主上下文或缩短关键路径时，明确子任务与可验收产物；并行写入先对齐接口、依赖和写入范围。不同文件不等于语义独立。
- **撤回点**：权限等待、未回收结果或不明写入时停止扩量，先核已有动作。到最终集成验收仍更慢、质量退步或整合成本不值时收回并行。
- 主执行者核证据、处理矛盾并验证集成树的生产者—消费者关系，不把转发报告当完成。独立评审给需求、验收与产物，咨询给相关状态和已试路径；都不是默认全量历史。

## 5. 怎样检查，而不是把流程跑完？

- **默认**：复用能检出目标错误的检查，先确认相关基线和已有失败；实现后验真实使用路径、受影响调用方和失败／边界情况。体验交使用者判断，编译、截图或成功退出各自只证明有限范围。
- **按任务补缺口**：调试先留复现；重构缺行为保护先补特征测试；已知 bug 检查 red/green；未知差异先核意图，不自动把当前行为固化为正确答案；性能优化先测瓶颈并保持语义。
- 迁移先核消费者、可重复执行和恢复；整项维护按约定范围列已查／未查，不能用一个小补丁冒充查全。结构性改动用一次代表性后续需求检查可继续修改性；普通文案不强制做二改实验。
- **撤回点**：检查把错身份、漏事件或真实内容差异也放过，先撤回该判定器的接收资格，补应通过与应失败的样本。需求／等价规则确实改变时先确认依据并重核受影响结果；不为修绿删除断言或扩大忽略范围。

## 6. 要增加评审层吗？

- **默认**：保留确定性检查和项目风险准入；需要第二视角先用原生本地评审。报告可核缺陷、影响与证明方式，不以评论数量判断质量。
- **改变条件**：有明确漏审类型再试独立会话、多 Agent 或交叉模型，用事故样本与确认无需修改的样本一起校准；独立性来自可查依据，不来自换品牌。
- **撤回点**：重复发现、无效修补、费用失控或只增加处理负担时收窄，复审聚焦新增差异与未关闭风险。模型意见先核实，不为清空评论扩大修改；离线胜出先窄试，不直接替代全部人审或发布门槛。

## 7. 中断、续改与完成

- **默认**：有效状态被中断先原生继续；核最新需求、分支／当前提交、工作树、证据版本及未完成 worker／外部任务。原目标已取消或人已接管时不覆盖其工作。
- **改变条件**：错误路径污染且前向修复不收敛，才比较受控回退与重启；先保留原产物，明确文件、Git 和外部副作用各自是否恢复。执行逻辑／保存格式换版时核旧读、首次新写、冷读与下一轮，不拿“成功恢复”代替结果验收。
- **撤回点**：外部操作结果未知先查询，不盲目重放；状态或授权不清停止相关写入。需要交接时复用现有记录，保最新目标、关键决定、工作身份、证据版本、未完成动作和下一安全步骤，不复制最长历史。
- 完成按当前版本的原验收核对：通过、失败、未运行、阻塞分别报告；旧版通过不沿用，预算耗尽不算成功。若请求包括上线／恢复，再核目标渠道实际结果；仅实现请求不新增发布授权。

## 8. 怎样决定保留本包或其他新配置？

- **默认**：先写采用决定与必须保留的行为，再用少量真实任务比较旧方案和候选；包括正常、边界、已知失败与后续修改，不只挑旧模型失败题。2–3 个用例只够找问题，不足以证明普遍优势。
- 整包有／无对照可决定是否采用；要解释单项贡献再做单因素或消融。固定任务、验收、工具与权限，记录有效运行、任务完成、合规、质量及总费用／等待／人工返工；保原始产物和失败，留一部分未用于改提示的任务。
- **撤回点**：必要行为退步、差异小于波动或新增投入不值，就保留旧配置；评分变更后对齐两组口径，不能边改判据边报提升。采用率、评论被处理和模型一致不直接代表正确；模拟或离线检查不证明模型行为收益。
