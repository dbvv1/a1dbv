# 完成一个现有开发目标 🧪 试用

**把下面提示词交给持续负责原目标的主 Agent；已有任务记录够用，就在原处补齐必要信息。** 适用于跨阶段实施、接回已有结果或多人分工；小改动直接完成并验收即可。先确认宿主实际提供所需工具、执行环境与权限。

## 填好任务输入，再交给主 Agent

```text
继续完成 <现有需求／issue 及入口>，让 <使用者> 能 <可观察结果>。
必须保留 <既有行为>；不做 <非目标、已取消或被取代的要求>。
完成条件是 <项目检查、真实消费者行为、必要失败路径>。

项目规则与必要输入：<入口、版本、接口和依赖>。
当前工作：<仓库、分支、HEAD、未提交差量与可恢复产物>。
已有任务与结果：<原调用／结果入口、最后确认状态、尚待接收项>。
写入归属：<当前写者、独占写域、共享决定、旧写者退出状态>。
交付范围：<本次允许的外部动作、目标仓库／分支、明确停点>。
待核事项：<结果未知的外部动作、具体阻碍与恢复条件>。
缺项先从现有记录和实际状态查；只有会改变下一步的未知才提问。

你保留完整目标、共享决定、整合与最终验收责任。
先核最新需求、实际版本及差量、已有结果和当前写者。
已回结果先接收；仍运行的留原入口；未知状态先查。
旧写者未确认停止时保全其工作，继续不冲突的调查和独立任务。

按依赖选择连续实现或委派。共享状态多的小改动留在主线；
独立调查和验证可并行；实现先定接口、依赖及唯一写入归属。
独立写入用各自工作副本，并明确端口、数据、服务等资源归属。
每项交接给目标、必要输入、可写范围、验收和停点。

结果回来就核实际差量、运行输出及受检版本，接收、返工或留阻碍。
按依赖整合，比较源码、输入、依赖、环境与验收要求的变化；
保留未受影响证据的原版本与复用理由，重验受影响或影响不明的路径。
最终版本完成项目要求的交付检查和真实消费者验收。
发布已获准时串行提交，回读目标仓库、分支、精确提交与内容；
另查该提交的 CI 实际状态。外部动作结果未知，先查原请求回执。
明确拒绝只停对应动作，保留原因，不换入口重试。

每阶段结束都回到原目标：有可执行的实施、接收或验收就继续。
等待时保留原任务入口；换人前确认旧写者停止并留下可恢复产物。
到达约定停点时交回本次范围的结果，并保留原目标剩余项。
完整验收完成才交付；确实阻塞且无可继续的授权工作，或目标取消时，
按实际状态交接未完成项、恢复条件和下一步，不用阶段结束代替完成。
```

## 交回什么，怎样判断接收

在原任务记录或提交说明中保留四项，链接已有证据即可：

- **结果与差量**：完成了哪个原始需求，实际文件、补丁或产物在哪里。
- **检查与版本**：受检版本及完整工作状态，命令、结果、证据和相关环境；复用项注明原版本与理由。
- **实际落地**：已发生的外部动作、目标内容与回执；将已通过、失败、未运行和待人工判断分开。
- **剩余工作**：未完成验收、原 worker／job 入口、具体阻碍、写者归属与下一步。

负责人据原需求、实际产物和真实消费者结果决定接收；需要机器核对多条验收记录时，再按 [README 的使用步骤](README.md#使用步骤)选用 spec/report 校验器。

**试用范围**：本次只试用了结果接收与证据复用步骤：核对本仓扫描器编码修复的固定候选及既有回归、POSIX 检查，保留原写者退出未确认这一阻碍，并保持旧工作树隔离。新模板尚未贯穿完整任务；整合、发布及新读者完整路线仍待验。[候选](https://github.com/dbvv1/a1dbv/commit/7deb5bc8f206e1a28e7e6dde0a6432fcffe2044a)与[独立接收记录](https://github.com/dbvv1/a1dbv/commit/9bce5cb67218731362b0c9d010193963d88135ef)，核实 2026-11-04。
