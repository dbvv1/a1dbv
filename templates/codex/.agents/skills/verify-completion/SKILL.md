# 用证据核对完成状态

核实时间：2026-10-10；🧪 试用。[经验] 以下为可移植流程建议，未进行 Codex 运行时实测。

读取用户要求、当前 diff 和已有验收记录，确定本次必须成立的结果。按实际变更选择检查：文档通常检查内容与链接，运行时改动检查相应行为；不假设任何通用测试命令必然适用。

涉及机器消费的配置或生成文本，用实际下游版本读回产物，核关键字段与行为含义；下游没有读回入口时按其输入契约验证。包内嵌的依赖按实际执行产物核对，远端流程仍单独接收。[模块实跑来源实例](https://github.com/dbvv1/a1dbv/blob/1421144bfdab8034d41188ef86da5f5f96b6db50/experiments/release-title-roundtrip/README.md)核实于 2026-10-31；本 Skill 的 Codex 运行时仍未实测。

对每项必需验收，核对或补充以下证据：

- 实际命令/观察方式、退出状态或观察结果、可复查产物
- 证据针对的 revision、具体未提交改动状态及会影响结果的输入
- `passed`、`failed`、`blocked`、`not_run` 或有理由的 `not_applicable`；项目有自己的状态 schema 时沿用其等价状态，不新增不兼容字段

先比对证据覆盖的代码、输入、直接消费者、依赖、环境、检查命令和验收要求，再决定复用还是补验：

- 已核这些因素未变或变化不影响原结论时，可复用原证据；保留原版本、命令和受检范围，说明当前差量为何无影响，不改标签冒充本次运行。仅提交号变化或无关文案修改，不自动使全部检查失效。
- 任一相关因素改变或影响不明时，补跑受影响的适用检查；检查器没改，但输入或下游版本改变，也须重新判断。旧结果仍只证明原状态，不在复验前宣称当前通过。
- 原证据为失败、受阻或未运行时，保留原状态；只有未经核实的成功自报时，先取得可复查输出或补验，不能作为已通过证据。

已有验收器时使用它及其真实 schema，不另写重复工具，也不把验收器通过等同于产品行为已验证。

在现有授权内运行适用检查；需要缺失工具、网络、写入或权限时，准确报告阻碍及所需下一步。失败应保留具体错误，区分既有基线问题与本次回归；没有基线证据时不要推断失败早已存在。

不为了宣布完成而删测试、降低断言、修改验收条件或引用其他版本的输出。验收条件确需改变时交回用户确认。

输出已完成结果、关键证据和剩余风险。必需验收仍失败、受阻或未运行时，明确任务尚未验证完成；如本次仅做静态检查，只声明静态检查范围内的结果。
