# 保存与恢复任务

编辑更新：2026-10-24；🧪 试用。[经验] 以下为可移植流程建议，未进行 Codex 运行时实测。

## 保存

复用现有 `PROGRESS.md`、任务计划或用户指定记录；没有时，按项目约定选一个位置。保留未解决事项和必要决策，不创建相互冲突的状态副本。

记录下一位执行者无法仅从代码得知的内容：

- 当前目标及来源、最新约束、非目标、验收条件和剩余步骤；已取消或被取代的要求也要标明
- 实际 HEAD、未提交/未跟踪改动的范围，以及证据对应的工作树状态；有现成快照或摘要时引用它。仅写“dirty”不足以识别具体版本
- 已执行检查的命令、结果、证据位置、受检范围及版本、相关依赖与环境；尚未验证的改动单独列明
- 阻碍、尚待批准的具体动作、已有授权的范围，以及下一步安全动作

不为生成检查点而自动 commit、stash 或清理用户改动。记录结论与可核查依据，不存凭据、私密原始日志或内部思考过程。

## 恢复

先核对最新要求与权威记录：记录后是否发生目标变更、取消或他人接管；有变化就更新原有剩余步骤，不执行被取代的步骤。再核当前文件、HEAD 和未提交改动是否仍匹配。非 Git 项目使用已有版本标识或文件快照，不假设 Git 可用。

恢复或压缩后，从当前权威来源重读本步适用的路径规则与 Skill 正文；不要把已激活标记或摘要中的零散复述当作完整规则已恢复。仅加载本步需要的规则；无法读取时标明阻碍，不执行依赖该规则的步骤。

外部动作中断后，先核对精确动作与参数，区分“确认已提交 / 确认未提交 / 未知”：已提交只收集结果；未知先停下核对。仅在确认旧执行已结束、未提交且当前仍获授权时考虑重试；缺回执或旧错误日志不能证明未提交。查询后重试仍有竞态，自动重试还需服务端幂等或等价保证，不能承诺 exactly-once。所需工具、权限或模型不可用时写明阻碍，不假设拥有原会话能力。

按受检范围核对代码、相关输入、依赖、环境、检查命令和验收要求的变化，只将受影响或影响不明的检查列为待复验；提交SHA变化或无关文件改动本身不使全部证据失效。复用时保留原版本，说明当前差量为何不影响该结果，不能重贴版本标签冒充新运行；旧环境通过也不证明新环境已可用。保留原始失败与阻碍，不能用新摘要改写为成功。输出简短恢复结论：当前状态、可复用证据、待复验项和下一步。
