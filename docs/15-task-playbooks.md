# 15 · 按任务类型的打法

> 更新：2026-10-17（UTC+8）。任务起点见下；Codex 的[五情境入口](01-agents/codex.md#五种情境先做最小改变)说明何时再加知识、工具或流程。版本与验证范围见各节研究链接。
> 依据包括 Anthropic 官方最佳实践与 Opus 5.5 指南 **[一手]**、Willison 与 HumanLayer 的公开实践 **[社区]**；组合建议标为 **[经验]**。除明确标注的局部实测外，案例均据公开材料；仅支持局部机制，不代表当前产品推荐或 AI／固定 Skill 净收益；详细来源与反证见研究链接。

## 0. 总表

| 任务 | 最大的风险 | 关键动作 | 验证手段 | 自主度（见 [14 第 7.1 节](14-synthesis.md#71-这个任务该给-agent-多大自主权)） |
|---|---|---|---|---|
| [理解陌生代码](#1-理解陌生或遗留代码) | 自信地讲错 | 只读探索 + 要求引用文件和行号 | 抽查引用 | 高（只读） |
| [调试](#2-调试) | 修症状不修根因、改测试让它通过 | 收集失败证据；能复现就复现，定位且获授权则修复 | 相关回归测试与实际路径，说明未验证项 | 按风险与授权 |
| [新功能](#3-新功能) | 方向错、堆出难维护的代码 | 按未决问题选择计划，以可运行的**垂直切片**提早反馈 | 每片都能实际运行 | 按授权推进，关键需求取舍由人定 |
| [重构](#4-重构) | 行为悄悄改变 | **先写特征测试** | 重构前后测试一致 | 中高 |
| [大规模迁移](#5-大规模迁移与升级) | 统一改法漏例外，或跨依赖／状态受损 | 先选现成迁移器或 Agent 补丁，再按机制试点扩量 | 跨文件消费者、重跑与恢复边界 | 按风险、覆盖与授权 |
| [补测试](#6-补测试) | 写出永远不会失败的测试 | 先选保护既有行为或查当前差异 | 已知 bug 验 red/green；未知回归核前后行为与意图 | 高 |
| [性能优化](#7-性能优化) | 凭感觉改、没有数据 | 测量瓶颈并确定不能改变的行为 | 基准数据 + 语义对照 | 按影响与授权 |
| [代码评审](#8-代码评审) | 挑刺、过度设计 | 新会话 + 只报阻断性问题 | 每条都要说明如何证明 | — |
| [文档与杂活](#9-文档提交信息发布说明) | 事实、权限或兼容说明写错 | 按推理需求和错误代价选模型 | 核对来源、命令和相关行为 | 按风险 |
| [原型和一次性脚本](#10-原型和一次性脚本) | 造完整替代却没人改用，或把原型直接当生产代码 | 比较现成方案、局部补充与完整替代，再按真实使用补差距 | 试验目标；真实用户或数据另需安全与恢复检查 | 高（限已授权范围） |
| [已有产品改进](#102-已有产品按问题选择改进) | 功能正常却难用，或改法损伤原任务与维护能力 | 按交互问题或实现取舍选择改法 | 按改动机制复验必要路径与撤回条件 | 按影响与授权 |

## 1. 理解陌生或遗留代码

**✅ 先只读走通一条实际调用路径。** 用 Plan 模式或只读探索，禁止改文件；结论引用文件与行号，分开确认与推断。按请求的执行顺序写线性走读，术语混乱时再维护带代码例子的 `GLOSSARY.md`。**[经验：采用判断；社区：Willison 的 linear walkthrough]**

```
阅读 src/billing，按一次“月度结算”的执行顺序讲解调用链。
每一步给出文件:行号；分开标注“读代码确认的”和“推断的”。
不要修改任何文件。最后列出需要我确认的关键问题。
```

**局限**：面向人的走读不应自动变成常驻指令，仓库概览对 Agent 的收益需另验，见 [03 的研究](03-context-engineering.md#22-指令文件到底有没有用研究证据)。

## 2. 调试

**✅ 已有明确失败就复现、定位、修复、重跑；缺什么证据再补什么。** **[经验：采用判断]**

1. 优先用稳定失败的测试或脚本；无法本地复现时核对日志的版本、输入与环境，必要时加最小诊断
2. 根因不明就做能区分候选原因的小实验；已定位的小问题不必凑假设数量
3. 过滤日志后再读；稳定的回归脚本可交给 `git bisect run <复现脚本>`
4. 补回归，测试本身有独立错误才修测试；禁止为变绿削弱断言、删除用例或改变未授权的行为
5. 先跑相关检查，再按影响扩展集成/全测；仓库必跑入口照做，实际路径可用 curl、短脚本或浏览器补验

依据：[BAML 双 PR](research/2026-10-12-baml-and-review.md#baml实现反馈纠正研究计划)。**[一手：历史补丁；研究]**

**兼容修复按输入机制选范围，不只按版本高低。** 升级消费者或全局关闭能力前，先分清哪些输入仍需该能力。例见 OCRmyPDF 的[两种故障与取舍](research/2026-10-12-development-conditions.md#ocrmypdf兼容修复按输入机制分流)。修订不保证所有输入或旧文件恢复。**[社区／一手；经验：修复选择]**

**局限**：无法复现时的局部修复仍有验证缺口；预期冲突、关键输入或权限缺失须说明具体阻塞并询问。

## 3. 新功能

**✅ 按不确定性决定计划深度，先交付一条可运行路径。** **[经验：采用判断]**

| 尚未确定什么 | 做法 |
|---|---|
| 目标、接口和验收已有依据 | 在授权内直接做并验证，不因规模大补齐流程 |
| 业务规则或兼容契约未明确 | 先澄清会改变实现的取舍，再更新已有计划 |
| 跨层依赖或可运行反馈路径未清楚 | 梳理必要接口／调用关系，选能尽早试用的垂直切片 |

沿真实接口与依赖打通可运行路径，不统一规定前端与数据库的实施顺序；100–200 行可供拆分参考，不是等待人批准的门槛。给出任务、完成标准与需询问的取舍；跨会话保存最新目标、约束、结果与下一步。**[一手：Opus 5.5 指南；社区：HumanLayer；经验：切片建议，见 [07](07-workflows.md#34-大功能的前置设计与垂直切片-)]**

**✅ 用户要求扩功能时，先还原任务；已有专用入口可能满足时，让其实际试用。** 入口已能完成任务、但难发现时，先改善默认入口或说明，再决定是否扩展混合视图；不要仅凭“源码里已有”关闭需求。[Clink 用户实际改用历史弹窗](research/2026-10-13-product-feedback-contract.md#clink先试已有入口再决定扩功能)；入口改动后仍有人未发现过滤方式。**[社区／一手；经验]**

**✅ 新增视图先复用语义相同的业务组件，等具体需求出现再补窄扩展点。** 说明修改层与须检查的旧调用者。见 Discourse 的[前后源码](research/2026-10-12-development-conditions.md#discourse共享组件承接后续需求)；落地不等于上线或维护收益。**[一手：源码与 PR；研究]**

**局限**：旧计划不能锁住新反馈，恢复时须核对当前代码与授权，见 [20](20-codex-long-horizon.md#4-恢复包必须包含最新任务而非最长历史)。

## 4. 重构

**✅ 先锁定行为，再做小步等价修改。** 补特征测试，包括看起来奇怪但需保留的行为；每步之后运行相关检查。机械改名先用已有 IDE／语言重构；重复调用规则有现成 codemod 覆盖就优先复用；少量异质调用或需逐项判断业务含义时由 Agent 补丁。评审专查是否复制了已有实现。**[经验：采用判断]**

**清 lint 时，先确认诊断适用于真实调用契约。** 无 `await` 的测试仍可能依赖异步上下文，JavaScript 调用者也可能依赖 Promise 拒绝处理；有明确需要就保留边界、说明原因并窄范围豁免，不机械删 `async` 或加入无业务需要的等待。确认调用者不依赖时才改同步并验证。Ruff／ESLint 反例见[契约边界](research/2026-10-12-development-conditions.md#清-lint保留异步调用契约还是删除-async)。豁免不能替代行为验证。**[社区／一手；经验]**

**局限**：GitClear 的重复／移动信号只提示检查复用与结构，不能据此设重构配额、认定当前 Agent 倾向复制或项目维护成本上升；正确性仍看本项目行为对照。见 [09](09-review-and-quality.md)。**[一手：厂商材料；研究：采用边界]**

## 5. 大规模迁移与升级

**✅ 先选改法，再按差异试点扩量。** 来源与形状明确的重复变换优先现成语法工具；跨文件引用、继承或类型缩窄优先类型／框架迁移器；例外交 Agent 补丁。见[维护链与源码](research/2026-10-12-development-conditions.md#重复代码迁移语法规则类型分析与第二次执行)。**[一手／社区；经验]**

- **依赖升级失败，先收窄坏组合，再决定是否扩大迁移**：已确认 ABI 不兼容可临时限制传递依赖；直接依赖新版已补正确约束时，优先评估排除其坏旧版，按仍支持的解释器分段设下限，保留必要上限。缺兼容组件仍须限版或修构建。见 [Airflow 的分段修订](research/2026-10-12-development-conditions.md#依赖解析修复排除坏组合同时保留支持面)。**[一手／社区；经验]**

- **原生能力替换依赖**：核自有消费者的选项与错误契约，取消须验请求停止、业务识别和收尾／下一步。窄适配足够就无需仿造旧库整套错误；必要行为承接不了则保留成熟依赖。[GP2040-CE 的取消修复](research/2026-10-12-development-conditions.md#原生替换请求取消之后消费者能否继续)保留 fetch、修选项转发与业务分类；仅历史维护链，无最终版本独立端到端复验，不证明少依赖更好。**[一手／社区；经验]**

**依赖与数据边界明确后，再选执行方式。** 脚本可用 `claude -p`；并行／`/batch` 只拆可独立验收的单元，共享接口、分析范围或持久状态相关步骤按依赖处理。worktree 不保证语义独立，检查不授权高影响操作。见[官方契约](research/2026-10-12-development-conditions.md#批量入口先选改法再选执行方式)与 [08](08-multi-agent.md)。**[一手；经验]**

**共同验收按改动机制选用，机械改名不必全套。** 小批试跑不设通用样本门槛。**[一手／社区；经验，证据见本节链接]**

- **试点与整合**：核跨文件行为、消费者与资源契约；依赖升级核实际解析组合及业务入口，批处理再验整合结果。退出成功仍须核漏改／跳过及原因
- **重试与复用**：核分片归属、调用次数、已迁移调用与跳过原因，检查首次产物再跑是否还会变；一次性迁移器从固定可恢复起点重做。重复变换、覆盖不清或例外过多就暂停扩量，修规则或退回局部补丁。需求改变契约须改规则并复验旧行为；零 diff 不等于语义正确

**从交互转脚本，保住所需项目知识与后台能力。** 普通 `claude -p` 加载项目上下文；`--bare` 跳过 `CLAUDE.md`、Skill 等自动发现，自 2.1.286 起不启动后台任务且超时命令会停止。已审查的可信项目需要项目约束时，保留普通模式，或显式提供必要上下文与工具；依赖后台构建就保留支持该路径的运行方式。外来仓库先按 [10](10-security.md#3-防护原则)限制启动配置。见[契约与版本](research/2026-10-12-development-conditions.md#交互试点转脚本bare-不是等价加速)。**[一手；经验，未运行客户端]**

- **跨语言**：核“谁分配→返回后谁用→何时释放”及 allocator 绑定对象，补内容与清理回归。[VibeTunnel](research/2026-10-12-vibetunnel-maintenance.md)。**[一手：维护补丁；经验]**

- **混版本／降级**：可收窄默认写入、保留显式新格式；用旧版本读取新版本实际写过的状态，核恢复后后台任务是否再生成不兼容产物。[Git MIDX 默认格式回退](research/2026-10-12-vibetunnel-maintenance.md#持久状态回退git-midx-的旧读取者边界)缺原用户最终复测。**[一手：非 AI 历史机制；经验：验收建议]**

- **退役实现**：实现选择器与入口禁用分开；保留仍有用的禁用开关及旧调用者所需的窄适配。受支持扩展仍依赖旧行为或前置修订未到时延后删除；弃用通知与保留符号不保证旧调用者可用。见 [Jetpack 仪表盘开关](research/2026-10-12-development-conditions.md#退役实现选择器保留独立禁用能力)。**[一手／社区；经验]**

- **配置回退**：关新格式写入后，用开启前、开启期间和关闭后写入的混合数据，分别验正常服务与导出／恢复命令；同版本关开关不证明旧版可读。见 n8n 的[读写拆分与命令初始化修订](research/2026-10-12-development-conditions.md#n8n配置回退与独立导出入口)。**[一手／社区；研究]**

- **数据库默认值**：常驻进程持旧 schema 缓存且 ORM 省略 INSERT 字段时，先让相关写入者的显式赋值／写列保护生效，再迁移；否则延后或选获准停写窗口。验旧缓存下的实际落盘值，兼容窗口结束再清理；写列不决定正确默认值，也不保证无保护的旧写入者安全。见 [GitLab 固定实现与测试](research/2026-10-12-development-conditions.md#数据库默认值写出字段不等于写对值)，未运行测试。**[一手／研究]**

- **恢复旧快照／删除新系统数据**：明确恢复时间点及升级期间将丢的新增／修改，在隔离数据上验证恢复，再由负责人选保留、转换或接受损失。仅损失明确接受且恢复已验证时，才有条件强制回退；[Grafana 历史记录](research/2026-10-12-development-conditions.md#grafana回退的恢复时间点与保护性拒绝)有清表启动但丢失警报的反例。**[一手／社区；经验]**

- **职责迁移**：职责改变后向当前负责服务查询，避免仍在旧层扫描或重建状态。见 [Scion 复盘与反例](research/2026-10-12-development-conditions.md#迁移后的事实归属与旧调用方式)。**[一手：自述，未复测；经验]**

## 6. 补测试

**✅ 先选保护已认可行为，还是查当前差异。** **[研究：采用判断]**

- **保护行为**：用契约或独立依据定预期，测试可直接通过；已知 bug 验旧版失败、修后通过；关键断言用反例／变异检查
- **🧪 查未知回归**：对高风险差异，按改动意图与保留行为生成前后对照测试；旧版通过、新版失败后，先核行为变化是否预期，再修代码或弃候选；已覆盖就不扩生成
- 通过公共接口观察结果，测试名写行为，避免断言 mock 返回值或照抄算法；确认有长期保护价值才并入回归套件

依据：[公共边界测试](research/2026-10-12-community-source-records.md#3-matt-pocock控制权与领域语言)与 [JiTTest 目标比较](research/2026-10-12-development-conditions.md#生成测试先选保护未来还是查当前差异)。后者是内部部署自述，未证 Codex／Claude 净收益；保留 CI／人审。**[社区／一手／研究]**

**✅ 先核本次选中了相关消费者测试，再考虑新增选测。** 依赖、预打包配置或非模块夹具改变时，显式跑消费者测试或用已有映射；`changed`／`related` 成功退出不足为证，原生选测可靠就保留。

缓存以“代码未变”跳过原生环境检查就撤掉短路；配置、锁文件或共享设施使映射失效时，核已有扩大运行／重建路径及过滤范围后再恢复增量。见 [Vitest 与 Polylogue](research/2026-10-12-development-conditions.md#增量验证已有回归测试是否真的被选中)；选中通过不证明未表达的兼容要求。**[一手／社区；经验]**

**🧪 测试仍是瓶颈时**，先比较修慢夹具／重复扫描与已有安全并行；常见改动可缩小范围，计入映射建立／刷新和漏选补跑成本后再决定是否加选测。[remote-store 暂缓引入的试验](research/2026-10-12-development-conditions.md#新增选测能力先比较改动类型与完整运行成本)的种子试验不代表日常改动，也不授权撤检查、放宽隐私或全并行。**[一手：报告；经验，2026-10-16 UTC]**

外部格式／协议用目标版本生产者的公开、可脱敏产物校准预期，据独立证据修正旧断言。[RTK 编码修订](research/2026-10-12-development-conditions.md#外部生产者校准错误预期)也有旧预期错误。**[一手；经验]**

**预演须保住下轮边界。** 保持业务数据及下轮接受配置／判进度的状态不变，从已通过的正式基线验“修改→预演→普通执行”，该拒绝的仍拒绝；允许日志和隔离产物。见 rclone 的[修订与入口差异](research/2026-10-12-development-conditions.md#rclone预演不能替下一轮提交控制状态)；CLI 修复不保证 API 传参生效。**[一手／社区；经验]**

新增写入须验业务行与派生版本／审计状态；序列化判等须覆盖可接受类型及业务不同的值。[sqlite-chronicle 修订与固定 SQL 实测](research/2026-10-12-development-conditions.md#写入路径扩展与序列化判等sqlite-chronicle)有旧类型漏报。**[一手；经验：局部实测与建议，未运行包 CLI]**

**🧪 输入组合多、契约可表达且执行便宜时，补小范围属性测试。** 从文档／调用找不变量，在已有环境搜反例；先核属性和输入域，再固定输入、版本与随机条件。[NumPy 与 dateutil](research/2026-10-12-development-conditions.md#属性测试搜索反例不等于确认或修好缺陷)有跨构建修订与日历误报。**[一手；经验]**

**局限**：旧版无法运行则保留回归缺口；属性可能错误，通过不证明所有精度、分布或业务要求。

## 7. 性能优化

**✅ 先给 profiler/基准、实际规模输入与完整命令，写清不能改变的行为。** 一次改一项，保留前后数据，多次运行看中位数；运行正确性测试，并按改动机制补旧测试漏掉的行为。**[经验：采用判断]**

**正确加速未达目标，按新热点与剩余预算续改。** 只见 native 入口就补内部耗时；保留各轮补丁／验证，选满足必要行为和目标负载的候选，不默认交末版或追单负载最高数。满足目标、无新依据或预算到限即停。[PerfAgent 评估与反例](research/2026-10-13-domain-skill-contract.md#性能续改观测层与候选选择)运行身份未完全对齐。**[一手；研究]**

**探索不同实现，先比较轻量候选搜索，再决定是否接完整进化框架。** 成本计入未形成候选的生成、失败重试及复评，并为独立复评留预算；评分波动先廉价筛选，再独立重测竞争版本，留未参与选择的输入验收。见[比较与记账边界](research/2026-10-13-domain-skill-contract.md#竞争实现先比较轻量搜索并为复评留预算)；仅数学／AIME 结果，单线与多候选缺同条件净收益比较。**[一手：论文与源码；研究]**

**✅ 搜索赢家的内核与分派范围分开决定。** 同一热点已有可适配的成熟内核时，比较保留优化方向、替换生成内核，并按真实输入分布重定门槛（[Roaring 接收与替换](research/2026-10-13-domain-skill-contract.md#性能候选接管可保方向换内核)）。接收方新增类型、比较器或规模时，按其负载选择：范围明确且收益成立就留窄快路径，其余走已有实现；共享分派退化则拆开内核与入口判断回滚，大输入收益不能抵消小输入损失（[libc++ 接管与重投](research/2026-10-13-domain-skill-contract.md#搜索赢家接管后保内核还是扩大分派)）。无新负载或入口变化不必重建搜索；libc++ 为历史 RL 与人工接管。**[一手／社区；研究，非当前 LLM 净收益验证]**

**功能正确后按 profiler／调用链热点选优化。** 转换／分配／复制占比明显，就先查能否消除多余工作，再考虑缓存／快路径；算法或 I/O 主导则先处理它们。跨调用缓存反复补生命周期时，比较继续修补、退役后复用现成调用机制与局部热点实现，按目标负载接受或拒绝退化（[CPython 历史取舍](research/2026-10-13-domain-skill-contract.md#跨调用缓存反复修补时比较退役与局部实现)，历史人工优化）。删复制须保 [pandas](research/2026-10-13-domain-skill-contract.md#性能质量先消除表示转换与重复复制) 的缺失掩码与复制／别名语义，并核 [SGLang](research/2026-10-13-domain-skill-contract.md#消除复制前核对下游布局契约) 的下游布局契约；不能满足就保留必要物化或限制路径，`view` 换 `reshape` 不保证复制。**[一手／社区；研究]**

**批处理优化先定：只改批大小，结果是否应相同？** [alchemy-utils](research/2026-10-12-alchemy-utils-evolution.md)有 NULL／默认值随批大小变化的反例；先定缺失与显式 NULL 契约，再验跨批回滚、schema 推断、默认值与旧文档。全局推断和立即流式写入冲突时，由人选预扫、缓冲或接口变化，不必为优化安装完整流程。[程序与输出](../experiments/alchemy-batch-semantics/README.md)已核对，运行仅据对端报告，非本侧 API／性能复测。**[经验：报告；一手：源码；研究]**

**🧪 已有 React 界面的热点是重复渲染时，可局部比较编译器自动 memoization，不批量删除已有手工 memo。** 核实际编译与发布入口，用原业务交互验收；不兼容处临时退出并跟踪根因。开发编译等待／内存与生产交互收益分开量，必要时保生产、收窄开发启用，仍须验编译产物。[Sanity 局部退出与 Onyx 分阶段启用](research/2026-10-13-domain-skill-contract.md#前端自动优化按交互和构建阶段采用)的历史采用不证明当前版本全面更快。**[一手／社区；研究：采用边界]**

## 8. 代码评审

**✅ 用独立上下文审 diff，只报会阻止合并的具体问题。** 给评判标准，不灌入实现过程中的推理；每条包括文件、行号、失败条件及证明方式。工具可选 `/code-review`（`--max-findings`）、`/ultrareview`、Codex Security Cloud 或 CodeRabbit，见 [09](09-review-and-quality.md)。**[一手：官方用法；经验]**

[BAML 两条 PR 都获自动肯定](research/2026-10-12-baml-and-review.md#baml实现反馈纠正研究计划--4-自动评审和测试记录能证明多少)提醒回到具体行为核评审结论。

**局限**：追改每个挑刺会增加过度设计，评审“通过”也不能替代实际验证。

**✅ 按错误代价选能力，按内容核对证据。** 已核实信息的机械整理可先用低成本模型/非交互模式；涉及权限、架构、兼容或迁移时保留足够推理，核对来源、代码、命令与行为约定。**[经验：采用判断]**

## 10. 原型和一次性脚本

**按任务选读**：原型的价值与替代范围尚待判断，读[10.1](#101-原型判断任务价值与替代范围)；已有明确改进目标，直接读[10.2](#102-已有产品按问题选择改进)。下列交付与证据边界适用于两类任务。

接入真人或持久化前补身份权限、数据隔离、迁移兼容、备份恢复、错误处理和回归；交付核许可、持续成本与接手者。交付失控先核部署版本，用虚构数据走跨角色路径；试用遵守隐私和授权，越界先问。见 [KPI 反例](research/2026-10-12-codex-delivery-cases.md)及 [23 前端验证](23-browser-verification.md)。**[社区；经验]**

**证据边界**：局部回执不证明全路径、留存、四步整体有效或维护总成本下降；不同用户不能拼成长期对照，不能跨案例补齐缺口。**[研究：范围限定]**

### 10.1 原型：判断任务价值与替代范围

**✅ 先验证一条值得完成的任务，再决定补哪里、保留多少。** 以下四步按当前问题选用，不必加齐所有检查。**[经验]**

1. **定核心任务、推翻条件和替代范围。** 按须保留的系统及输入输出比较复用、窄补充与完整替代；先做能独立完成有用一步的产物。实际接入丢必要语义、要求错误角色操作，或须补齐全流程才有用，就重划范围。[Segment 与 Tract](research/2026-10-13-product-feedback-contract.md#替换哪一段工作流segment与tract的范围选择)支持比较，非“越小越好”。**[一手／社区；经验]**

   一次性任务完成一次可能就够，重复任务再看下次；未迁移、未付费或一次负反馈不等于无价值，原型也可发现新需求。仍须比较结果、可用性、数据边界与运行责任，少代码或早停不必然更好。见[创业试验及反例](research/2026-10-13-product-feedback-contract.md#需求成立与否试用也可以导向停止)、[Jules 替换](research/2026-10-13-product-feedback-contract.md#jules从自建常驻服务到现成运行能力)。**[研究；一手／社区]**

   **同仓新增命令，先比较复用完整命令还是底层操作。** 锁、错误处理、输出与参数的组合成本高时，可复用底层规则／操作，保留独立入口、必要分步并验最终结果；契约合适仍可用成熟 CLI，不建议外部调用私有 API。见 [Restic](research/2026-10-13-product-feedback-contract.md#restic复用命令还是底层操作)。**[一手／社区；经验]**

2. **用真人任务区分反馈。** 让试用者解释结果并完成任务：“尚无机会”延后，“没理解”核含义，“运行失败”复现，“没价值”查减负与必要选择。[Motif](research/2026-10-13-product-feedback-contract.md#原型复访尚无机会不等于不值得使用)仅短期自报；Agent 可提反例和试用顺序，但[模拟反馈](research/2026-10-13-product-feedback-contract.md#模拟用户可以帮助选测试不能单独否决需求)不能独自否决需求。**[研究；经验]**

3. **试用已指出改进目标时，选改法并复验。** 具体取舍见[已有产品改进](#102-已有产品按问题选择改进)，结果用于下一步范围判断。**[经验]**

4. **由负责人决定保留、缩小、复用或停止。** 需求仍在但维护不成立可暂停实现；现成能力变化后重比外部处理、窄集成与重建，核目标人的平台、格式、任务数量、时效和失败可见性。[Mealie](research/2026-10-13-product-feedback-contract.md#mealie撤掉实现不等于撤掉需求)的单样本不证明整批替代。**[一手／社区；经验]**

### 10.2 已有产品：按问题选择改进

**围绕明确收益选改法。** 功能正确仍可改善层级、引导与响应；明确受益操作，复用已有状态和版面。步骤关系可见，并列能力不作装饰编号；品牌独特性另判。

**复验按改动机制选用**：按真实规模／依赖分别验看懂与完成；涉及连续交互时，以正常操作速度复验完整路径。见 [CodeAid](research/2026-10-13-product-feedback-contract.md#修改版再使用可见性改善仍须通过真实任务)、[CodexBar](research/2026-10-13-product-feedback-contract.md#codexbar发布后的理解反馈)、[领域质量反例](research/2026-10-13-domain-skill-contract.md#质量提升领域依据目标与过程分开判断)。下列保留各类问题的具体取舍与检查。**[研究／一手／社区；经验]**

#### 交互与状态

- **采集噪声**：先比较准入／去重，再决定是否加搜索或整理；按实际来源连续验短输入误丢，分别定过滤范围与默认值；重复内容可保留旧对象并前移。[Buffer](research/2026-10-13-product-feedback-contract.md#buffer自动采集的噪声先改入库还是继续加功能)仅有适配版改善回执，不是隐私防护。**[一手／社区；经验]**
- **结果／确认对象错误**：选项可见仍错，核[实际参数与默认值](research/2026-10-13-product-feedback-contract.md#openwhispr选项出现后仍须核对实际参数)。搜索先分准入、排序与输入次序，再选场景排序、保序或放宽查询；全词命中不必关闭容错。候选过滤与整库检索分别定延迟，按正常速度验“输入→确认”，再选缩短等待、提示或提交保护；不放慢测试掩盖错选，延迟不能照搬。见[搜索取舍](research/2026-10-13-product-feedback-contract.md#搜索改进结果准入排序与输入次序)、[连续操作](research/2026-10-13-product-feedback-contract.md#keepassxc连续筛选后确认的是哪个对象)。**[一手／社区；经验]**
- **看得见却不好用**：先分清当前是辨认对象、核对输出还是编辑数据，再在摘要、预览与原编辑入口中选择，不统一默认。

  短查找与持续结果集可分入口，但须交接查询、结果及未完成搜索；可编辑预览另定保存／退出／撤销，关闭不等于放弃（[Zed](research/2026-10-13-product-feedback-contract.md#zed查找与编辑共用结果不等于共用退出语义)，fork 仅自用）。

  持续对照所需的条件与结果保持可见；阶段依赖可分步，但说明预览范围、更新状态和返回路径。局部预览不替代完整核查，自动图表未必适合先查数据。让熟悉后的原用户重做任务；保留字段不等于保住原路径。见 [Zotero](research/2026-10-13-product-feedback-contract.md#zotero结果预览与原编辑入口如何取舍)、[Metabase](research/2026-10-13-product-feedback-contract.md#metabase同屏条件与分步预览的竞争取舍)、[Home Assistant](research/2026-10-13-product-feedback-contract.md#home-assistant字段保留与原操作路径是两回事)。**[一手／社区；经验]**
- **直观编辑 Markdown**：比较原文＋预览、源上渲染与富文本转换。须保特定语法时，可先试可关闭的源上渲染并核保存前后差异；需直接操作格式结构且目标格式能承接时，再评估富文本。键盘／读屏不满足就保原入口。见 [Joplin 的表示与保存取舍](research/2026-10-13-product-feedback-contract.md#joplin直观编辑先选表示与保存契约)。**[一手；研究：采用判断]**
- **连续输出跟不上**：追最新状态可合并过时进度；按序消费则比较队列、分批与取消，验积压、取消后新输出、短结果紧接提示符及大量输出。回看／跳过不能替代自动阅读和必要结果；漏结果或不能及时中断就撤回统一策略，按任务／宿主重选。[NVDA 反馈与回滚](research/2026-10-13-product-feedback-contract.md#nvda追最新状态还是按序消费输出)的队列仍是候选。**[一手／社区；经验]**
- **连续缩放与定位**：经常需要停在固定倍率时，把软停靠、临时越界和自由缩放分别比较；按实际设备走完“放大定位→调整→越界后继续→返回”。默认值按目标任务选，额外偏好设置计入发现与维护负担。见 [darktable 的修订与复测](research/2026-10-13-product-feedback-contract.md#darktable连续缩放的停靠与自由越界)。**[一手／社区；经验]**
- **往返找位置**：比较保留位置、显式跳转与改布局；分别验滚动、聚焦、快捷键及首次／重访／返回落点，追加／刷新不抢焦点。按目标浏览器／读屏组合连续验，其他环境成功不能代替。见 [Joplin 与 Discourse](research/2026-10-13-product-feedback-contract.md#joplin与discourse导航可达之后保留任务位置)。**[一手／社区；经验]**
- **省步后仍重复／难恢复**：自动结束分别验成功后下一次与失败后恢复；丢重试机会就按结果状态收窄。反复补同一步则分一次性操作、持久偏好与全局默认，调整入口／保存范围，验新对象、连续操作与重开，不必整项回滚。见 [LocalSend](research/2026-10-13-product-feedback-contract.md#localsend省掉完成点击后为何收窄自动结束)、[GIMP](research/2026-10-13-product-feedback-contract.md#gimp一次性合并与记住工作流选择)（只验已有选项）。**[一手／社区；经验]**
- **重复提交／编辑后想反悔**：重存、重试与重新入队分别核状态／排序，不凭调用来源猜意图。防丢失、检查点与可放弃试改也分开选；核画布、持久草稿与发布边界，验“修改→试运行→放弃或保留”，命名版本／保存确认不等于试运行后决定。见[Karakeep](research/2026-10-13-product-feedback-contract.md#karakeep重复对象不等于重复意图)、[n8n](research/2026-10-13-product-feedback-contract.md#n8n自动保存稳定检查点与可放弃的试改)；后者仍未恢复未保存试运行，不宜一律加设置或关自动保存。**[一手／社区；经验]**
- **协作中只撤回自己的操作**：复用本地历史，保留无关远端贡献，另定同对象同属性冲突；验“本地改→远端改→撤销→重做”。同属性／组合对象仍可能覆盖远端值；单人整体回退可用快照，不默认加框架。见 [Excalidraw](research/2026-10-13-product-feedback-contract.md#excalidraw撤销自己的操作与恢复整份旧文档)。**[一手／社区；经验]**

#### 实现与维护取舍

- **退休旧实现**：默认采用与删除旧路径分开，分别验交互和后台／批量；缺必要能力时比较窄适配、兜底或缩小支持。兼容开关不保证回旧实现，局部成功不足以退休，也不永久默认双实现。恢复旧绕路前先核是否重引工作不可达，再比较修复加取回入口、窄适配或缩小支持，说明额外负担；关反馈不算成功。见 [GitHub Desktop](research/2026-10-13-product-feedback-contract.md#github-desktop保住工作与保留旧绕路)、[VS Code](research/2026-10-13-product-feedback-contract.md#vs-code默认采用与退休旧实现分开)。**[一手／社区；经验]**
- **减少组件**：核可选能力是否变基础硬依赖；仍支持不开功能的用户时，验安装、启动与升级，再选合并、隔离或缩小支持。开关未必隔离迁移。[Immich 历史变化](research/2026-10-13-product-feedback-contract.md#immich减少同步层也改变基础运行的依赖)非当前部署指南。**[一手／社区；经验]**
- **保留窄适配**：目录缺项先比较配置更新与动态发现；参数／返回值／流式变化仍须改代码并验证。必要任务反复需接收者手改且无人更新，就重比受维护连接、集中适配与缩小支持；少容器不等于少负担。见 [Open WebUI](research/2026-10-13-product-feedback-contract.md#open-webui少一个服务之后谁维护协议适配)。**[一手／社区；经验]**
