# 15 · 按任务类型的打法

> 更新：2026-10-17（UTC+8）。本页给任务起点；Codex 的[五情境入口](01-agents/codex.md#五种情境先做最小改变)说明何时再加知识、工具或流程。来源、版本与验证范围见各节研究链接。
> 依据包括 Anthropic 官方最佳实践与 Opus 5.5 指南 **[一手]**、Willison 与 HumanLayer 的公开实践 **[社区]**；没有单一出处的组合方法标为 **[经验]**，案例来源与审计范围链接到研究页。

## 0. 总表

| 任务 | 最大的风险 | 关键动作 | 验证手段 | 自主度（见 [14 第 7.1 节](14-synthesis.md#71-这个任务该给-agent-多大自主权)） |
|---|---|---|---|---|
| [理解陌生代码](#1-理解陌生或遗留代码) | 自信地讲错 | 只读探索 + 要求引用文件和行号 | 抽查引用 | 高（只读） |
| [调试](#2-调试) | 修症状不修根因、改测试让它通过 | 先收集失败证据，能复现就复现；已定位且获授权则修复 | 相关回归测试与实际路径，说明未验证项 | 按风险与授权 |
| [新功能](#3-新功能) | 方向错、堆出难维护的代码 | 按未决需求、接口与验证缺口选择计划；用可运行的**垂直切片**提早反馈 | 每片都能实际运行 | 按授权推进，关键需求取舍由人定 |
| [重构](#4-重构) | 行为悄悄改变 | **先写特征测试** | 重构前后测试一致 | 中高 |
| [大规模迁移](#5-大规模迁移与升级) | 统一改法漏例外，或跨依赖／状态受损 | 先选现成迁移器或 Agent 补丁，再按机制试点扩量 | 跨文件消费者、重跑与恢复边界 | 按风险、覆盖与授权 |
| [补测试](#6-补测试) | 写出永远不会失败的测试 | 区分 bug 回归与既有行为保护 | 回归 red/green；关键断言用反例或变异检查 | 高 |
| [性能优化](#7-性能优化) | 凭感觉改、没有数据 | 测量瓶颈并确定不能改变的行为 | 基准数据 + 语义对照 | 按影响与授权 |
| [代码评审](#8-代码评审) | 挑刺、过度设计 | 新会话 + 只报阻断性问题 | 每条都要说明如何证明 | — |
| [文档与杂活](#9-文档提交信息发布说明) | 事实、权限或兼容说明写错 | 按推理需求和错误代价选模型 | 核对来源、命令和相关行为 | 按风险 |
| [原型和一次性脚本](#10-原型和一次性脚本) | 造完整替代却没人改用，或把原型直接当生产代码 | 比较现成方案、局部补充与完整替代，再按真实使用补差距 | 试验目标；真实用户或数据另需安全与恢复检查 | 高（限已授权范围） |

## 1. 理解陌生或遗留代码

**✅ 先只读走通一条实际调用路径。** 用 Plan 模式或只读探索，明确不要改文件；要求每个结论引用文件与行号，分开确认与推断。按请求的执行顺序写线性走读，术语混乱时再维护带代码例子的 `GLOSSARY.md`。**[经验：采用判断；社区：Willison 的 linear walkthrough]**

```
阅读 src/billing，按一次“月度结算”的执行顺序讲解调用链。
每一步给出文件:行号；分开标注“读代码确认的”和“推断的”。
不要修改任何文件。最后列出需要我确认的关键问题。
```

**局限**：面向人的走读不应自动变成常驻指令，仓库概览对 Agent 的收益需另验，见 [03 的研究](03-context-engineering.md#22-指令文件到底有没有用研究证据)。

## 2. 调试

**✅ 已有明确失败就复现、定位、修复、重跑；缺什么证据再补什么。** **[经验：采用判断]**

1. 优先用稳定失败的测试或脚本；无法本地复现时核对日志的版本、输入与环境，必要时加最小诊断
2. 根因不明就做能区分候选原因的小实验；已定位的小问题不必凑假设数量
3. 过滤日志后再读；稳定的回归脚本可交给 `git bisect run <复现脚本>`
4. 补回归，测试本身有独立错误才修测试；禁止为变绿削弱断言、删除用例或改变未授权的行为
5. 先跑相关检查，再按影响扩展集成/全测；仓库必跑入口照做，实际路径可用 curl、短脚本或浏览器补验

主要依据是 [BAML 双 PR](research/2026-10-12-baml-and-review.md#baml实现反馈纠正研究计划)：调查帮助选择更窄的修改位置，但计划中的测试输入仍需实施纠正；研究应回答修哪层、保留什么。**[一手：历史补丁；研究：采用判断]**

**兼容修复按输入机制选范围，不只按版本高低。** 升级消费者或全局关闭能力前，先分清哪些输入仍需该能力。OCRmyPDF 分别修生产格式、跳过可选连字并保留复杂文字整形，见[两种故障与取舍](research/2026-10-12-development-conditions.md#ocrmypdf兼容修复按输入机制分流)。这些固定修订不证明所有输入或已交付旧文件已恢复。**[社区／一手；经验：修复选择]**

**局限**：无法复现时的局部修复仍有验证缺口；预期冲突、关键输入或权限缺失须说明具体阻塞并询问。

## 3. 新功能

**✅ 按不确定性决定计划深度，先交付一条可运行路径。** **[经验：采用判断]**

| 尚未确定什么 | 做法 |
|---|---|
| 目标、接口和验收已有依据 | 在授权内直接做并验证，不因规模大补齐流程 |
| 业务规则或兼容契约未明确 | 先澄清会改变实现的取舍，再更新已有计划 |
| 跨层依赖或可运行反馈路径未清楚 | 梳理必要接口／调用关系，选能尽早试用的垂直切片 |

按真实接口与依赖打通一条最小路径，每片可运行，不统一规定前端与数据库的实施顺序；100–200 行可供拆分参考，不是等待人批准的门槛。一次给出任务、完成标准与需询问的取舍；跨会话在已有记录保存最新目标、约束、结果与下一步。**[一手：Opus 5.5 指南；社区：HumanLayer；经验：切片建议，见 [07](07-workflows.md#34-大功能的前置设计与垂直切片-)]**

**✅ 用户要求扩功能时，先还原任务；已有专用入口可能满足时，让其实际试用。** 入口已能完成任务、但难发现时，先改善默认入口或说明，再决定是否扩展混合视图；不要仅凭“源码里已有”关闭需求。[Clink 用户实际改用历史弹窗](research/2026-10-13-product-feedback-contract.md#clink先试已有入口再决定扩功能)后仍保留建议列表做补全，维护者随后调整 F7 默认与文档。回执早于默认改动，且后续用户仍未发现过滤方式，不能把改入口当成可发现性已验收。**[社区／一手；经验：采用建议]**

**✅ 新增视图先复用语义相同的业务组件，等具体需求出现再补窄扩展点。** 让 Agent 说明下一需求落在哪层、哪些旧调用者须一起检查。Discourse 后续客户插件沿共享组件补扩展点，见[前后源码](research/2026-10-12-development-conditions.md#discourse共享组件承接后续需求)；局部扩展落地尚不证明上线或维护收益。**[一手：源码与 PR；研究：采用建议]**

**局限**：旧计划不能锁住新反馈，恢复时须核对当前代码与授权，见 [20](20-codex-long-horizon.md#4-恢复包必须包含最新任务而非最长历史)。

## 4. 重构

**✅ 先锁定行为，再做小步等价修改。** 补特征测试，包括看起来奇怪但需保留的行为；每步之后运行相关检查。机械改名先用已有 IDE／语言重构；同一调用规则重复多处且现成 codemod 已覆盖时优先复用，少量异质调用或业务含义需逐项判断时由 Agent 直接补丁。评审专查是否复制了已有实现。**[经验：采用判断]**

**清 lint 时，先确认诊断适用于真实调用契约。** 无 `await` 的测试仍可能依赖异步上下文，JavaScript 调用者也可能依赖 Promise 拒绝处理；有明确需要就保留边界、说明原因并窄范围豁免，不机械删 `async` 或加入无业务需要的等待。确认调用者不依赖时才改同步并验证。Ruff RUF029 不提供自动修复，其报告与 ESLint 反例见[契约边界](research/2026-10-12-development-conditions.md#清-lint保留异步调用契约还是删除-async)。豁免不能替代行为验证。**[社区／一手；经验：采用判断]**

GitClear 的重复与移动信号只提示检查复用和结构，不能设重构配额或证明当前项目维护成本上升，见 [09](09-review-and-quality.md)。**[一手：厂商材料；研究：采用边界]**

**局限**：群体相关性不能证明当前 Agent 必然倾向复制，重构是否正确仍由本项目行为对照决定。

## 5. 大规模迁移与升级

**✅ 先选改法，再试点扩量。** 同类调用有现成工具就优先复用；语法规则处理来源和形状明确的重复变换，跨文件引用、继承或类型缩窄优先类型／框架迁移器，例外交 Agent 补丁。试点按这些差异选样。TanStack 有省工与成功退出却漏改的报告，Angular 会跳过不兼容情形，见[维护链与源码](research/2026-10-12-development-conditions.md#重复代码迁移语法规则类型分析与第二次执行)。**[一手／社区；经验：采用判断]**

**依赖升级失败，先收窄坏组合，再决定是否扩大迁移。** 已确认 ABI 不兼容时可临时限制传递依赖；若直接依赖新版已补正确约束，优先评估排除其坏旧版，并按仍支持的解释器分段设置下限。保留其他必要上限，再验实际解析组合及业务入口。[Airflow 的分段修订](research/2026-10-12-development-conditions.md#依赖解析修复排除坏组合同时保留支持面)保留了旧 Python 与 SQLAlchemy 约束；它不证明所有 ABI 故障都能只改版本声明，兼容组件仍缺时继续限版或修构建。**[一手／社区；经验：采用判断]**

**依赖与数据边界明确后，再选批处理。** 脚本调度可用 `claude -p`；并行或 `/batch` 只拆可独立验收的单元，共享接口、分析范围或持久状态相关步骤按依赖处理，再验整合结果。worktree 不保证语义独立，检查也不授权高影响操作；官方小批试跑不是通用样本门槛。见[官方契约](research/2026-10-12-development-conditions.md#批量入口先选改法再选执行方式)与 [08](08-multi-agent.md)。**[一手；经验：采用判断]**

**准备重试或复用时，检查第一次产物再跑是否还会变。** 核对分片归属、调用次数、已迁移调用与跳过原因；一次性迁移器从固定可恢复起点重做。重复变换、覆盖不清或例外过多就暂停扩量，修规则或退回局部补丁。需求改变契约须改规则并复验旧行为；零 diff 不等于语义正确。上述历史证据不证明当前 Agent 净收益或缺陷仍存在。**[一手／社区；经验，证据同上]**

**交互试点转脚本时，保住必要项目知识。** 普通 `claude -p` 加载项目上下文，`--bare` 跳过 `CLAUDE.md`、Skill 等自动发现；已审查的可信项目需要约束时保留普通模式，或显式提供本次必要上下文与工具。`--bare` 自 2.1.286 起不启动后台任务，超时命令会停止，依赖后台构建就保留支持该路径的运行方式。外来仓库先按 [10](10-security.md#3-防护原则)限制启动配置。见[契约与版本](research/2026-10-12-development-conditions.md#交互试点转脚本bare-不是等价加速)。**[一手；经验：采用判断，未运行客户端]**

跨语言沿真实路径检查“谁分配 → 返回后谁用 → 何时释放”，将失败转成内容与清理回归。[VibeTunnel](research/2026-10-12-vibetunnel-maintenance.md) 的释放修复还需纠正 allocator 绑定对象。**[一手：维护补丁；经验：采用判断]**

混用版本或降级时，让旧版本读取新版本实际写过的状态，并检查恢复后后台任务是否再生成不兼容产物。[Git MIDX 默认格式回退](research/2026-10-12-vibetunnel-maintenance.md#持久状态回退git-midx-的旧读取者边界)保留显式新格式能力、收窄普通写入；没有原用户最终复测。**[一手：非 AI 历史机制；经验：验收建议]**

**配置回退应保留既有数据的读取能力。** 关闭新格式写入后，用开启前后及关闭后写入的混合数据，分别验正常服务和导出／恢复命令；同版本关开关不等于旧版本可读。n8n 的[读写拆分与命令初始化修订](research/2026-10-12-development-conditions.md#n8n配置回退与独立导出入口)支持此检查，导出测试未独立运行。**[一手／社区；研究：采用建议]**

**迁移回退还要验升级期间的业务变更。** 恢复旧快照或删除新系统数据前，明确恢复时间点和会丢的新增／修改，在隔离数据上验证恢复，再由负责人决定保留、转换或接受损失；仅损失明确接受且恢复已验证时才有条件强制回退。[Grafana 历史记录](research/2026-10-12-development-conditions.md#grafana回退的恢复时间点与保护性拒绝)中，清表能启动却丢了警报；未独立运行。**[一手／社区；经验：采用判断]**

试点须覆盖跨文件行为与资源契约；职责改变后向当前负责服务查询，避免仍在旧层扫描或重建状态。见 [Scion 复盘与反例](research/2026-10-12-development-conditions.md#迁移后的事实归属与旧调用方式)；机械改名不必套全部检查。**[一手：自述，未复测；经验]**

## 6. 补测试

**✅ 用独立的预期保护行为，再确认测试能发现相关错误。** **[经验：采用判断]**

- 保护既有正确行为的测试可以直接通过，预期来自契约或独立依据
- 修 bug 优先 red/green：旧版本失败、修复后通过；关键断言可用反例或变异检查
- 通过公共接口观察结果，测试名写行为，避免断言 mock 返回值或照抄实现算法

主要依据是 Willison 的 red/green TDD 实践与[公共边界测试 Skill](research/2026-10-12-community-source-records.md#3-matt-pocock控制权与领域语言)。**[社区；一手：配置]**

**✅ 测试能失败，还要确认本次选中了相关消费者。** 依赖、预打包配置或非模块夹具改变时，显式跑已知消费者测试，或用已有触发映射；不只凭 `changed`／`related` 成功退出收尾。选择符合预期就保留原生增量运行，不必另建依赖图或加 reviewer。

**外层“代码未变”的缓存若跳过原生环境检查，应撤掉该短路。** 配置、锁文件或共享设施使映射失效时，先核已有扩大运行／重建路径覆盖变更，再恢复增量；扩大范围仍要核过滤条件。见 [Vitest 与 Polylogue](research/2026-10-12-development-conditions.md#增量验证已有回归测试是否真的被选中)。选择器只覆盖可见关系，选中通过也不证明未表达的兼容要求。**[一手／社区；经验]**

**🧪 新增选测能力前，先看慢在哪、常改什么。** 保留可靠的原生选择器；新增一套前，比较修慢夹具／重复扫描和已有安全并行。测试仍是瓶颈、常见改动能有效缩小范围，才计入映射建立／刷新和漏选补跑成本后试用。见 [remote-store 暂缓引入的试验](research/2026-10-12-development-conditions.md#新增选测能力先比较改动类型与完整运行成本)；单仓种子试验不代表日常改动，也不授权撤检查、放宽隐私或全部并行。**[一手：报告；经验，2026-10-16 UTC]**

接入外部格式或协议时，用目标版本生产者的公开、可脱敏产物校准预期，允许据独立证据修正旧断言。[RTK 编码修订](research/2026-10-12-development-conditions.md#外部生产者校准错误预期)同时纠正实现与测试，本仓注释和测试一致不等于兼容。**[一手；经验]**

**预演还要保住下一次正式执行的边界。** 除业务数据不变，还须防止预演更新下轮接受配置或判进度的状态；从已有基线连续验“修改→预演→普通执行”，该拒绝的仍拒绝。日志和隔离产物可以保留。rclone 修复只阻止提交规则 hash，保留预演列表，见[修订与入口差异](research/2026-10-12-development-conditions.md#rclone预演不能替下一轮提交控制状态)；历史报告不是本仓复测，CLI 修复不证明所有 API 传参已生效。**[一手／社区；经验]**

新增写入路径须同时验业务行与派生版本／审计状态；序列化判等既测可接受类型，也测业务不同的值能否区分。[sqlite-chronicle 修订与固定 SQL 实测](research/2026-10-12-development-conditions.md#写入路径扩展与序列化判等sqlite-chronicle)中，BLOB 写入修复仍让含 NUL 文本漏报版本变化。**[一手；经验：局部实测与建议，未运行包 CLI]**

**🧪 输入组合多、契约可表达且执行便宜时，补小范围属性测试。** 从文档和真实调用找不变量，用已有环境搜反例；失败先核属性与有效输入域，再固定输入、版本和随机条件。[NumPy 与 dateutil](research/2026-10-12-development-conditions.md#属性测试搜索反例不等于确认或修好缺陷)分别显示找到缺陷仍需人工分析、跨构建修订，以及日历语义误报。**[一手；经验：采用判断]**

**局限**：不能运行旧版本时保留回归缺口，但不要求每个新增测试都先在正确代码上失败；属性自身可能错误，属性通过也不证明所有精度、分布或业务要求。

## 7. 性能优化

**✅ 先给 profiler/基准、实际规模输入与完整命令，写清不能改变的行为。** 一次改一项，保留前后数据，多次运行看中位数；运行正确性测试，并按改动机制补旧测试漏掉的行为。**[经验：采用判断]**

**正确加速未达目标时，按新热点和剩余预算续改；只见 native 入口就先补内部耗时。** 保留各轮补丁与验证，选满足必要行为和目标负载的候选，不自动交末版或追单负载最高数；满足目标、无新依据或预算到限就停。见 [PerfAgent 评估与反例](research/2026-10-13-domain-skill-contract.md#性能续改观测层与候选选择)；发布材料运行身份未完全对齐，不证明当前客户端净收益。**[一手；研究]**

**探索不同实现时，先比较轻量候选搜索，再决定是否接完整进化框架。** 成本含未形成候选的生成、失败重试和复评，并为独立复评留预算；评分波动时先廉价筛选，再独立重测竞争版本，并留未参与选择的输入验收。见[比较与记账边界](research/2026-10-13-domain-skill-contract.md#竞争实现先比较轻量搜索并为复评留预算)；数学／AIME 实验不证明生产收益，单线续改与多候选也未完成同条件净收益验证。**[一手：论文与源码；研究]**

**✅ 搜索赢家交付后，保留内核与扩大快路径是两项决定。** 接收方新增类型、比较器或规模时，按其负载选择：范围明确且收益成立就留窄快路径，其余走已有实现；共享分派退化时拆开内核与入口判断回滚，不用大输入收益抵消小输入损失。见 [libc++ 接管与重投](research/2026-10-13-domain-skill-contract.md#搜索赢家接管后保内核还是扩大分派)；这是历史 RL 与人工接管，无新负载或入口变化时不必重建搜索。**[一手／社区；研究，非当前 LLM 净收益验证]**

**功能正确且 profiler／调用链显示转换、分配或复制占比明显时，先查能否消除多余工作，再考虑缓存或快路径；算法或 I/O 是瓶颈则先处理它们。** 删复制前核下游实际内核的布局契约，不接受就保留必要物化或限制支持路径；[SGLang 回滚与重投](research/2026-10-13-domain-skill-contract.md#消除复制前核对下游布局契约)表明 `view` 换 `reshape` 不保证恢复复制。[pandas 补丁](research/2026-10-13-domain-skill-contract.md#性能质量先消除表示转换与重复复制)则利用既有后端与隔离减转换／复制，仍保留缺失掩码及复制／别名语义；均不证明当前 Agent 或完整 Skill 净收益。**[一手；研究]**

**批处理优化先确认：只改批大小，结果是否应相同？** [alchemy-utils](research/2026-10-12-alchemy-utils-evolution.md) 在不同批大小下出现默认值／保留旧值与 NULL 差异。先定缺失与显式 NULL 契约，再验跨批回滚、schema 推断、默认值与旧文档；全局推断和立即流式写入冲突时，由人选预扫、缓冲或接口变化。明确目标即可优化，无须装完整流程。[程序与输出](../experiments/alchemy-batch-semantics/README.md)已核对，但运行是对端报告，非本侧 API／性能复测。**[经验：报告；一手：源码；研究]**

## 8. 代码评审

**✅ 用独立上下文审 diff，只报会阻止合并的具体问题。** 给评判标准，不灌入实现过程中的推理；每条包括文件、行号、失败条件及证明方式。工具可选 `/code-review`（`--max-findings`）、`/ultrareview`、Codex Security Cloud 或 CodeRabbit，见 [09](09-review-and-quality.md)。**[一手：官方用法；经验：采用判断]**

**局限**：追改每个挑刺会增加过度设计，评审“通过”也不能替代实际验证。

## 10. 原型和一次性脚本

**✅ 先验证一条值得完成的任务，再决定补哪里、保留多少。** 以下四步是从研究与案例提炼的采用建议；按当前问题选用，不必给每个原型加齐所有检查。**[经验]**

1. **定核心任务、推翻条件与替代范围。** 给 Agent 使用者的任务、必须保留的系统及输入输出，比较直接复用、窄补充与完整替代，再做能独立完成有用一步的产物。看实际接入，不只看抱怨或请求；补充层丢必要语义、让错误角色操作，或须补齐全流程才有用时，重划范围。[Segment 与 Tract](research/2026-10-13-product-feedback-contract.md#替换哪一段工作流segment与tract的范围选择)支持比较，不支持“越小越好”。**[一手／社区；经验]**

   一次性任务完成一次可能就够，重复任务再看下次是否值得用；未迁移、未付费或一次负反馈不能单独判无价值，原型也可发现新需求。比较结果、可用性、数据边界与运行责任，删代码或更早停止不必然更好。见[创业试验及反例](research/2026-10-13-product-feedback-contract.md#需求成立与否试用也可以导向停止)、[Jules 替换](research/2026-10-13-product-feedback-contract.md#jules从自建常驻服务到现成运行能力)。**[研究；一手／社区]**

   **同仓新增命令，先比较复用完整命令还是底层操作。** 核锁、错误处理、输出与参数的组合成本；成本高可复用规则与底层操作，保留独立入口和必要分步。见 [Restic](research/2026-10-13-product-feedback-contract.md#restic复用命令还是底层操作)。成熟 CLI 契约合适仍可用，不建议外部调用私有 API；分步交付仍须验使用者最终结果。**[一手／社区；经验]**

2. **用真人任务区分反馈。** 让试用者解释结果并完成任务；复访时“尚无机会”延后判断，“没理解”核含义，“运行失败”复现，“没有价值”查是否减负或拿走必要选择。见 [Motif](research/2026-10-13-product-feedback-contract.md#原型复访尚无机会不等于不值得使用)，短期自报不代表留存。Agent 可提反例和试用顺序，[模拟反馈](research/2026-10-13-product-feedback-contract.md#模拟用户可以帮助选测试不能单独否决需求)不能独自否决必要功能或产品。**[研究；经验]**

3. **围绕明确收益改进，再跑真实输入与连续操作。** 功能正确也可改善层级、引导与响应；先说明哪个操作更易理解或完成，复用已有状态和版面。按真实规模及依赖分别验“看懂”和“完成”：步骤关系可见，并列能力不为装饰编号，品牌独特性另判。见 [CodeAid](research/2026-10-13-product-feedback-contract.md#修改版再使用可见性改善仍须通过真实任务)、[CodexBar](research/2026-10-13-product-feedback-contract.md#codexbar发布后的理解反馈)、[领域质量反例](research/2026-10-13-domain-skill-contract.md#质量提升领域依据目标与过程分开判断)。**[研究／一手／社区；经验]**

   - **自动采集的杂项淹没有用内容**：先比较采集准入与重复规则，再决定是否加搜索或整理功能；按用户实际来源连续操作，核有意短输入是否被误丢。过滤范围与默认值分别定，重复内容可保留旧对象并移到前面。[Buffer](research/2026-10-13-product-feedback-contract.md#buffer自动采集的噪声先改入库还是继续加功能)原用户自编译适配版后报告改善，随后补丁合入；仅支持该工作流，不证明正式发行后的留存，也不是隐私防护。**[一手／社区；经验]**
   - **结果不对或确认了旧对象**：选项可见仍错，核[实际参数与默认值](research/2026-10-13-product-feedback-contract.md#openwhispr选项出现后仍须核对实际参数)。搜索分清准入、排序和输入次序，再选场景排序、保序或查询放宽；全词命中不必关闭容错。已有候选过滤与整库检索分别选延迟，按正常速度验“输入→确认”，再选缩短等待、提示或提交保护，不放慢测试掩盖错选。见[搜索取舍](research/2026-10-13-product-feedback-contract.md#搜索改进结果准入排序与输入次序)、[连续操作](research/2026-10-13-product-feedback-contract.md#keepassxc连续筛选后确认的是哪个对象)；延迟不能照搬。**[一手／社区；经验]**
   - **看得见却不好用**：先分辨认对象、核对输出与编辑数据，再选摘要、预览或原编辑入口，不统一默认。短查找与持续结果集可分入口，但须交接查询、结果和未完成搜索；可编辑预览另定保存、退出与撤销，关闭不等于放弃。见 [Zed](research/2026-10-13-product-feedback-contract.md#zed查找与编辑共用结果不等于共用退出语义)（后续 fork 仅单人自用）。持续对照所需的条件与结果保持可见；有阶段依赖可分步，但说明预览范围、更新状态和返回路径，局部预览不替代完整核查，自动图表未必适合先查数据。让熟悉后的原用户重做任务，字段保留不等于原路径无损。见 [Zotero](research/2026-10-13-product-feedback-contract.md#zotero结果预览与原编辑入口如何取舍)、[Metabase](research/2026-10-13-product-feedback-contract.md#metabase同屏条件与分步预览的竞争取舍)、[Home Assistant](research/2026-10-13-product-feedback-contract.md#home-assistant字段保留与原操作路径是两回事)。**[一手／社区；经验]**
   - **连续输出跟不上**：追最新状态可合并过时进度；按序消费则比较队列、分批与取消，并验积压和取消后的新输出。可回看或跳过提示不能替代原自动阅读和必要结果。验短结果紧跟提示符、大量输出及中断后内容；漏结果或无法及时中断就撤回统一策略，按任务与宿主重选。见 [NVDA 反馈与回滚](research/2026-10-13-product-feedback-contract.md#nvda追最新状态还是按序消费输出)；队列是待验证候选，非已交付替代。**[一手／社区；经验]**
   - **往返时反复找位置**：比较保留位置、显式跳转与改布局，区分可滚到、可聚焦和快捷键。分别定首次、重访和返回落点，追加／刷新不抢焦点；按目标浏览器／读屏组合连续验，换浏览器成功不替代原环境。见 [Joplin 与 Discourse](research/2026-10-13-product-feedback-contract.md#joplin与discourse导航可达之后保留任务位置)。**[一手／社区；经验]**
   - **省步后仍有重复负担或不能恢复**：自动结束分别验成功后下一次和失败后恢复；抢走重试机会就按结果状态收窄。反复补同一步时，区分一次性操作、持久偏好和全局默认，调整入口／保存范围，用新对象、连续操作及重开验，不必整项回滚。见 [LocalSend](research/2026-10-13-product-feedback-contract.md#localsend省掉完成点击后为何收窄自动结束)、[GIMP](research/2026-10-13-product-feedback-contract.md#gimp一次性合并与记住工作流选择)；后者只确认已有选项恢复并重开记住，非全工具覆盖或新补丁效果。**[一手／社区；经验]**
   - **重复提交或编辑后想反悔**：再次表达意图、重试与明确重新入队分别处理，核保留状态和排序，不按调用来源猜目的。防丢失、检查点和可放弃试改也分别选；命名版本／保存确认不等于“试运行后决定”，须核画布、持久草稿与发布边界，连续验“修改→试运行→放弃或保留”。[Karakeep](research/2026-10-13-product-feedback-contract.md#karakeep重复对象不等于重复意图)保留对象／创建时间仍改归档排序；[n8n](research/2026-10-13-product-feedback-contract.md#n8n自动保存稳定检查点与可放弃的试改)避免运行旧定义仍未恢复未保存试运行，均不支持一律加设置或关自动保存。**[一手／社区；经验]**
   - **协作中只想撤回自己的操作**：复用本地历史，保留无关远端贡献，另定同对象同属性冲突；验“本地改→远端改→撤销→重做”。同属性或组合对象仍可能覆盖远端值；单人整体回退仍可用快照，不默认加框架。见 [Excalidraw](research/2026-10-13-product-feedback-contract.md#excalidraw撤销自己的操作与恢复整份旧文档)。**[一手／社区；经验]**

4. **由负责人决定保留、缩小、复用或停止。** 需求仍在但维护不成立，可暂停实现；现成能力变化后重比外部处理、窄集成与重建，核目标人的平台、格式、任务数量、时效与失败可见性。单样本成功不证明整批被替代。见 [Mealie](research/2026-10-13-product-feedback-contract.md#mealie撤掉实现不等于撤掉需求)。**[一手／社区；经验]**

   - **要退休旧实现**：默认采用与删除旧路径分开决定；交互和后台／批量组件分别验，兼容开关不保证能回旧实现。缺必要能力时比较窄适配、兜底或缩小支持，不凭局部成功退休，也不永久默认双实现。负反馈若要求恢复旧绕路，先核是否重引工作不可达；比较修复加取回入口、窄适配或缩小支持，并说明额外负担，关反馈不算迁移成功。见 [GitHub Desktop](research/2026-10-13-product-feedback-contract.md#github-desktop保住工作与保留旧绕路)、[VS Code](research/2026-10-13-product-feedback-contract.md#vs-code默认采用与退休旧实现分开)。**[一手／社区；经验]**
   - **要减少组件**：核可选能力是否变成基础硬依赖。仍支持不开功能的用户时，验安装、启动与升级，再选合并、隔离或缩小支持；功能开关未必隔离迁移。见 [Immich 历史变化](research/2026-10-13-product-feedback-contract.md#immich减少同步层也改变基础运行的依赖)，非当前部署指南。**[一手／社区；经验]**
   - **要保留窄适配**：目录缺项先比配置更新或动态发现，参数／返回值／流式变化仍须改代码并验证。必要任务反复需接收者手改且无人更新时，重比受维护连接、集中适配或缩小支持，少一个容器不等于少负担。见 [Open WebUI](research/2026-10-13-product-feedback-contract.md#open-webui少一个服务之后谁维护协议适配)；不同用户与后续镜像不是同人长期对照。**[一手／社区；经验]**

   接入真人或持久化前补身份权限、数据隔离、迁移兼容、备份恢复、错误处理和回归；交付核许可、持续成本与接手者。交付失控先核部署版本，用虚构数据走跨角色路径；试用遵守隐私和授权，越界先问。见 [KPI 反例](research/2026-10-12-codex-delivery-cases.md)及 [23 前端验证](23-browser-verification.md)。**[社区；经验]**

**证据边界**：材料是不同项目的局部机制与使用报告，不是当前产品推荐或本仓新实测；局部回执不代表全路径、长期或四步整体有效。各链未复测项、版本及反证见研究链接，不能跨案例补齐，也不证明 AI／固定 Skill 净收益或维护总成本下降。**[研究：范围限定]**
