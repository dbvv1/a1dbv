版本：v1.3 · 2026-11-04  
状态：已完成 Claude 与 Codex 针对性复核；用户已确认作为正式实施依据

> 本 SPEC 定义本阶段改造范围，不自动扩大现有生产授权。现有 AGENTS、LONG-TERM-PLAN、TASKS 和授权红线继续有效。

# 1. 核心目标

当前首要问题不是缺少通用调度基础设施，而是 Dot 醒来后没有稳定地把时间转化为高价值交付：局部未知被当成全局阻塞、任务队列准备不足、容易完成的窄任务挤占高价值工作、成果停留在提案而没有进入页面或作品、旧规则和配置没有随决定同步更新。

本阶段目标：提高 Dot-A/B 每次唤醒后的有效工作产出；保持明确的后续任务；让本机低成本模型承担更多可验证工作；减少 Claude/Codex 订阅用于日常重复执行；及时接收成果；修复已证实的接收端缺陷；精简长期规则和重复机制；先用真实业务结果验证改善，再决定是否建设更复杂调度器。

**本阶段不建设通用 Orchestrator、SQLite 平台或完整运行仪表盘。**

# 3. Dot 每次唤醒的固定工作循环

此循环替换旧规则，不追加并列清单：

1. **接收结果**：先检查已完成、失败、unknown 和待审查工作。能接收的成果当轮接收；无法转化或不符合目标的提案明确放弃或退回。
2. **推进主成果**：优先把研究、提案和实验转化为答案页、模板、知识模块或案例的真实改进；完成标准是目标成果实质变化，不是增加任务卡或研究文件。
3. **补足预备任务**：每条活跃工作线保持一批规格明确、可独立执行的 ready 任务。初始可试每条线 3–6 项，按容量调整，不作为 KPI。
4. **派发并行工作**：明确、可验证、写入范围独立的任务优先交本机低成本模型；Dot 后台代理和云电脑承担适合的工作，为接收、审查和整合留容量。
5. **完成有效单元**：Dot 推进最重要目标；在途工作按真实进展续接，云端易丢失的工作按现有规则推送到可恢复分支。
6. **局部处理未知**：确认原动作及相关写入者结束后，只对已知无外部副作用、相同输入下可安全重复的步骤作有界重试。无法确认时只暂停对应动作，继续独立工作。
7. **更新并继续**：有实质变化时记录成果；无变化时写明卡点和下一步。Dot-A 两小时回执并入本步骤。等待用户批准的事项写入 TASKS「需要用户决定」，同时继续独立工作。沿用普通单元 2 小时、探索单元 4 小时硬上限；到上限先保全产物，再按原任务恢复合同续接，不得每次从头重试。

## 3.1 选题与收口

优先解决读者/玩家价值、核心能力和作品品质的真实差距，不因任务窄或容易完成而优先。按负责人实际接收能力控制在制工作；积压增长时优先接收、整合或延期，暂缓同类新开工，不得因数量上限自动删除有价值产物。A 看读者地图、答案页和模板实际变化；B 看模块成熟度、案例记分卡、内容覆盖和默认版本变化。不以提案数、任务卡数、提交数或心跳次数代表进展。

# 4. 任务队列与接收端

第一阶段继续使用现有 GitHub Markdown 任务卡、local-jobs、本机接收端、Dot 每小时心跳、接收端周期扫描、独立 worktree、结果分支和公开扫描。不新建通用调度器，不重写已可用的任务发现、领取、模型调用、工作区和结果回传能力。

# 5. 接收端差量修复

以接收端 c04201a 为基线。该版本已实现按 PID 与创建时间核登记进程、重新检查旧 unknown 隔离、收集声明的超时部分产物，并已有失败重试与次数上限；两份广扫产物已回传，现有 41 项测试通过。不得重做已完成能力，只补真实缺口。

- **进程退出**：主 CLI 关闭后，以登记进程身份（PID、创建时间等）核对是否仍有子进程/写者。确认写者退出后，不因历史 unknown 阻塞产物；仍有活跃写者或身份无法核实时，只暂停该产物收集/发布。不能仅凭主 CLI 退出推定所有外部调用结束。
- **安全重试**：确认原动作及相关写入者结束、没有可接收结果后，仅对已知无外部副作用且幂等的步骤重试一次。次数按同一输入修订/执行单元累计，进程重启不得重置。不得盲目重放外部副作用。
- **无人登录启动**：已有 S4U 探针失败记录 0x8007051F/1311，密码登录配置草案尚未注册。不要重复诊断；只有启动条件或凭据方案变化时再测。保存账号凭据必须先由用户决定。

# 6. 未知与成果验收

**未知只阻塞对应动作，不阻塞全局工作。** Fetch/检查失败不能只按名称判断是否安全重试；先确认原动作和写入者结束，再核对副作用和共享资源。部分产物可进入 review_ready 并注明未完成审查。外部写入结果未知时先检查远端是否已生效。无仓库交付且无本机运行证据只记为「待核活动缺口」，结合 Dot 实际活动证据后才能归因为停工、等待或正常执行。

Task / Attempt / Artifact / Acceptance 是 SPEC 设计模型，第一阶段不要求 Dot 手工维护四套字段，也不写入每次必读规则。Codex 在接收端按需生成简洁的当前结果格式，优先映射现有记录，不引入复杂通用状态数据库。部分产物可接收；accepted 必须绑定具体范围和版本。

# 7. 模型与成本

Dot 后台代理和云电脑是主要云端执行资源；本机 DeepSeek 等低成本模型承担规格明确、可验证任务；Codex GPT-6.1 Sol 用于需要 Codex 专项工程能力的工作，确实困难时可升级 GPT-6 Astra；Claude 用于方向指导、复杂问题和高价值判断。

P0–P3 表示任务重要性和风险，不是模型排名，也不在第一阶段写入 Dot 每次必读规则。P2/P3 资源映射允许动态调换。Dot 按难度、成功概率、质量风险、等待时间、额度和历史表现选择资源；可只升级困难子任务，不强制逐级升级。

Dot 可在实际已验证的入口内直接派发 Codex 工作会话。云端 Dot 与本机 Codex CLI 是否可互相控制，必须实测；不可用时沿用指导席位派发明确子项，不得模拟登录或使用非公开接口。

分别记录实际模型提供方、模型 ID、执行入口、可观察调用量、订阅使用和 API 费用。不可观测值标 unknown。目标是降低总投入和低价值订阅消耗，不为追求零订阅而反复让弱模型失败。

由 Claude 核心会话负责精简。长期规则（手册、细则、A/B 提示词）目标从约 38 KB 收敛至 20 KB 以内；同时检查 Dot 每次读取的 TASKS、local-jobs README 和模板 Skill（合计约 77 KB）。删减重复说明、迁移按需知识，但不得为达到字节目标删除权限、生命周期或安全语义。

同一规则只保留一个权威位置；用替换旧文字代替持续追加；临时纠偏完成后删除；研究过程和回执不进入长期提示词。

# 10. 进度指标

第一阶段不新建完整仪表盘，扩展现有 progress.mjs 或已有进度入口：
- Dot-A：读者地图新增/升级的问题、答案页和模板实际改动。
- Dot-B：案例记分卡、知识模块成熟度、内容覆盖和默认版本更新。
- 系统：结果交回到被接收的等待时间、用户介入次数、待核活动缺口时长。

指标必须说明时间窗口和数据来源。任务拆得更碎不能自动增加有效成果数。失败、取消、部分接收和 unknown 分开记录。不可观测状态标 unknown，不包装成在线或空闲。

# 11. 两至三周验证

2–3 周是观察窗口，不是日历到期自动判定成功。样本不足就报告不足。

观察 A/B 是否持续有明确后续任务；是否减少超过 4 小时的待核活动缺口；本机接收端利用率是否改善；结果回传后是否及时接收、合入或明确放弃；地图、模板、模块和案例默认版本是否实质推进；用户介入是否减少；返工、重复调用和质量缺陷是否增加。

若改善主要来自工作循环、队列和规则精简，不建设新调度基础设施。地图状态、记分卡、正文修改和默认版本更新只是结果线索，必须关联可感知的读者/玩家改善；同一成果跨页更新只计算一次。

# 12. 何时才引入更强调度基础设施

只有真实证据表明多个宿主争抢任务、状态冲突导致重复执行/成果丢失、现有扫描造成可量化接续损失、接收端无法恢复真实调用，或跨账号运行确实需要共享状态时，才评估 SQLite、通用租约、Watchdog、事件总线或 Orchestrator。

引入前必须明确唯一运行状态所有者、宿主、离线行为、Git 与运行态冲突处理、旧执行者写权失效和回滚方案。不能预先认定 SQLite 是答案。

# 14. 测试、回滚与安全

测试覆盖：Fetch/读取失败只阻塞单步；重试前核原动作和写入者结束及副作用；主 CLI 退出但子进程仍写入时不得发布；确认写者退出后能收集部分产物；失败重试次数跨重启累计；外部写入结果未知时先对账；本机接收端离线和恢复；A/B 维持 ready 任务；提案进入正式页面/模板/作品或被明确放弃；旧规则改变后同步回扫脚本、配置和测试。

现有运行流程在新循环和接收端修复验证前继续可用。新代码先在独立分支和隔离任务中测试；不得让新旧接收器同时领取同一任务。切换失败时停止新改动，保留成果和原任务状态，按现有授权恢复旧路径。外部副作用先核实是否已发生。

继续遵守 AGENTS.md 授权红线、公开仓库扫描、凭据与私人数据隔离、单写者、Git 快进发布和不强推规则。

# 15. 成功标准

1. Dot-A/B 每次唤醒能处理结果、补足任务并推进有价值目标。
2. 有 ready 工作时，不因局部 unknown、等待批准或单项故障而全局停摆。
3. 本机接收端有持续、有效的明确任务，而不是长时间空队列。
4. 研究和提案及时进入答案页、模板、知识模块或案例，或被明确放弃。
5. 旧约束随规则变化同步修正，长期规则明显精简。
6. 用户反复催办和协调指导席位的次数下降。
7. Claude/Codex 订阅用于高价值指导或必要工程，不被日常重复工作消耗。
8. 质量、返工和总投入没有因追求速度而恶化。

不预设未经测量的百分比目标。先建立基线，再比较同类任务的完整交付和质量。

**核心思想：先让 Dot 每次醒来都能持续做正确的事，再根据真实瓶颈决定是否建设更复杂的调度基础设施。保留有效系统，修复已证实缺陷，删除冗余机制，以实际成果而不是活动量衡量效率。**
