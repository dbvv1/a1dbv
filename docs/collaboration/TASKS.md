### D6 · 主力 Codex：从问题到最小改变

- **目标**：读者不需要读完机制研究，就能决定先怎样开展任务，何时才值得调整工作流。
- **范围**：现有 Codex 第 6 节为主，15 提供入口；Claude 页只补必要差异。不要新建一套通用提示模板或配置集合。
- **内容**：围绕明确 bug、存量新功能、探索原型、跨会话任务，分别写最少输入、原生起点、需要人的决定、出现什么具体失败再加哪项能力。区分领域知识 Skill、工具扩展、工作顺序约束和验证反馈，不仅比较品牌。
- **证据起点**：已有 Codex 机制调查、Cookbook 不同协作方式、官方 Skills/Superpowers 对照，以及 Catalog Compare/h3o 案例。可补新证据，但不要把旧示例参数当成当前 Astra 推荐。官方文档、用户报告与本仓库判断分开。
- **新补的具体比较**：方向正文已读 Matt Pocock TDD 的用户确认要求，以及 Superpowers 调试 Skill 的依赖和停止阈值。比较“公共接口/独立预期”等有用知识与额外控制环节，不将小文件直接称为低成本；无来源的 95% 比例、三次失败即架构错误等不作为事实采用。
- **验收情境**：① 目标明确且已有失败测试时，不被额外访谈拖住；② 首输出慢与测试运行慢不会得到同一条“降低 effort”建议；③ 原型试用后需求改变时，能继续探索而非被旧 spec 锁死；④ 已跨会话但状态足够时，不强制安装记忆服务；⑤ 仅缺新框架 API 知识时，不默认安装完整流程。
- **结果要求**：给出当前建议和改变建议的条件。无受控对照时不报提速、成本或成功率数字。没有必要为文档验收运行付费模型。

### D7 · 深度分析：保留判断，修正过度推论

- **目标**：使 14 成为可借鉴的判断框架，而非将当前观察写成永恒定律。
- **范围**：先处理开篇的普遍解释、规律一的能力表与评审推论、规律三对人的作用；其他章节只处理相同结论的直接引用。不要全仓重写。
- **修订依据**：[方向正文中的推理审查](../research/README.md#分析文章自身也要接受反驳)。另看实施端已修正哪些句子，保留正确改动，不重复指责旧版本。
- **完成条件**：区分“验证器是否可靠”和“Agent 是否能找到正确实现”；不以容易检查断言模型近乎完美；不以没有唯一答案断言 Agent 只能模仿；不以评审与生成共用模型为由断言评审无增益。将人的需求发现、反馈与学习纳入建议，允许先原型再设计的情境。
