# Brief: 游戏知识与 AI 制作链审计（Web 优先阶段）

**审计席位：** GPT 专业聊天 02  
**主仓库：** https://github.com/dbvv1/a1dbv  
**关联案例：** FPS-Like、MOBA-Like、Star-Rush-Reborn

## 1. 当前使命与阶段边界

本方向的核心使命：帮助一名程序员、没有专职美术和音频人员的条件下，借助 AI 将独立游戏从概念推进到可发布质量。研究必须服务于实际制作选择、完整工作流和案例质量。

**当前生产与验证阶段以 Web 游戏快速开发为主。** 当前优先验证 AI 是否能在 Web 技术栈中完成端到端游戏制作和持续迭代，包括玩法规格、代码、模拟、渲染、UI、2D/3D 资产、动画、材质、特效、音频、接入、测试、浏览器运行、第二次需求修改和质量验收。

**当前不要求把生产主线迁移到 Unity 或 Unreal，也不要求现在完成 Unity/UE 原生垂直切片。** Unity、Unreal 内容可以作为知识储备、官方能力参照或未来扩展专题；除非用户明确改变方向，不能把原生引擎接入、MCP/CLI 实测或引擎项目交付列为当前阶段 P0/P1。

Web 优先不等于只检查“有没有 Web 技术内容”。必须深入审计现有 Web 方法、工具链、资产质量、工作流、验证能力和实际案例的质量；网页同样以高品质为目标。

## 2. 审计范围

- `domains/game-dev/` 全部核心模块与制作链。
- Web/TypeScript/Vite/Three.js 等当前案例实际采用的技术路线。
- 客户端、模拟、物理、AI、输入、相机、渲染、UI、音频、性能与浏览器兼容。
- 2D/3D 资产、材质、特效、光照、角色、场景、动画与音频制作。
- AI 生成资产的质量、许可、可编辑性、导入、接入、二次修改和批量一致性。
- AI Coding Agent 在游戏开发中的实际任务分配、工具调用、测试和长程迭代。
- 游戏制作 Skills、模板、验证流程及其在三个案例中的实际采用情况。

Unity/Unreal 专题只在知识正确性、时效性、与 Web 主线的边界关系或未来储备价值方面审查，不把原生引擎实操作为当前交付要求。

## 3. 核心问题

1. 现有 Web 游戏制作知识是否准确、先进、可执行？哪些默认方案具体有问题？
2. 从需求到可玩 Web 游戏，AI 全链路在哪些环节已跑通，在哪些环节失败或仍靠人工兜底？
3. 生成的 2D/3D/动画/材质/特效/音频是否达到案例实际需要的品质？问题具体是什么？
4. 资产能否稳定接入 Web 工程、保留可编辑源并经历第二次修改？成本、失败率和返工在哪里？
5. 当前测试、无头浏览器、WebGL/Canvas、固定机位截图、性能测量和人工体验的验证链是否足以支持质量判断？
6. 三个 Web 案例是否真正使用并验证知识模块？哪些知识只是文档存在，未在案例中产生效果？
7. AI Agent 在策划、编码、资产生产、调试、验证和迭代中，哪些任务能可靠承担，哪些环节仍需要人做关键判断？
8. 现有内容是否存在错误、过时、重复、缺乏依据或与当前 Web 主线无关的篇幅？
9. 哪些改进最能提高 Web 游戏最终品质、完整制作能力和迭代效率？

## 4. 质量审计要求

不能只列“缺少 Unity/Unreal 实测”或“缺少某个知识章节”。应深入检查已有内容的技术正确性、实现起点、失败边界、可复现性和实际使用价值。

至少抽查：
- 关键页面给出的默认方案是否能按步骤执行。
- 关键 Skill 是否能在真实 Web 案例中完成任务。
- AI 生成资产从产出到接入、二改的完整证据。
- 案例的真实运行、画面/声音/操作和非作者评价证据。
- 当前工具链是否存在更强替代方案，以及迁移是否值得。

## 5. 交付

1. 当前使命与阶段理解（确认 Web 优先，说明 Unity/Unreal 当前边界）。
2. 游戏知识体系的真实成熟度地图。
3. 当前 Web 全链路已跑通、部分跑通、未跑通的环节。
4. 已有技术内容的具体正确性/质量问题及证据。
5. AI 资产与制作链的实际质量、二改和返工问题。
6. 三个案例对知识体系的实证与反证。
7. 应保留、修复、合并、淘汰和暂缓的内容。
8. 当前阶段最高优先级任务候选 3–8 项（不足可少于 3 项），每项给目标、证据、写入范围和可验证验收标准。
9. Unity/Unreal 相关未来储备单独列出，不混入当前阶段优先级。
10. 未验证事项。

Wave 1 只读，不修改生产代码或 main。
