## 总体判断与成熟度

**MOBA-Like 已是具备真实模拟、可复现对局、3D 客户端和工程质量保障的单机 MOBA 原型，不是只有菜单或占位机制的 demo；但尚未证明达到 brief 设定的高质量 MOBA 核心体验。最大差距是玩家能否在真实 GPU 画面和完整对局中，持续清楚、及时、有满足感地完成战斗。**

## 证据与范围

1. `docs/brief.md` 定义约 10 分钟单线 MOBA，重点为技能出手/命中手感、团战可读性、机器人决策像人；视觉目标是 LoL 风格化战场，不能以接入低多边形包视为达标。
2. README 当前描述一名玩家与机器人对战，可选 Veyra/Morrow，对手仍为 Veyra。野区、在线匹配、商城不属于当前阶段。
3. package scripts 提供网页构建、模拟、测试、类型检查和 smoke；技术栈包括 Three.js、recast-navigation-js、Vite、TypeScript、Vitest、Playwright。
4. 本机存档通过原模拟与机器人逐帧复演并核终点哈希；仅同一浏览器存储，不承诺跨浏览器/平台确定性。
5. brief 区分 castStarted、castResolved、castCancelled、basicAttackHit；普攻包含准备、提交、弹体飞行、接触和取消，避免把出手误当命中。
6. MOBA-Like 最新 main 提交修复图标整批导出：staging、完整校验、发布、回滚和恢复现场。提交说明报告 15 项独立复核测试、568 项游戏测试及构建/扫描通过；同时明确非断电持久事务、替换期间不保证持续可读。
7. a1dbv TASKS 记录 Site v22、近期修复与 568 项测试通过；仍将硬件 GPU 画面、操作手感、完整对局列为人工验收。quiet 材质、v12 指令缓冲、镜头＋Q/W 不因 CPU/构建通过而视为整体品质通过。

**证据边界：** 测试数字来自提交说明和项目记录，本审计未重新执行。近期部分浏览器运行回退 Canvas2D，不能视为 WebGL2/GPU 验收。本审计未亲自试玩、试听或完成整局，未取得本轮 GPU PNG/录像和盲评。brief 指定 LoL 官方基础玩法为主参照、Thronefall 为辅助地景参照；本轮未重新试玩或同机位对照。

## 关键发现

### F1 核心战斗可读、可控、有反馈尚未证明达标（高）
brief 的基本战斗是跟兵线进塔前，完成走A/停止、施法命中、受击/护盾反馈、理解塔威胁并撤退；英雄、兵、塔、地面、动作、特效、声音、HUD 应整体提升。工程机制有实质进展，但真实画面是否清楚及时悦目无法从源码推导。近期部分运行自然回退 Canvas2D；项目文档也明确 Canvas2D 缺少 3D 效果、插值和临时跟随。因此页面能跑/tick 能推进不等于核心品质通过。

### F2 当前仍是 1v1 单线，5v5 未实现（高）
brief 的 B 里程碑才要求玩家加九名机器人完成离线 5v5，并验证补兵、交战、撤退、推塔、协同、拥堵和同屏可读性。模拟可配置多单位不代表网页端已有完整 5v5。应先完成 A 阶段基本战斗，再扩 B。

### F3 AI 有决策基础，但“像人”与团队协同证据不足（高）
源码检索确认 HeroBot、难度参数和机器人状态；brief 目标包括补刀、换血、撤退、推塔、支援。最新定量记录主要是 v11 normal 200 局，且未启用 --verify-targets；不能据此证明当前版本高低难度、镜像平衡或 5v5 协同。旧 v8/v9 数据不能代替 v11/v12。需检查补刀时机、危险评估、撤退、目标切换和团队协同决策轨迹。

### F4 GPU/WebGL2 与设备性能证据有缺口（中高）
项目有 WebGL2 主路径、Canvas2D 回退、固定出图入口和 smoke runner；要求显式声明 GPU/software renderer 并保存原始 renderer、构建身份和失败阶段，方向正确。但近期云端运行有时无法创建 WebGL2，Canvas 回退不能证明材质、光照、动画、GPU 性能或目标设备体验。应先取得准确生产构建 GPU 证据。

### F5 导航/单位拥堵存在明确适用边界（中）
brief 对 v10 接触分离限定为已发布凸矩形通路；近点过滤使局部直达检查不是任意凹角/薄障碍的连续碰撞保证；也不是完整 Crowd/刚体系统，不保证任意密度或窄口零重叠。扩展 5v5、复杂地形或狭窄入口前须验证拥堵、卡死、绕行和攻击射程边界。

### F6 平衡数据覆盖不完整，版本结果不可混用（中）
v11 normal 200 局全部终局、无异常/超时/卡死，蓝98/红102，中位约10分35秒；但未启用目标检查。旧 v8/v9 高低难度和镜像数据属于旧规则，不可作为 v11 结论。应补齐同一当前版本的难度、镜像、多种子数据。

## 已有成果处理建议

- **保留：** 固定帧模拟、种子+命令回放、状态哈希、内容版本兼容；LocalMatch 统一拥有模拟/机器人/输入历史；存档逐帧复演；普攻真实准备/释放/接触事件；smoke 构建身份和 renderer 分类；新局成功后替换旧档；图标整批 staging/回滚。
- **修复/扩展：** 基本战斗整套视觉、音频和反馈；AI 决策质量和多单位协同。
- **暂缓：** 5v5、野区、大量英雄/装备、联机按 brief 里程碑推进；先验收或退役现有旁置候选，不增加第四个未验收单元。

## 与标杆的差距

- 战斗可读性：有事件语义和基本 HUD，但缺少可复核 GPU 同屏战斗图像/录像。
- 输入承诺：前摇、取消、释放后走位已进入规则；真实键鼠响应、动画/命中同步、走A连贯度待实玩。
- 命中反馈：已区分提交与真实接触；仍需音画证明命中、护盾、受击、死亡和未命中不混淆。
- AI：有机器人和难度参数；当前 1v1 样本不能代表成熟 MOBA 的补刀、撤退、目标切换与团队协同。
- 内容：两英雄一条兵线是最小循环；阵容、地图目标、视野和内容深度与成熟 MOBA 差距明显，但当前阶段不要求先实现全部内容。
- 视听：已有 3D 场景和制作链，尚无 GPU 实图和非作者评审证明达到目标风格。
