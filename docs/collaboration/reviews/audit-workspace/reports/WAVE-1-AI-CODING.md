## 1. 总体判断
**本仓 AI Coding 知识资产已明显超过一般工具清单／趋势汇编；主要短板已从资料不足转向真实项目净收益、长期质量与独立验证不足。**

应保留“发现 → 试用 → 写成选择”主线。13 前沿雷达、25 AI 探索、explore-frontier、write-task-guide、模型／上下文／长程开发决策页已形成相互衔接的知识生产链；固定源码、PR／issue、补丁、测试、消费者接收与失败记录让内容远超纯二手研究。

但证据密集不等于 AI Coding 总体效果领先。同题模型比较、跨项目可迁移性、长周期开发质量、读者独立采用率和方法净收益仍缺独立证据。近期研究显示：静态单轮 benchmark 难覆盖持续需求变化；真实会话中的开发者纠偏仍普遍；多 Agent 框架不存在可直接外推的普遍赢家。下一阶段应优先做少量预注册、真实任务、独立判分的质量验证，而非扩大研究目录。

## 4. 关键发现（按严重程度）

### F1 · 高：M6 尚未形成证明方法净收益的独立证据链
25 已区分发现遗漏、读取缺口、已读未转化并要求固定参照分母；M6 三题准备材料有硬条件／薄层／未知判定；11-03 周校准冻结两个 HN 查询样本并记录不可读来源。但“无已确认可改变动作的新遗漏”不是 M6 方法成功，旧三题先导也未证明渠道扩展的普遍收益。
**影响：** 候选数、引用数、周扫描完成或局部命中率不能作为成效。应看行动性遗漏、转化缺口、错误推荐纠正、决策质量、复核成本和真实采用。
**建议：** 保留预注册设计；下一轮只选一项自然出现、可客观判定的真实 AI Coding 决策，冻结任务与基线后做独立留出查漏，先验证是否改变选择。

### F2 · 高：长程真实开发质量尚未闭环
long-tasks.md 明确完整实施、整合与消费者验收路线仍待验证；context-management.md 明确原生压缩／新会话仍待真实读者验证。MACBench 显示持续需求变化下 checklist 与严格实例成功存在差距，过多运行时修复可能损害最终功能。
**影响：** 长程任务可能持续推进，却丢约束、产生回归或最终不完整；局部绿灯不代表完整交付。
**建议：** 用一个真实持续开发任务端到端验证：冻结初始需求与后续变更，记录约束保留、可运行状态、回归、返工、最终目标、人工接管和总资源；中间可运行性与最终质量分开判定。

### F3 · 高：开发者纠偏和不准确状态报告应成为一等质量指标
EMNLP 2026 对真实会话归纳七类失配，涵盖项目读取、意图、规则、动作边界、实现执行与进度报告；91.49% 可见问题的解决仍需要用户明确纠正。
**影响：** 若只统计补丁／测试／接收状态，会低估信任与协调成本。
**建议：** 自然任务轻量记录纠偏类型、是否改变实现／权限／验收、发现时点、返工与人工成本；只计可观察事件，不推断模型内部状态，不建重型遥测系统。

### F4 · 中：多 Agent 不应被包装成“越多越先进”
long-tasks.md 主张按依赖委派、共享状态多时单 Agent 连续做、独立写域才 worktree、单写者；近期框架研究显示功能覆盖不等于效率，token 与执行时长有明显差异。
**影响：** 并行收益必须超过协调、复核、重复阅读、冲突和整合成本。
**建议：** 不新增编排框架任务。自然出现独立工作单元时，比较同一任务边界下单 Agent 与有界委派的有效交付、返工、等待、协调成本和质量；非同题只作案例，不下因果结论。

### F5 · 中：13 首屏 Top 5 可能被误读为全行业排行榜
页面已说明排序依据、已试范围和换路条件，但外部读者仍可能忽略它是本仓任务行动入口，而非全行业最新／最佳排名。
**建议：** 不重写 13。下一次自然读者测试，让未读背景的开发者仅凭首屏解释排序依据、何时不适用、哪些只到资料／源码层；出现实际误读再最小修订。

### F6 · 中：模型／effort 起点仍是实验假设
model-roles.md 已披露外部团队与独立评测的样本限制，并明确本仓净收益待验证。
**建议：** 自然任务记录实际模型 ID、effort、工具、成功条件、返工、最终差量和总投入；任务类型不同不合并成模型排行榜。

## 6. 与标杆的差距
1. 从局部机制到完整软件交付：需要持续需求变化下的最终正确性、回归与维护质量证据；MACBench 可作评价参照。
2. 从工程自报到真实使用者失配：补充开发者纠偏、意图偏差、边界越权和状态报告失真的可观察指标。
3. 从多 Agent 机制到净收益：需要同题、同约束的端到端质量／成本比较；外部框架研究不能替本仓背书。
4. 从资料校准到 M6 效果：需要独立冻结参照和真实采用结果，不能用热门样本数替代。
