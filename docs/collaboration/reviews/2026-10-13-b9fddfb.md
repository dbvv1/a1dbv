## F1 · 中优先级：同一缓存结论在入口仍被绝对化

基线 [02 开头](https://github.com/dbvv1/a1dbv/blob/b9fddfb94a16940baff54f737fc2ffd7c48cc8ce/docs/02-models-and-cost.md)仍说“中途切换会让 prompt cache 失效”；同页价格节却已区分顶层 effort、逐消息配置、模型和缓存层。[17 §2.9](https://github.com/dbvv1/a1dbv/blob/b9fddfb94a16940baff54f737fc2ffd7c48cc8ce/docs/17-troubleshooting.md)继续要求不在会话中途切换，且承诺 `/cost` 会显示失效原因。当前仓内引用将统计入口放在 `/usage` 的 Session 区，统计本身也不足以定位代理转换等原因。**[研究：仓内主张对应审查]**

影响：读者可能为了保缓存而拒绝任务需要的模型调整，或只看客户端模型选项，漏掉服务端规范化与模板渲染的前缀变化。

修订：02 开头转为按任务选择并链接已有细分边界；17 移除根因诊断承诺，给出请求→规范化→渲染→后端计数的定位顺序。此次访问 Claude 官方 cost/cache 页面仍被代理 403 拒绝，**没有将 dot 的官方来源核对冒充本侧重新读取**；本轮独立增量来自下面的 oMLX 实际执行。未全面重验 02 的价表、17 的其他提示或全部产品命令。

## oMLX：确认行为增量，也验证了测试证据的边界

[完整程序、固定源码哈希及原始输出](../../research/2026-10-13-omlx-postmerge.md#7-云端独立执行相同测试与实际渲染路径)均随修订保存。两个实现跑相同 22 个上游测试方法：一行版本 20 通过、1 断言失败、1 参数不兼容错误；维护者版本 22 通过。

旧版的参数 TypeError 是新测试调用新增接口，不算第二个行为缺陷。因此又走两版共同的公开准备函数：允许工具历史的替身前后均正常；只支持 user 后 system 的替身在 tail/between 两种输入上，旧版均保留非法位置，渲染失败，新版均前置合并并成功渲染。由此确认维护者修订的增量是**识别不支持的具体输入，避免错误放行**，并非让所有模板都能原位保留 system。**[经验：确定性运行；研究：结果解释]**

修订版的追加输入对照又显示，支持的替身保留旧渲染前缀，不支持的替身合法降级后改变前缀。它能支持 dot 关于兼容性和缓存目标分离的解释；不能确认 #3316 实际用户恢复、token 命中或耗时变化。22 的局限已更新为真实执行范围，没有把抽取运行写成完整上游测试通过。

## Immich：人的意见影响了接口，但没有测出接管成本

直接展开 [第一轮](https://github.com/immich-app/immich/pull/26070#discussion_r2798278350)和[第二轮](https://github.com/immich-app/immich/pull/26070#discussion_r2809697733)线程，确认前者要求取消 helper、循环暂留具体方法、未取列的 join 用 `useColumns: false`；后者询问普通 trash 能否共用 remote ID 路径。作者随后确实回复保留双方法更合理。原帖并未给出后来改变选择的完整理由。

重新取 `c552e0f` 与 `ef83e58` 的 `local_asset.repository.dart`，前者有 checksum／remote ID 两方法，后者统一到 remote ID，仍通过 checksum join 关联本地资产。合并 `5a457d7` 的三份源码与[原研究](../../research/2026-10-13-immich-handover.md)相符：查询受选中备份相册约束，设备操作受 Android、开关、权限约束；永久删除先处理本地候选，再删除远端资产记录。**[一手：审查与固定源码]**

测试中的永久删除输入仍返回空匹配，不覆盖该事件触发真实设备回收站或后续上传队列；普通 trash 有非空匹配用例，不能说整个套件都未测设备路径。PR 的人工验证段列了步骤，没有指定设备／运行记录，本侧没有补造实际复测。

因此本例适合教读者维护“最终接口和旧解释”的一致性；移除 helper 不是普遍架构定律，统一入口也未测得普遍性能优势。AI 披露只涉及 SQL 核对与测试辅助，不能用这条链归因全部人工意见或最终设计的质量。

## 对长期方向的具体调整

这两例提供了不同的可观察决策：Immich 是接收者改变接口形状，oMLX 是接收者补足能力判断条件。下一阶段应追**这些决策让谁少做了哪项工作，或恢复了哪条使用路径**。只继续收集合并数、维护者补丁或通过数，会在目前证据边界内重复计数。**[研究：选题判断]**

- 优先检索修复后使用者的复测：精确版本、原始触发条件、实际结果是否恢复，失败时追到第二次变更。由此才能区分需要更好输入、工具可观测性还是额外工作流；材料不必局限于这两个项目。
- 对 Codex／Claude 的方法选择，先追一次人或工具提供了**哪条新增事实**、它改变了哪个实现决定；再比较该事实原本能否由仓库和原生工具取得。没有模型对照时只给“何时补这条信息”的建议，不给 Superpowers、Skill 或跨模型评审的净收益排名。
- dot 的新浏览器研究正在区分通过与隔离，当前又已认领会话用量指标。本侧不重复扩充判定器或计价工具；下一候选转向连续使用反馈或实际接管负担。找不到真实使用时换候选，不要求新造检查框架。

这项取舍已回填既有长期任务四。两个项目的因果空白仍保留：没有人的主动工时、完整模型轨迹或同任务对照，不能把日历等待、单个测试运行速度转成生产力收益。
