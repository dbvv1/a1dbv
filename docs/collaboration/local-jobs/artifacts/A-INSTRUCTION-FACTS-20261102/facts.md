## 影响操作的差量

1. **Claude 原生 AGENTS 的“可用”有具体条件，不只是 v2.1.277+。** 官方当前页列出三种不可用情形：版本低于 v2.1.277；用 `/plugin` 禁用了读取 `AGENTS.md` 的内置插件；从 v2.1.276 或更早升级后的某些“首个会话”。另外，**v2.1.281 之前** Bedrock、Vertex、Foundry、LLM gateways 或关闭遥测的会话只读 CLAUDE 文件，官方建议升到 v2.1.281+；[在线 changelog 的 2.1.281 节](https://code.claude.com/docs/en/changelog)与 [v2.1.285 CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/v2.1.285/CHANGELOG.md) 已收录该条，v2.1.281 标签自带的 `CHANGELOG.md` 缺这一条。读者应先跑 `claude --version`，再在 `/config` 确认 **Project instructions** 存在且不是 `claude-md`／`managed-only`；不要只核版本号。
2. **Claude 的优先级是“回退／拼接”，不是 CLAUDE 内容覆盖 AGENTS。** 默认 `claude-md-or-agents-md`：工作目录及祖先目录有 `CLAUDE.md`、`.claude/CLAUDE.md` 或 `CLAUDE.local.md` 时只读 CLAUDE 文件；没有才读 `AGENTS.md`。用户级 `~/.claude/CLAUDE.md`、组织 managed CLAUDE 和 `.claude/rules/` 不参与这个“是否改读”的判断。被读取的 CLAUDE 文件按 managed → user → project → local 拼接，同目录 `CLAUDE.local.md` 排在 `CLAUDE.md` 后，不是后者覆盖前者。需要两者同时读时，官方给的是 **Project instructions** 的 `claude-md-and-agents-md`，每目录先 CLAUDE 后 AGENTS，并跳过已加载过的同一文件；但该值写在 `pluginConfigs` 下时只在 `~/.claude/settings.json`、`--settings` 或 managed 设置生效，项目／本地设置会被忽略，所以它不能替代提交进仓库的导入。
3. **Codex 的“指令链”有页面未写的取值与上限。** 每个目录只取一个文件：`AGENTS.override.md` 优先，其次 `AGENTS.md`，再到 `project_doc_fallback_filenames`；从项目根（默认含 `.git` 的目录，可用 `project_root_markers` 改）向下拼接到 cwd，文件间空行连接，越靠近 cwd 的内容越靠后；空文件跳过，合计达到 `project_doc_max_bytes`（默认 32 KiB）后停止添加。读者若放了 `AGENTS.override.md` 或依赖长文件末尾的规则，实际加载会与只看 `AGENTS.md` 不同。项目根也不是固定等于仓库根：嵌套 `.git`、子模块或自定义 root markers 会改变拼接起点。
4. **Codex 0.150.0 起，未信任项目不加载项目级 AGENTS。** 0.150.0 发布说明写明 “Untrusted projects no longer supply project-level `AGENTS.md` instructions”；对应源码提交在 active project 为 untrusted 时跳过项目级发现、保留用户级指令，并把信任级别放进指令缓存键。但 0.150.1 有仍未关闭的报告称 untrusted 下 `AGENTS.md` 仍进入 `debug prompt-input` 和 `codex exec`；本次未启动客户端，**0.166.0（当前稳定版，2026-10-29）是否已修未知**。自动化或临时目录里，不能把“文件在仓里”当成一定被加载。
5. **Codex 会话中途换目录：shell `cd` 不重载，TUI 的 `/cd` 是否重载官方未说明。** 官方说指令链在启动时构建、每次 run 重建，TUI 通常每个启动会话一次；维护者在 issue 中明确建议改 cwd 后新建会话。页面提醒不要把 shell `cd` 当原生重载成立。当前交互文档另有 `/cd <path>`，会继续在所选目录对话，但没有说明是否重建指令链，记未知；按维护者口径仍应新开会话再核。
6. **Claude 附加目录：开关只扩到 CLAUDE 文件与 rules，不扩到 AGENTS。** `--add-dir` 默认不加载该目录的 CLAUDE 文件；`CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` 加载 `CLAUDE.md`、`.claude/CLAUDE.md`、`.claude/rules/*.md`、`CLAUDE.local.md`；同一表明确写 `--add-dir` 目录的 `AGENTS.md` 不加载。共享 AGENTS 要在主项目 `CLAUDE.md` 里显式导入，且该导入是项目外部路径，仍按外部导入批准规则处理。
7. **外部导入批准规则与页面一致，但可核对的面比页面写的多。** 项目级外部 `@` 导入首次弹框列出文件；拒绝后保持禁用且不再弹。原生读取的 `AGENTS.md` 若导入外部文件，只在此前已批准外部导入时加载，运行时不弹框。Claude 交互启动时还会显示一行 `no CLAUDE.md found; AGENTS.md loaded: <path>`；`/context` 的 **Memory files** 用于 CLAUDE.md 与 rules，直接读取的 `AGENTS.md` 路径看 `/memory`（v2.1.280+）。用 `InstructionsLoaded` Hook 做证据时要注意：直接读取的 `AGENTS.md` 不触发该 Hook，只有由 `CLAUDE.md` 导入或符号链接的 `AGENTS.md` 才触发。
8. **两个依据锚点已失效。** 页面第 94 行的 `#my-agentsmd-isnt-loading` 在当前 HTML 中不存在，实际 id 是 `my-agents-md-isn’t-loading`（含连字符与弯引号）；`#remove-an-earlier-agentsmd-workaround` 也不存在，实际是 `remove-an-earlier-agents-md-workaround`。`#share-one-file-with-other-coding-tools` 与 `#import-additional-files` 仍有效。事实本身不变，但读者点链接会落到页首而不是对应小节。
