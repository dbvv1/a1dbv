# B-AI-GAME-SUPPLY-SOURCES-20261027 · 原始证据

本单元新增三条可试的制作线索，以及一条明确不列为路线的反例。三者都不是“零人工”：人工分别守在选型、删面、试玩和许可四道门上；没有任何一例证明角色、场景、音效可以全自动生成并直接商用。

- **代码即角色**：Blocks Beyond the Stars 把生物做成运行时代码生成的方块身体，配程序步态与 IK，模型生成和绑定环节被整个绕开；AI 不生成 3D 模型，只供贴图、图标和音频。
- **先锁色板，再生成 2D 素材**：Void Balls 用固定 7 色板约束 Replicate 出的精灵、背景与图标，再用 ElevenLabs 生成 9 个音效和 3 首曲子；可借的是约束，不是“8 个 Agent”这个数字。
- **先削轮廓，再做 image-to-3D**：Warpact 把概念图压成单色剪影再送 Hunyuan 低模，随后用 Agent 找倒角、人审批删面，最后多视图重贴图；2,552 三角面降到 791，但人工仍亲手删了 211 个面。
- **不列为路线**：SimCity 2000 克隆能跑，但它是受版权保护原版的复刻，社区质疑逆向合规、手机性能与游玩价值；代码生成的 3D／矢量与 GPT Image 2 位图没有独立许可，音乐音效则为 CC 授权、可按相应 CC 条款复用。可借的是“PowerPC 模拟器＋10,000 游戏日自动验证”的迁移验证机制，不是角色／场景／音效供给。
- **中文同题证据**：indienova 上两位从业者分别给出“出图可用率约 30%、仍需人工精修”和“AI 角色要有真人原画底板才有辨识度”，与本轮英文案例的结论一致。

## 1. Blocks Beyond the Stars：代码即角色，AI 供贴图与音频

**结论：这是本轮最接近“没有美术人员也能持续出货”的可审样板，但它的角色是程序方块人，不是生成式 3D 角色；资产许可也不随代码开源。** 🧪 可玩入口现成、源码与资产账本公开，值得 dot-B 亲自跑第一小时。

### 入口、版本与平台

- 浏览器实验版：<https://play.blocksbeyondthestars.de/?lang=en>
- 固定发布：`v2026.10.28`，2026-10-25 UTC 发布，含 Windows、Linux、实验性 macOS 与 WebGL 包：<https://github.com/marceld23/BlocksBeyondTheStars/releases/tag/v2026.10.28>
- 官网与开发日志：<https://www.blocksbeyondthestars.com/en/blog>
- 本条目引用的源码与文档均按该发布标签读取，例：<https://github.com/marceld23/BlocksBeyondTheStars/blob/v2026.10.28/NOTICES.md>
- 完整游玩回路：教程包的基础训练（`data/stories/tutorial/story.json`，b1–b6）依次要求移动与进食、采矿、冶炼／制作、建造、扫描／研究、起飞、飞行、停靠／交易、降落新世界；README 的短介绍是“醒来在船上→降落星球→采矿→合成→设计／建造飞船→飞行→停靠”。修船不在基础链路，而是后续可选深挖课程 c6.2；`docs/developer/SHIP_REPAIR.md` 说明它修的是战斗与 EVA 造成的船体损伤。本轮未运行，回路是否成立未验证。

### 作者过程与 AI／人分工

项目由父子两人发起、母亲参与平衡与联机测试：孩子提需求并做主要试玩，父亲负责提示、编排与集成，AI 生成代码与素材。开发日志按天记录版本，更新理由常常直接来自玩家报告；仓库的 `AGENTS.md` 面向 AI 代理编写，说明这不是一次性生成，而是持续几个月的“人定方向、AI 执行、高频发版”。[社区：作者自述]

人做的是：玩法取舍、提示与集成、试玩、平衡、联机测试、许可与发布；AI 做的是：代码与架构、贴图与图标、音效与音乐、NPC 对话后端。作者没有给出“AI 完成百分比”，也没有工时账本。

### 角色、场景、音效各自怎么供给

- **角色：不生成模型，直接由代码搭。** `CreatureBuilder` 从服务端描述符用方块拼出身体，`CreatureRig`／`CreatureAnimator` 每帧摆姿势，步态数学与两骨腿 IK 放在共享层并有单元测试；文档明确写“无蒙皮网格、无导入动画片段、无 Mecanim”。生物有 11 种体型（标准、泰坦、水母、鳐、巨像、沙虫、蛛形、双足、蠕虫、利维坦、天空巨人），同一种子在不同客户端得到同一身体。[一手：`docs/developer/CREATURE_RIG.md`、`docs/developer/ART_BIBLE.md`]
- **场景：程序生成加运行时图集。** 星球、地形、洞穴与群系按种子生成；方块贴图是运行时 64×64 图集，AI 生成 64px 像素风瓦片，再在运行时拼图集，避免为每个星球手摆场景。[一手：`docs/developer/CLIENT_SHELL_AND_ASSETS.md`、`NOTICES.md`]
- **音效：三类来源按成本与效果分工。** 337 个音效文件用 ElevenLabs 生成（含 18 条 NPC 无词语音、生物叫声、环境声、武器与机械声）；51 首背景音乐由 40 首 Suno 加 11 首 ElevenLabs Music 生成；UI、警报、部分环境循环则用代码合成。文档写明“用少量素材做变化”：对同一组生物叫声做音高／速率偏移，而不是为每个程序生成的物种单独录音。[一手：`NOTICES.md`、`docs/developer/SOUND_DESIGN.md`、`docs/developer/MUSIC_TRACKS.md`]
- **“100% AI”需要打折扣看。** README 宣传“100% 资产由 AI 创建”，但项目自己的账本记录了三类例外：一张玩家手绘的 `rune_stone` 贴图（署名并说明是确定性脚本微调，不是模型生成）、油与气体等程序化材质、以及代码生成的方块头像与 UI 面板。更准确的说法是“AI 负责大部分贴图／图标／音频，代码与程序化管线负责形体与场景”。[一手：`NOTICES.md`、`docs/developer/ART_BIBLE.md`]

### 许可与成本口径

- **代码**：AGPL-3.0-or-later。**资产不自动跟随代码许可**：`NOTICES.md` 要求每个捆绑资产“permissive 或自有”，并说明 AI 音效、音乐、图标分别受 OpenAI、ElevenLabs、Suno 的账户条款约束；仓库没有给第三方复用这些生成资产的独立授权。项目不发布模型权重，生成在厂商服务端完成；想借的是管线，不是整包资产。[一手：`LICENSE`、`NOTICES.md`]
- **成本**：ElevenLabs 付费；`SOUND_DESIGN.md` 的 Principles 仍留“cost-gated”旧句，但同文档“Cost gate (ElevenLabs)”一节已改为 blanket-approved，不再逐批审批。没有订阅金额、生成次数或总账；游戏免费、无内购。不能据此推算净成本。[一手：`docs/developer/SOUND_DESIGN.md`]
- **失败与返工**：README 明确这是开发中项目，会有 bug、存档与联机行为随版本变化，Windows／macOS 构建未签名；每日发版本身就是持续返工的信号，但没有公开“哪些版本被回滚”的清单。

### 与已收录案例的差异

- **对 Remnants of R’lyeh／Meshy 路线**：那类案例卡在生成网格的拓扑、绑定与近景精度；本作根本不生成角色网格，改用“方块身体＋程序动画”绕开拓扑与绑定，代价是角色只能是方块语言。
- **对 Codex Mortis**：Codex Mortis 因角色动画达不到目标而改用 shader 摇摆；本作给出的是可运行的步态与 IK 系统，证明方块角色的动画可以程序化，而不是只能放弃。
- **对 DragonScape Idle**：两者都靠“风格约束＋人选图”；DragonScape 用 content hash／style hash 保留已采用图，本作把风格约束下沉到运行时图集与固定美术圣经，规模更大但可复用性更低（资产不开放）。
- **对 Riposte**：两者都是代码优先；Riposte 用 Three.js 几何与材质堆建筑，本作把世界与生物都变成数据驱动的程序形体。

3. 方块生物在近景是否读得出角色差异，还是只是换色方块；11 种体型在实际游玩中能否被感知。
4. 48 种星球类型下，AI 贴图是否出现明显风格漂移；运行时图集的接缝与可读性。
5. 联机自建服务器的门槛；每日版本对存档的破坏频率。
6. 若要把资产用于本项目，需逐项回 OpenAI／ElevenLabs／Suno 条款确认商用与再分发，不能因代码是 AGPL 就当作整包可用。

## 3. Warpact：先把轮廓削到单色，再做低模与重贴图

**结论：这是本轮唯一给出“image-to-3D 怎样接近 game-ready”完整数字的案例；它明确不是零人工，人工亲手删了 211 个面、审批了 477 个倒角面。** 🧪 可免费在浏览器与 Google Play 试玩，但只详细公开了一个载具单位，还没有角色管线。

### 入口、版本与平台

- 浏览器试玩：<https://playwarpact.com/start/>（免费，需 WebGL）
- 官网与 Dev log：<https://playwarpact.com/>；2026 年 7 月的更新日志提到 Google Play 版已上线，2026 年 9 月有地形、导弹车、坦克与手机操作更新。
- 资产管线原文：<https://playwarpact.com/blog/lowpoly-hybrid/>（2026-09）
- HN 讨论：<https://news.ycombinator.com/item?id=49636237>（检索时 3 分、1 条评论，评论者为作者）
- 完整游玩回路：官网称可建造基地、采油、出兵，对 AI 或玩家进行陆海空对抗；本轮未运行，回路是否完整未验证。

### 作者过程与 AI／人分工

作者是个人开发者，做一款跨平台 RTS，目标包含受限 Android 设备。管线的五步是：概念图（一次四张、迭代选一张）→ 削成单色无阴影剪影（两三次图像编辑）→ Hunyuan 3D 低模生成并开 smart topology（生成结果 1,443 面，多为四边形，折合 2,552 三角面）→ Blender 加自建 AI 编辑 UI 清理（Agent 找倒角，人审批；人还亲手删了 211 个隐藏面）→ 图像模型生成多视图参考，交 Meshy retexture（四视图、保持 UV 与几何、8K、付费计划可重试 12 次），最后 Agent 把约 50 MB 的下载模型降采样到游戏规格。[社区：作者自述]

人做的是：概念选择、剪影编辑、亲手删面、审批倒角、最终验收；AI 做的是：概念与剪影生成、低模生成、倒角检测、纹理参考与优化。作者明确写“没有 image-to-3D 模型能一次给出可用的低模”，所以这条线的价值是步骤顺序与判断点，不是“自动”。

### 与已收录案例的差异

- **对 Formula Minus One**：FM1 是草图→图像→Tripo→Blender 清理，流程相似但没有给出面数与人工删面的账；Warpact 把“低模预算”写成可执行的剪影步骤，并记录每一步的面数。

## 4. 不列为制作路线：SimCity 2000 克隆
