## 三个语义例子

以下只核规则含义，不称代码、模型或客户端实跑，也不代表任何具体项目的验证结果。

| 情形 | 可保留的原证据 | 为什么可复用或须复验 |
|---|---|---|
| **仅不相关文档／提交 SHA 变化**。原验收在 C1 对某受检文件及其输入运行并记录通过、命令、依赖版本和环境；C2 只改不参与该验收的文档，或仅因合并／rebase 换了 SHA。 | C1 的通过结论及其原版本、命令、环境；可在 C2 标注“复用 C1 结果及原受检范围”。 | 受检代码、直接消费者、相关输入、检查命令和依赖环境未变，原验收条件仍适用，因此可复用；记录必须保持“C1 的结果”，不写成“C2 重新通过”。若改动的文档本身属于原验收对象（例如链接检查），它就不是无关改动，对应检查须重验。 |
| **受检代码、直接消费者、相关输入、检查命令或相关依赖环境改变，且变化影响该结论或影响不明**。C1 的受检函数通过；C2 改了该函数、改了直接调用它的入口，升级了相关依赖／运行时，或更换了检查输入与检查命令。 | C1 的原通过记录、失败记录和受检范围，作为历史证据保留。 | 改变本身不自动作废旧结论：受检代码、直接消费者、输入、命令与依赖环境的变化都纳入影响判断，变化确实影响该结论或影响不明时，受影响检查须按 C2 复验；逐项核对确认某项变化不影响该结论时，该检查可按原范围复用并注明判断依据。若依赖或环境变化波及整条原验收，按 C2 重验原验收；不能把 C1 的通过写成 C2 的通过。 |
| **影响无法确定，或只有旧版成功自报**。只有“已全部通过”的旧报告，缺受检提交、命令或环境；或当前改动的影响面查不清（消费者未知、依赖锁定缺失等）。 | 旧报告可作为历史陈述与失败记录保留，不被删除或改写。 | 缺少事实版本、相关输入、检查命令、依赖环境和原验收条件时，不能判断旧结论是否仍适用，因此不得复用；先补齐这些事实，再按当前版本复验。旧版自报的成功不升级为当前验收，未知也不改写成通过。 |
