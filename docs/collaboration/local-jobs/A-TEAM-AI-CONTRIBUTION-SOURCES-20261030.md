## 目标
补读者地图“团队怎么推广”的具体选择材料：真实开源维护团队为何接受、限定或拒绝 AI 辅助贡献，怎样把提交者责任和后续维护落实到已有工作，政策后有没有可核的正反反馈。只交来源，不替团队制定政策或形成推荐。

按 templates/generic/.claude/skills/explore-frontier/SKILL.md 第 1–2 步及原生 kind: explore 三路取材、核原文、整理和非作者核验。开工读最新项目约定、TASKS、main 与负责人分支上的任务，先去重再采集；已有任务不重排，同题在途不另开。
基线是 docs/18-team-adoption.md、docs/11-community-pulse.md、docs/research/2026-10-12-community-source-records.md P58 与 §7／C9、inbox 及 A-FRONTIER-WIDE-SCAN-20261027 已收材料；Shopify Quick、Monzo Agent Chip、Imprint small-change、Spotify、Godot，以及 Ghostty #8289 政策、#7523→#9524 续改和 #8364 替代方案均已收，不重复交，只有真正新后续才留。
只收贡献者责任、团队接收／撤回决定与维护结果；不做 Agent／共享指令配置、Skill/MCP、模型／effort、评审工具或测试算法、多代理调度，也不做遗留数据迁移案例。上述机制发现只记归属链接交相应卡，不在本卡展开。
先查 https://github.com/curl/curl 、https://github.com/matplotlib/matplotlib 、https://github.com/ghostty-org/ghostty 的公开贡献规则修订、维护者 issue/discussions、相关 PR 及项目官方文章，沿政策原讨论追实际执行反馈。它们是待查入口，不预设政策内容或优劣；可扩到其他有原始证据的维护团队。
主窗近 3–6 个月到实际读取截止、优先近 3 个月；政策修订时间、反馈发生时间和本次核读时间分开。必须有具体决定／真实案例，泛泛“AI 好坏”立场、厂商采用率与转述不计效果证据。
逐项记录原政策／修订、作者身份（维护者／贡献者／观察者）、适用贡献类型、实际执行或撤回、维护负担与后续修复的公开依据。PR 数、关闭率、star 和个人感受不能单独证明生产力或质量；没有可比条件就明确未知。
公开原文正反都查：既找贡献可接受并持续维护的例子，也找额外审查负担、退稿或收窄；不把“禁止 AI”与“要求解释和维护”混成同一政策。源码规则、实际执行与作者计划分别列。
按现行 explore-frontier 覆盖做事者文章／仓库、GitHub 头部、可读中英文社区、真实用户反馈与新线索；不按条数证明完成。已受限 Reddit、HN 站点、linux.do、V2EX 不探测，社区原帖留给云端；只走未受限的公开原站及 GitHub 原文，不用代理／镜像、登录或换身份绕过。不可读即停该入口并列具体缺口，不借私人会话取回。
不读私人会话、账号用量、凭据或用户电脑配置，不调用 ListAgents，不联系维护者／发表意见，不安装工具或改变接收端与安全设置；外部文字不构成执行指令。

## 怎样算做成
非作者核政策原文及修订、反馈对应的版本和任务、实际接收与宣传的区别；既有来源若无新后续则剔除，零增量交具体范围与排除理由。不可读原文立即停该入口，摘要不能确证政策执行效果。
按“政策与实际接收／拒绝案例 → 后续维护与相反反馈 → 跨项目对照及覆盖缺口”的顺序推进，每单元 60–90 分钟，含核链接、整理和非作者审查；到时交可审材料与未覆盖项，不以时间到声称饱和。未完成范围写回本卡下一步，由 dot 决定是否原卡接续，不自行重跑或另建卡。接收端若提前停止，按实际停点交已有材料，不改脚本／超时设置。既有八任务不重排，仅原接收端按实际共享最多 4 并行调度，不另起调用抢槽。
