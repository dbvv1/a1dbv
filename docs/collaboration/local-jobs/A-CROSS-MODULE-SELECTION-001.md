## 目标

归 P90／P81：找一个真实未决、跨模块的完整产品功能，按当前强实践选择 Agent 怎样完成它，准备可执行的采用起点。问题是怎样交出集成后的功能，同时不把协调和返工都转给人；不预设多写者胜出。本任务先做选择与消费者准备，完整实现由负责人收到结果后接续。

基线是原生主 Agent 连续实现，按需并行调查／独审、单一代码写者；强替代是主 Agent 持有共享决定，按依赖划分自然独立的实现、必要时独立 worktree，再以统一消费者接收。仅当原生入口确有缺口才考虑额外编排框架。比较完成能力、真实关键路径、共享契约变更、集成遗漏和维护／人介入投入；不做正式 A/B，不用团队人数或一次成功证明提速。

## 调查与选择

沿运行手册来源要求查近三至六个月的头部团队／真实开发者实践，官方、社区（含中文）与开源实现对照，重点找完整产物、协作失败与撤回并行的原因。现有固定来源作起点，不把内部路线或宣传能力当当前最佳已证。保留来源日期、读到什么和不可读入口，关键 API 回官方与源码。

消费者要有自然未决需求：查最新 issue、实现和在制 PR，已有覆盖即排除；一个用户操作确实跨模块并共享接口／状态，同时存在可分离工作，不能为并行强拆。优先用公开 fixture 和现有测试即可消费的 CLI、文件产物或真实组件；必要运行入口必须在已有授权内可用。无新账号、付费、私有数据、持久服务或特权设施；不以别的任务授权绕开拒绝。

交最值得继续的一项条件选择：需求与固定源码、未被覆盖的证据、推荐路线及为何优于可信替代、共享契约／集成消费者、可借现成依赖与检查、必要权限、完成条件及下一执行起点。后续变化只取真实需求，没有自然二改不制造二改。没有合适消费者时交具体负结果和恢复条件，不用换一个小工具补数。
