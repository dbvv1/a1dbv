```text
1. 现状对照（不新建文件）：对照 G1、G2 和“长期交付”，检查 domains/game-dev/ 现有内容，在 domains/game-dev/README.md 里加一张缺口表。
   - 列：环节或模块、现有内容在哪、缺什么、优先级；
   - 不写成教程目录。
2. 开源摸底：G1 的美术与音频资产按资源类型分别找出 GitHub 上最有代表性的开源项目或工作流，每类最多 3 个。
   - 看四点：是否维护、是否有真实游戏在用、不经人工美术修补的直出质量、接入 Unity / Unreal 的成本；
   - 基准是单人程序、没有美术：差距只能靠选模型和参数、重新生成、脚本或程序化处理来补，补不上就写明；
   - 结果并入 domains/game-dev/03-generative-ai-in-games.md，按资源类型给出“采用 / 改造 / 不用”的判断；
   - 不做工具名单，每个判断都要说明离可发布还差什么。
3. 第一项深入：从缺口里选一个最影响独立游戏能否做成的环节（候选：3D 模型或动画到引擎可用资产、全流程的风格一致性、哪些美术风格最适合 AI 直出），做一轮深入调查。
   - 至少一项新证据：读一手源码或文档、找到真实游戏的复盘，或者一次可复查的小实验；
   - 结论写回对应专题。
4. 遵守锚点的每轮上限：新建研究记录不超过 2 份；不新建目录或编号专题，确有必要先问我。

回复用三个标题：已完成（附 SHA 和检查）／方向自检／需要我决定（最多三条）。
```
