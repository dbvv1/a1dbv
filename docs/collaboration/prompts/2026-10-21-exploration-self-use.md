# 内容项目探索提示词

用途：为一个真实内容项目找同题的当前最高水平，并把证据变成读者的选择。只用已有授权工具；本提示词不新增安装、付费、模型、引擎或发布授权。

## 输入

- 项目、读者问题与目标正文位置：【填写】。
- 要改变／确认／撤回的选择、目前默认：【填写】。
- 使用场景、硬约束、质量标准：【填写】。
- 已有研究与来源名册：【填写，可复用】。
- 截止日期、允许工具、时间／费用边界、停止条件：【填写】。

先读仓库约定与当前项目板，记录起始提交、开始时间和本提示词版本。已经知道的来源标“输入已知”，不作为本轮自主发现。

## 执行

1. 先找上限，再找现成方案。按题选名册里的团队／作者／作品，查近期原始工程文章、论文、演讲和采用产物；AI coding 优先近 3–6 个月及当前代际，游戏优先近两年。旧方案允许胜出，但要说比较过什么。
2. 先列会改变决定的未决条件，再从失败机制和邻近领域术语搜，不只搜产品功能：例如“Agent 启动不了”要查团队怎样简化命令和管理长进程；“评审不结束”要查重复发现、既存缺陷和复审收敛。查看原始站点明确链接的官方出口与相关作者文章；转载／精选仅带路线索，不按链接数凑证据。
3. 同题比较当前领先候选、主流参照和可行基线。保留原方案／不做；核最可能推翻推荐的反例。厂商功能表不证明质量最好，近期也不自动等于领先；找不到就写“最高水平未知”。
4. 决定性断言打开原文，记录作者、发布日期／版本、原文位置、读取程度、支持范围与利益关系。团队自报补团队规模、模型、代码库和人工把关；未知留空缺。证据冲突先对齐版本和调用路径。许可或硬约束未知，不当满足；访问拒绝不绕过。
5. 综合时保留决定性断言的单源支持片段、URL及必要上下文，不只接收混合摘要；停止搜索后核最终选择是否明确、硬约束是否满足，未知须保留。交付选择：采用／改造／自建／放弃，理由和撤回条件。写“选什么→借什么机制→保留什么→怎么验→何时撤回”，明确 Agent 能做什么、人判断什么。外部事实正确但未改变推荐时，保留原默认并解释。
6. 结束时冻结本轮来源和决定，按稳定来源ID分开发现遗漏、读取缺口与转化缺口；后验挑出的漏项只算候选确认比例，不冒充总体漏检率。再与独立审计卡／用户带入／回扫参照对照。不要为了让命中率变好而回写冻结稿。把新来源加入持续名册，把真正改变选择的结论放正文，详细材料留既有研究记录。

## 最小交付（同一研究记录即可）

- 最高水平卡：问题、领先做法／未知、来源日期与作者、主流与可行基线、本仓推荐层级及选择理由。
- 决定性证据表：去重原始来源、输入已知／自主发现／外部补入、已读相关正文／仅摘要／不可读、支持的断言、缺口与反证、采用状态。
- 一条正文改进与生成交接；没有新证据改变选择则说明保留原因，不硬造修改。
- 使用回执：提示词版本／起止时间／实际研究用时／等待与复核时间（观测不到写未知）；去重查验来源 N、相关正文已读 F，原文比例 F/N；其中决定性来源 D、正文已读 FD，另列 FD/D，D 为 0 时写不适用。搜索结果总条数不是 N；失败读取也保留在 N，转载和同源镜像不重复计数。旧来源复用与新读分列，不宣称旧原文是本轮读取。
- 漏检记录：独立参照的冻结日期、来源和相关性依据；漏掉什么、为什么影响读者、是发现遗漏／读取缺口／转化缺口／截止后新增。没有合格外部参照时写“尚无可计算分母”，不写 0% 漏检。

完成一张卡不等于完成一个项目。只有本提示词在内容研究开始前实际采用、形成独立读者问题的证据与正文交付，才记一个自用项目；同一项目的多张卡只计一次。历史任务不得追认。
