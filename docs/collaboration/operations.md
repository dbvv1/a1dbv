# 运行细则

> [手册](LONG-TERM-PLAN.md)管执行原则；本页管发布、恢复与运行。平台设置和渠道实测按需读[操作参考](operations-reference.md)。

## 1. 发布与恢复

**谁发布**：每个执行者把自己接收的成果直接快进推送到 `main`（锚点 2026-10-21 授权）。A 和 B 各自发布，不互相代合，也不走 PR（2026-10-20 用户决定）。范围是 a1dbv 的 `main` 和负责人自己的案例仓库默认分支（Star-Rush-Reborn 的 `master`，MOBA-Like、FPS-Like 的 `main`）。用 GitHub 连接器写 Git 数据或更新 ref 与命令行推送等价，同样只做快进。发布不包括部署，也不改账户权限。

1. 在自己的 `<执行者>/<主题>` 分支按[手册§7](LONG-TERM-PLAN.md#7-交付流程)完成审查、检查。
2. `git fetch origin main:refs/remotes/origin/main` 后合并进自己的分支，不 rebase 已推送提交；保留他人的 TASKS 行，本人行随交付改。
3. 只暂存本次文件，跑 `git diff --cached --check` 和 `python3 scripts/check_public.py`；提交后跑 `python3 scripts/check_public.py --commits origin/main..HEAD`，有发现就停止发布。再读 `git diff origin/main`。
4. `git push origin HEAD:main`，只允许快进；不强推，不改写已发布的历史。

**提交身份**：命令级 `-c user.name=… -c user.email=…` 署实际执行者，用 GitHub noreply 或固定机器邮箱，不改全局，无须再确认。

**失败恢复**：

- main 前进：回第 2 步。
- shell 无写认证：用已授权 GitHub 连接器发布同批文件，以最新 main SHA 为预期旧值，不新建凭据。
- 明确权限拒绝：只停被拒部分，不转交代发。其他改动先移除／替换被拒文件的引用，保证可玩后发布；被拒部分留本人分支，TASKS 记恢复条件。
- 超时、断连或结果未知：先核原动作和相关写者已结束，再核副作用、共享资源和远端结果。只对已知无外部副作用、相同输入可安全重复的步骤有界重试，不凭命令名称判断；部署、评论、付费调用等先对账，已生效不重发，未生效从断点续接。未知只停该步。

扫描命中／已发布泄露按 [AGENTS](../../AGENTS.md#执行约定)处理。串行小批发布；TASKS 旧行入 `archive/` 当日（UTC+8）日档。

## 2. 分支与交付

各自分支小步提交；同一文件、运行实例、输出目录单写者，同文件只一份待合入成果。独立工作并行，脏树混入无关内容才隔离检查。在途无数量上限，活跃线至少一个。交回结果和候选 72 小时内定去向：整合、补验（写缺哪层证据、谁做）或放弃；积压时先处理这些，暂缓同类开工，不按数量删有价值产物。结论只写到已达到的证据层（自动检查、实际运行、视听或非作者体验）。

### 2.1 跨执行者的发现与交接

开工、恢复、选下一项前运行 `git fetch origin '+refs/heads/*:refs/remotes/origin/*'`，用 `git branch -r --no-merged origin/main` 查在制分支，读 main 的 TASKS；认领只在合入提交里改自己的行。

跨执行者审计按[手册§6](LONG-TERM-PLAN.md#6-节奏与反馈)，不设整合者。受阻保存成果、下一步与恢复条件，继续独立项；授权、输入未变不重复被拒动作，也不反复提交“仍等待”。

## 3. Dot 运行保障

> 2026-10-25 用户授权，10-26 按官方能力重写。

dot 并行推进就绪工作，留审查、返工、整合和发布容量。后台代理、云电脑、本机同时用，Codex 额度最后用；[资源入口与直连登记](operations-reference.md#执行资源)。

**无进展与偏题**：连续两次心跳无新证据、动作或状态变化，或连续两个单元没推进本线主目标（A 的地图 ⏳／🟡 项、B 的记分卡最大差距），下一次必须换做法：重新诊断、隔离、转独立工作、回主目标或上报。

**实际运行与时限**：状态标签不证明执行，以工具结果、进程或产物增量为准。超过 30 分钟无新证据只核查原调用、远端及产物，不自动终止、清锁或重开；活跃单元不打断、不重复派发。普通单元 2 小时、探索单元 4 小时硬上限，到上限先保全产物，按原任务恢复合同续接，不从头重试（[SPEC §3](AUTONOMOUS-WORK-SYSTEM-SPEC-v1.3.md#3-dot-每次唤醒的固定工作循环)）。

**唤醒**：手上有可做事项就不结束；在途结果回来接续。每个 dot 只留一个每小时心跳，不另建调度；GitHub 事件范围与上游 PR 订阅见[操作参考](operations-reference.md#唤醒与设置)。心跳同步 main，重读本人提示词及 TASKS 当前重点，走“每次醒来”循环，不打断在跑任务。

- **dot-A 两小时回执（2026-10-26 用户授权）**：按 Run 计划时间换算 `Asia/Shanghai`，双数小时向本 ChatGPT 对话发一次，奇数小时只接续；同窗重试先核已发记录去重。内容就是循环第 7 步：有变化写成果，没变化写卡在哪一步、下一步做什么，最多三条。
- 需用户决定、平台休息或连续两次心跳确无推进时即时通知。
- 方向层修订后列出 a1dbv 笔记，删改冲突项；列出定时任务只留该心跳。笔记冲突以仓库为准。

**本机接收端**每 20 分钟运行，需开机并登录；脚本、配置、计划只在本机管理，不占 dot 心跳。kind、并行数、超时、领取、防重放及接收统一见 [local-jobs](local-jobs/README.md)。ready 超 40 分钟未领取，在 TASKS“分工”标出并通知用户检查开机、登录。

**权限与额度**：Custom rules 由用户设置，批准后重试与上游集成 403 处理见[操作参考](operations-reference.md#唤醒与设置)，不换通道绕拒绝。额度暂不作为约束（2026-10-26 用户决定）；平台休息时在 TASKS 记恢复时间，本机模型继续。
