# 运行细则

> 2026-10-17 从[运行手册](LONG-TERM-PLAN.md)移出，内容原文保留。开工不需要读本页；发布、恢复、交付检查或统计运行信号时再读。

## 1. 发布与恢复

- **首选 `git push`**：授权和写认证可用时，本地提交后整批推送；shell 缺写认证则用既有授权连接器，不反复试推、不自行新增凭据；
  提交身份元数据与远端写认证分开处理：缺作者时，内容执行者可交固定的受检索引树、基线 SHA 和变更文件，由串行发布者接手；需要本地 commit 时，用本次命令的 `-c user.name=… -c user.email=…` 如实标识实际执行者，不改全局配置、不冒用用户或厂商身份。缺作者本身不是用户授权缺口，也不需要新建凭据。[一手，2026-10-17（UTC+8）核实：[身份配置](https://git-scm.com/docs/git-config#Documentation/git-config.txt-username)、[命令级配置](https://git-scm.com/docs/git#Documentation/git.txt--cltnamegtltvaluegt)] [经验，2026-10-17（UTC+8），Git 2.47.3] 隔离临时仓库、`user.useConfigOnly=true` 禁用身份猜测时，未配置身份的 commit 退出128，本次命令提供执行者身份后退出0且未持久化身份；仅证明本地提交行为，未验证 push 授权或认证。
- **增量发布**：固定最新远端 `main` SHA，只上传变化文件；已确认成功的对象可复用，在工具上限内批量写入，最后以该 SHA 为预期旧值更新分支（CAS）。发布前基线已前进，先停发、整合并重验；CAS 拒绝也重新整合，不强推；
- **失败恢复**：记录失败阶段和成功回执；对象创建成功不等于分支发布成功。超时、断连或 `user cancelled` 只表明结果待核，不足以判定人工取消或审批超时。先读远端分支、目标提交及文件内容；确认已生效就不重发，未生效才从断点恢复。明确拒绝权限时停止该动作，不换路绕过；
- **续接本地操作**：开始操作前保存预期分支和本地 HEAD；恢复时及暂存／提交前逐一核对，不符或缺失就保留改动、先对账，不把当前值直接重记为旧操作的预期值。连接器发布可能生成不同 commit SHA，结合发布回执、tree 与内容确认原成果；已发布且没有实质增量时，不重复追加状态或提交。这些检查不是并发锁，仍须串行整合，并在发布前核对生成提交的父提交与预期基线、tree 与受检树一致；远端 CAS 另行保留。见 [20 的恢复边界](../20-codex-long-horizon.md#9-超时后动作究竟发生了吗)；
- **无人值守时**：开跑前确认发布授权、认证和审批路径；确需人工确认时保存断点，转做不依赖该确认的工作。汇报分别写远端 SHA、内容核对和 hosted CI 状态；
- **研究与发布分开**：研究并行，合入和发布串行、小批量进行。[经验，单仓单例] `c9e71c7` 发布前整合了前进到 `244bc9f` 的远端；`7a475db` 的发布回执核实了分支更新和五文件内容一致，hosted CI 未运行。这些记录支持恢复步骤，不证明失败率下降。

## 2. 分支与交付树检查

- **分支**：每个执行者用自己的分支，例如 `<执行者>/<主题>`；小步提交，合入前读取远端 `main`；检查 fetch refspec，若未跟踪 `main`，用 `git fetch origin main` 后立即固定 `FETCH_HEAD` 的 SHA，不把旧 `origin/main` 当最新。整合并重验后再发布。不强推，不改写已发布的历史，不覆盖他人的提交；
- **检查实际交付树**：先用 `git status --short` 核对新增文件；`git diff --check` 不覆盖未跟踪文件，暂存本单元后还要跑 `git diff --cached --check`。并行脏工作树不能代表待交付内容：固定索引树并导出到隔离目录运行离线入口，记录树 SHA；提交树须一致，整合或改动后重验。不要暂存其他执行者的文件。[经验，单仓单例] E4 日志的公开复演记录保留了去尾空格说明；2026-10-16 离线 Git 行为检查也复现了未跟踪文件漏检、暂存后检出尾空格；

## 3. M4 运行信号的统计口径

- **运行改进**：发布失败、审批超时、返工、上下文不够、并行冲突等问题，诊断后直接改本手册、执行者的配置或工作流，不另写过程文档。每周在 TASKS 交接汇总四信号，窗口用 UTC+8 周一 00:00 至下周一 00:00，未满周标截止时刻：发布失败数/发布尝试数（每次更新目标分支算一次，明确拒绝算失败，结果不明单列，发布前发现基线变化的停发不算尝试）；无人值守中断数/运行段数（从启动或恢复至完成或中断为一段，按结束时刻归周，未结束另列；原因不明不推定取消）；退回单元数/已审单元数（按首次收到自审或审计结论归周、单元去重，需实质修订才算退回）；本周合入单元从认领至远端合入的小时数（逐项及中位数，附样本量，未合入项另列已等待时长）。历史缺日志或分母写“未知”，无样本写“不适用”，不填零、不宣称改善；
