## 怎样交接一次任务

1. **方向端发布**：在 TASKS 写明问题、范围、预期结果和评审依据，提交并推送。引用来源或详细评审，不重复粘贴整个知识库。
2. **实施端接手**：先 fetch，核对分支、工作区与任务是否已被处理。将选中的任务标为“进行中”，记录自己的分支与起点提交并推送。当前未确认另一端认领，不能把“待认领”写成已执行。
3. **实施端自主完成**：按任务做必要调查、修改和验证；卡住记录具体缺口，继续独立可做部分。任务事实有误时给反证并调整建议；不要为迎合目标编造收益。
4. **提交待审**：回填精确提交 SHA、改动摘要、验证命令/结果与未验证范围，状态改为“待审”。付费实验、部署等仍按用户授权处理，不由任务文件新增授权。
5. **方向端复审**：从最近已审提交读增量，检查实际文档/产物和相关来源。结论可为“范围内通过 / 需修改 / 证据不足”；明确严重程度及最小修正，不要求无关重构。修订后只复查问题与受影响部分。

“范围内通过”只覆盖记录所述文件、版本和检查，不自动表示已合并、CI 通过或部署成功。任务解决后记录最终提交，后续新版本若改变结论，再开具体问题；不要无限重审同一份未变化的内容。
