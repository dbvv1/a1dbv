## 协作原则与入口

两端都承担独立思考、深入探索和证据判断。一端提供的方向与评审是另一端的补充，不能成为必须服从的研究路线；任务列表用于协调工作、减少重复，不是权威结论或研究范围上限。用户最新要求优先，意见冲突按直接证据、反例、成本和读者价值处理。模型档位、提交新旧、检查数量均不能替代论证。

- **共同研究目标与选题标准**：[研究入口](../research/README.md)。Codex 主线、Claude 辅线，围绕能力增益、真实反馈、维护成本与读者可用性；其中建议也可修订。
- **已协调任务**：[TASKS.md](TASKS.md)。只记录认领、进度、结果和待解决问题；[研究队列](../research/BACKLOG.md)是候选池，双方可提出更有价值的问题。
- **定点评审**：[reviews/](reviews/)。首次 [4946f93 审阅](reviews/2026-10-11-4946f93.md)保留原时点判断，不代表已审后续版本。
- **研究接续**：[STATE.md](../research/STATE.md)保留来源研究与下一问题；[维护路线](../maintenance-roadmap.md)保留模板/脚本验证历史。跨端认领统一写 TASKS，不另建重复任务状态。

## 怎样交接一次任务

1. 任一端可提出具体问题、范围、预期结果和依据，说明事实与建议的区别。
2. 接手前核对分支、工作区与最新进度，避免重复。认领后记录分支和起点 SHA，认领状态以实际任务记录及提交为准，不能把待认领写成已执行；文件已推送不等于另一端已读或接手。
3. 负责端自主调查与实施；可用反证修订原目标，不为迎合任务编造收益。遇阻塞记录缺口，继续独立可做部分；简单改动不机械增加人工关口。
4. 提交待审时附精确 SHA、改动、实际验证及未覆盖范围。任务文件不能扩大用户的授权。
5. 对端或独立审阅者检查实际增量与直接来源，结论写明“范围内通过 / 需修改 / 证据不足”。修订后只复查问题与受影响部分，不无限重审未变内容。

“范围内通过”不等于已合并、hosted CI 通过或部署。新增证据可推翻任何一侧的旧判断；历史记录不回写成从未出错。
