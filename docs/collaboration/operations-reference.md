# 按需操作参考

> [运行细则](operations.md)是发布和运行入口；本页保留设置步骤、入口选择及渠道实测，仅在对应操作时读取。

## 执行资源

| 顺序 | 产能 | 适合 | 额度 |
|---|---|---|---|
| 1 | dot 的后台代理（dot 内并行） | 调查、读源码、写初稿、写代码、独立审查 | 不计额度 |
| 1 | dot 的云电脑 | 克隆仓库、构建、测试、无头浏览器 smoke、资源处理，用户电脑关机也能跑 | 同上 |
| 1 | 本机模型（[细则§2.2](operations.md#22-本地模型协作)） | 做法明确的单元，和 dot 的代理并行下发 | 免费，要本机开机并已登录；接收端是固定脚本，不耗 Codex 额度 |
| 3 | Codex 云任务、本机 Codex 任务 | dot 自己做不了时才用，例如需要 Codex 环境的大批并行编码，或 dot 正在休息 | 计入 Codex 额度 |

**哪个 dot 直连本机会变化**，以 dot 资料页 Computers 显示的 “Your computer · Connected” 为准，不写死。直连的 dot 可以直接在本机开 Codex 任务，不等接收端；另一个 dot 走 local-jobs。两种方式都在 local-jobs 写任务文件：直连 dot 自己开的任务写 `status: running` 并注明“dot 直接执行”，接收端不再认领。

## 社区渠道

**探索分工**：大批量候选收集下发本机（`kind: explore`），社区原帖与深挖由 dot 在云端做。10-29 实测（[探索证据](../research/2026-10-15-exploration-evidence.md#社区入口实测-2026-10-29)）：本机打不开 Reddit、linux.do、V2EX 和 HN 站点，HN 的 Algolia API 可用；云端 curl 取得 linux.do、V2EX 列表 JSON、HN 首页和 X 账号页部分帖子，Reddit 被拦、知乎转登录。读不到的用 `site:` 搜索找线索并标为摘要，仍无原文的进收件箱等用户贴链接；明确拦截不绕过。

## 唤醒与设置

- **醒来的方式**：dot 自己决定暂停和唤醒，手上还有可做的事就不结束；在途任务回来就接续。dot 的 GitHub 事件只覆盖 PR（新建、转待审、关闭／合入、提交更新、审查、评论），不含分支推送、issue 和 CI。本仓库直接推送、不走 PR，所以靠 dot 自己唤醒加每小时心跳兜底（定时任务的最短间隔）；dot-A 向上游开的 PR 订阅审查和评论事件，维护者一回复就醒。

**减少等待**：常规的 GitHub 提交与推送由用户在各账号的 Custom rules（Settings → Personalization → Custom rules，插件权限另设）里设为无需询问。写法要列出仓库、文件类型和连接器操作，两个账号相同：“无需询问：向我本人拥有的 GitHub 仓库 dbvv1/a1dbv、dbvv1/MOBA-Like、dbvv1/Star-Rush-Reborn、dbvv1/FPS-Like 和我账号下的 fork 提交代码、脚本、文档、图片、音频、3D 模型等文件，包括 git 命令行快进推送，和 GitHub 连接器创建 blob、tree、commit、新建分支或快进更新分支；不含凭据和私人数据，推送前跑公开扫描；不强推、不删除分支、不改仓库设置与权限。”用户改过规则后，只对新增授权明确覆盖、且已确认没有执行的原动作重试；仍被拒就保留原恢复条件，不换通道或请另一端绕过。向开源项目上游开 PR 属于真正的外部操作，用户在对话里预先批准，平台仍要求确认时就停下来问。GitHub 集成在别人的仓库上创建 PR 或评论会返回 403（集成只能写装了它的仓库）：遇到时把分支推到 fork，在 TASKS“需要用户决定”写一行 compare 链接和拟定标题，由用户点开创建，不重试、不换凭据。
