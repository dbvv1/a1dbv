# a1dbv 自主工作系统 SPEC v1.4（草案）
## 从持续执行转向高价值成果转化与阻塞自恢复

- 日期：2026-11-05
- 状态：待 Claude 核心会话复核、Codex 工程可行性复核及用户确认
- 依据：正式 v1.3、Phase 3 七天计划、2026-11-04 20:00 至 2026-11-05 11:00 运行数据

> 本文件提交 Git 仅供共享和评审，不代表正式生效。用户确认前，v1.3、AGENTS、LONG-TERM-PLAN、TASKS 和现行授权继续有效。

# 1. 修订原因

v1.3 已改善工作循环、任务供给和本机接收端连续执行，但约 15 小时窗口暴露新瓶颈：
- Dot-A：main 零次合入，地图/答案页无变化；约 34 个文件、1050 行停留在分支，主要是测试、Hook 和模板。
- Dot-B：有工程活动，但三个案例默认分支缺少玩家可感知改进；部分工具/素材只通过 CPU 或静态检查，浏览器画面、试听、实际操作或整局验证未完成。
- 接收端：领取 21、交回 25、失败 0；B 接收 12 份且多数部分接收；A 无成果进入 main。
- Ready：A 15+，最长等待约 100 小时；B 8。
- Claude 核心会话反复巡查进度，常规统计应由 progress.mjs 承担。
- 本机任务使用 DeepSeek；Claude/Codex 订阅节省幅度尚无可靠数据。

这是单窗口信号，不足以证明长期趋势，作为待验证基线，不外推为永久结论。

**核心转变：从执行吞吐优先，转向成果转化、产品质量和故障后自主恢复。**

# 2. 目标

1. 提高研究、提案、工具和代码转化为正式产品成果的比例。
2. 减少长期停留在分支、部分接收、待审查的产物。
3. 让任务供给与接收/整合能力匹配。
4. Dot-A 优先推进读者地图、答案页、模板和真实 AI Coding 采用。
5. Dot-B 优先改善 FPS、单线大乱斗 MOBA、Star-Rush 的实际体验。
6. progress.mjs 承担常规统计和异常提示，减少 Claude 人工巡查。
7. 保留本机低成本模型产能，避免产生大量无法接收的低价值产物。
8. Dot 遇到问题后能诊断、恢复或隔离局部阻塞，并继续独立工作。

# 3. 成果转化优先

每次唤醒：
1. 接收已回传成果，核实产物、写入范围、测试和副作用。
2. 处理长期未合入分支、部分接收和待审结果。
3. 推进正式成果：A 推进读者地图/答案页/模板/真实采用；B 推进知识模块进入案例、案例体验和记分卡。
4. 只有接收/整合容量允许，且任务有当前价值、明确范围和验收方式，才增加同类派发。
5. 无依赖且高价值的独立工作继续并行。
6. 低价值/重复工作停止；有价值但暂不能接收的产物保留恢复条件。

不得把当轮合入变成无条件合入。质量、安全、独立审查或发布门槛未满足时保持待审并说明缺口。

# 4. 在制工作与积压治理

Ready 卡是供给，不是成果，不能为维持固定卡数持续造卡。已回传/待审/部分接收积压时优先处理积压，暂缓同类低优先级新任务；接收端空闲且无待整合成果时再补 ready。长期等待任务分类为仍有价值且有依赖、失去价值、重复、等待用户决定。不自动删除有价值产物。

报告口径区分 ready、in_progress、returned、partial、review_pending、accepted、integrated、blocked、cancelled。这是统计口径，不要求新建数据库或强制迁移旧任务字段。

等待阈值建议：returned/partial/review_pending 超过 24 小时，下一轮说明原因和动作；超过 48 小时无进展，暂停同类低优先级新派发；超过 72 小时，负责人明确接受、延期、阻塞或取消。现有约 100 小时等待任务逐项核实，不批量合入或关闭。阈值不替代任务硬时限、授权或外部依赖。

# 5. Dot-A：从工程活动转向读者价值

- 盘点约 34 文件/1050 行分支产物，分类为可合入、需补验、应拆分、延期或放弃。
- 不为清理而整体合入，先判断是否改变读者决策或实际开发能力。
- 优先推进读者地图高影响未解决问题。
- 将已验证推荐、替代方案、反例和真实采用写入答案页及默认模板。
- 暂缓没有明确读者价值/采用路径的新 Hook、测试框架和模板扩展。
- 前沿探索必须改变实际技术选择，或被真实开发任务验证。

有效成果：读者问题变成可执行答案；核心答案页/模板实质改善；方法在真实仓库采用并验证；或修复关键正确性/安全/可靠性问题。测试文件、Hook、模板骨架、研究笔记和分支代码本身不自动算读者价值。

# 6. Dot-B：从工具建设转向案例体验

工具、素材和 CPU 测试是生产手段，不是最终产品成果。每个工具任务必须说明服务哪个案例问题、如何接入作品、由什么运行/画面/声音/操作证据验收。

- FPS：将角色 adapter、reload/switch、固定机位和音频工作接入实际训练赛/完整回合；验收覆盖浏览器运行、射击/换弹/命中反馈、画面和声音。
- MOBA：遵循单线大乱斗定位和 A/B/C 阶段。优先让阶段 A 已有技能、命中、受击、塔威胁、赏金事件形成玩家可理解的视觉、音频和 HUD 反馈。阶段 B 离线单线 5v5、阶段 C 海克斯增强不得混成阶段 A 缺陷。
- Star-Rush：优先完成可实际驾驶、可观察、可比较的弯道/路段；工具和 CPU 检查必须继续走到浏览器场景、画面、驾驶手感、音效和人工体验验收。

游戏知识和案例生产继续 Web 优先、AI 全链路。Unity/Unreal 不得成为当前生产验收要求，除非用户明确改变方向。工具/资产完成必须包括接入、二次修改、运行和质量验收。

# 7. 产品质量证据门

案例任务标注证据层级：源码/数据存在；自动化验证；实际运行；视觉/音频检查；实际试玩、非作者评价或对照体验。不得把低层级证据描述成高层级结论。当前阶段需要画面、声音或操作判断时，缺少相应证据不得标记为完整品质验收。

# 8. 统一进度报告

扩展现有 progress.mjs，不新建完整仪表盘：
- 执行层：领取、执行、交回、失败、实际入口、可确认模型、在途和 unknown。
- 交付层：完整/部分接收、待审查、进入 main/正式默认版本的产物、returned 到 accepted 与 accepted 到 integrated 等待时间、超时项负责人和下一步。
- 产品价值层：A 的读者地图、答案页/模板、真实采用；B 的模块进入案例、记分卡变化、默认版本和玩家可感知改进。
- 质量门：自动测试、浏览器运行、视觉/音频、人工体验分别报告。

# 11. 实施顺序

1. 清理与转化：A 盘点分支，推进高价值答案页/模板或明确延期/放弃；B 盘点部分接收成果，决定补验、接入案例、延期或拒绝；无依赖的高价值工作继续。
2. 产品级验收：FPS 进入训练赛/完整回合；MOBA 阶段 A 形成清晰玩家反馈；Star-Rush 完成可驾驶路段的画面、操控和音频验证；游戏知识验证 Web 优先 AI 全链路。
3. 进度报告差量升级：检查 progress.mjs 是否覆盖执行、交付、产品价值；只补可靠采集的缺项，输出分母、时间窗、来源和去重口径。
4. 持续优化：每次选择一个主要瓶颈，小范围修正并验证收益；无可观察收益的机制删除或回退。

# 12. 权责与安全

用户保留使命、方向、授权红线和重大决策；Claude 核心是方向/规则唯一权威；Dot-A/B 自主规划、执行、接收、整合和发布；Codex 负责明确工程任务；GPT 专业聊天负责领域审计。

不改变 Git 单写者、公开扫描、凭据边界、无强推和发布规则。不引入通用 Orchestrator、SQLite、事件总线或新仪表盘，除非真实证据证明必要。成果转化优先不等于降低质量门槛或强制合入。

# 13. 阻塞自恢复协议

**核心原则：局部问题不得自动演变为工作线或全局停工。**

## 13.1 记录与范围
记录具体失败动作、时间、原始错误/证据、受影响任务、影响范围、当前状态、已尝试方案、下一步和恢复条件。分类为操作级、任务级、工作线级或全局级；不得把单次动作失败泛化成平台/权限永久受限。

## 13.2 历史状态重新验证
历史失败只是线索，不是当前事实。每次唤醒或重试前重新核对当前环境、权限、分支/提交关系、进程、远端状态和原动作是否已结束。没有当前证据，不得沿用旧限制结论。

## 13.3 有界诊断和恢复
在现有授权内考虑修正输入/配置、核对依赖和状态、安全幂等重试、选择已授权替代资源、缩小任务范围、保留产物并延期。不得绕过权限、换账号规避拒绝、盲目重放外部副作用或无限重复相同失败。每次尝试必须产生新证据或改变条件；否则停止原样重试。

## 13.4 局部隔离与继续
只暂停被阻塞动作及真实依赖；同一工作线其他独立任务继续；另一工作线继续；其他已授权资源可用时继续其他工作。更新阻塞记录和恢复条件，不得每次心跳只重复同一状态。

全局等待是例外。只有所有剩余 ready 工作均被同一全局能力阻塞，且没有安全、获授权的替代工作时，才允许全局等待；必须列出受阻任务和证据。

## 13.5 复查阈值
- 发现后立即：核验当前状态、确定影响范围并列出恢复/隔离/替代决策。
- 约 30 分钟仍未恢复：检查是否有新证据/条件变化；没有则停止原样重试，转向独立工作或明确等待条件。
- 约 2 小时仍阻塞：重新评估任务价值、依赖和替代路径。
- 约 24 小时仍阻塞：Dot 明确等待、延期、取消或升级给 Claude/用户，并说明已尝试方案及具体需要的决定。

涉及用户授权、凭据、不可逆外部副作用、付费/额度或生产发布红线时立即停止越权尝试并请求决定；时间阈值不构成额外授权。

## 13.6 行为验收
验证 Dot 能否区分一次 Git Push 拒绝与全局发布权限；Fetch/网络失败只暂停依赖步骤；权限缺失时不绕过；单一工具不可用时继续其他已授权任务；同一错误连续发生时停止无变化重试；全局等待时提供所有剩余任务均受阻的证据。

写入提示词不等于完成，必须用真实任务记录和行为验证。

# 14. 成功标准

1. A 高价值分支产物进入答案页、模板或真实采用，或有依据地延期/放弃。
2. B 工具/资产进入案例，并形成运行、视听或体验证据。
3. 部分接收和待审积压下降，超时项都有责任人和下一步。
4. Ready 队列与真实接收能力匹配。
5. progress.mjs 区分执行、交付和产品价值，unknown 如实呈现。
6. Claude 减少常规进度巡查，集中于方向和重大纠偏。
7. 本机模型产能转化为正式成果，返工没有抵消成本优势。
8. Dot 遇到局部故障能诊断、恢复或隔离，并持续推进独立任务。
9. 产品质量不因追求更快合入而下降。
