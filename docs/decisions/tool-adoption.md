# 新模型、Skill 或配置是否值得换

**✅ 保留能交付的现有配置，在眼前的真实任务上只试一项有意义的变化；用原验收看质量，再分别看人工投入、等待和费用，决定这类任务留用还是撤回。** 候选可以是换模型、加一个窄 Skill，也可以是删掉多余流程。先用项目已有测试和产物比较，不必先搭评测平台。

## 第一步：把这段接到当前任务前

**选一个正在做的修复、功能或审查，填两项后交给现有 Agent。** 例如候选填“本次审查从 medium 改 high”，目标填“找出跨文件调用遗漏”；具体启动方式见[模型与档位选择](model-roles.md)。配置只对本次任务生效，原配置留作恢复入口。

```text
本次试用：[一个候选变化]；希望改善：[当前任务的具体质量或投入问题]。
先记下现有模型/配置和任务起点，保留原配置与已有工作。
沿用原任务、权限和验收；候选只用于本次任务，不改全局默认。
用现有检查验证交付，缺少关键回归才补；保留产物、diff 和失败记录。
结束时分别报告：质量变化、人工检查/修补、开始到可接收的等待、可见用量/费用。
把主 Agent、子 Agent、重试和整合都计入；未知项写未知。
最后建议这类任务保留还是撤回，并指出决定性的产物或结果。
```

**有可重放的任务，就从同一起点、按同一验收比较原配置和候选；已有完整基线可直接复用。** 只有候选结果时，先标“🧪 本任务可用”，下一次同类工作继续观察。质量目标可以是更好的可读性、审查覆盖或使用体验，原方案不必先失败；也不为试工具另造任务。

## 怎么决定留还是退

| 分开看什么 | 看什么实际结果 | 怎么选 |
|---|---|---|
| **质量** | 需求是否完成、必要行为是否保留；目标质量由测试、实际产物或使用者核对 | 质量达标、必要行为保住，再比较收益；关键回归先修或撤回 |
| **人工投入** | 配置、阅读、检查、补事实、修补与整合所花的主动工时 | 只把工作转给人却无目标收益，就缩减流程或恢复原配置 |
| **等待** | 从开始到结果可接收的实际时间，含失败、重试、排队和验收 | 节省能改变当前交付才有价值；工具调用少不自动算更快 |
| **费用／用量** | 主、子 Agent 与重试的实际总用量、账单；订阅只用可见额度 | 同质量更省，或质量提升值得额外投入就留；总投入超出取舍则退 |

**先按任务留用，再考虑扩大默认。** 例如审查更完整、等待稍长但能接受，就只给审查升档；小修复多了问答和文档却没改善交付，就关掉这次流程补充。结论不清楚时保留原配置，后续真实任务继续比。整包也能作为一个候选；要知道是哪一项起效，再拆开比较。

依据：[22：任务、验收与完整投入](../22-agent-evaluation.md#1-要回答的是一个决策)及[四层结果](../22-agent-evaluation.md#2-分开记录四层结果)，原核实 2026-10-22；本页为按任务采用的简化用法。

## 强团队和真实使用者怎样取舍

| 实际决定 | 可以直接借的做法 |

| **Cloudflare，10-19**：协调器保 `medium`，代码质量审查转 `high`；同时发现性能审查在 `medium` 漏掉有效发现，准备另试高档 | 按角色分别留退；整条链省钱，不能抵掉关键发现减少 |
| **V2EX 使用者与 Luca Cavallin**：有人因小任务流程膨胀卸载 Superpowers，也有人保留它做详细计划与实施交接；Luca 保留常用核心，同时清理长期不用的扩展 | 只保留当前任务确实用得上的环节。装得多、调用多或个人好评，都不是质量判据 |

## 本仓已有结果：保留有效交付，撤掉无增量机制

**公开扫描修复保留原生回归，不新增常驻依赖。** 本仓在真实漏检上试过 Hypothesis；生成检查没有发现新问题，也没改变规则，最终交付窄修复和 `unittest`，未将它加入运行依赖。这次取舍是“该任务已有回归够用”，复杂输入仍可另选属性测试。

**JSON 导出修复保留严格输入契约，而不宣布提示词胜出。** 新修复让 `NaN`、`Infinity`、`-Infinity` 六份非法配置从全部被接收变成全部拒绝；八份合法对照仍完成 `stage → promote`，包括空对象和合法大指数。它支持接收这个脚本修复；模型或提示词谁更好，要有相同任务条件下的对照，现有结果不作这项判断。

在仓库根目录重跑这份已采用修复的回归：现有回归使用临时合成配置，实际调用导出 CLI 的 `stage → promote`，不读取个人配置。

```bash
python3 -m unittest discover -s tests -p test_config_export.py -v
```

依据：[本仓真实采用与撤回](../../experiments/scratch-path-scan-adoption.md)；[JSON 导出修复](https://github.com/dbvv1/a1dbv/commit/023c325247b9f50375cea14e72b807d35b3fa316)、[实现](../../scripts/export_ai_config.py)与[21 项原生回归](../../tests/test_config_export.py)；原核实 2026-10-26。

## 何时不适用

- **环境、权限或服务不可用：** 先恢复执行条件，再判断候选；把认证失败算成模型能力差会选错方向。
- **要全团队切换、承担生产风险或对外宣称通用优势：** 扩到有代表性的实际任务与独立验收，按[22 的评估方法](../22-agent-evaluation.md)补足证据；本页的一次可逆试用只负责眼前的选择。
