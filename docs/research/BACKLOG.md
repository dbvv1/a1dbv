> [运行手册](../collaboration/LONG-TERM-PLAN.md#4-工作线唯一的任务编号)的 M1–M6、GA–GF 是唯一顶层工作线；R01–R16、WP0–WP13 和 G1–G4 仅作既有研究／实验计划索引，不另建任务体系。完成证据留在原研究记录与 [协作归档](../collaboration/archive/README.md)，不再排成待办。

选题先处理用户／阶段审计问题、到期动态事实，再补核心页面的成熟度缺口。每次只追一个能改变建议的问题：固定当前判断、所缺证据、下一动作与停止条件。功能正确以后仍可研究体验、性能和表现的上限；公开源码能说明机制，不能独自证明使用收益。以下选题与排序均为 **[研究：本仓库判断]**。

公开资料与固定源码调查可继续，不把所有线都卡在实测。实际实验按阶段边界另获授权；安装、下载等具体操作以现行授权及 TASKS 为准，本页不新增授权。没有新证据就换题或关闭，不靠重复案例、工具名单或反复验收制造进展。

## M3 · 四条主线

### 四条长期任务：以真实开发结果组织研究

四条主线是方向，不是第二套认领编号。以下每项归 M3，跨线结果回流到唯一主专题；源码机制、作者报告、独立复测与本仓实验分别记证据。先复用已有来源，再补不同作者、接收方或反例；同一实验的文章、视频与仓库不算三个独立样本。

### 一、AI 怎样帮助发现值得做的软件（R07／R09／R14）

- **M3：两个都可用的方案，哪一个值得保留？** [产品反馈记录](2026-10-13-product-feedback-contract.md)已有 Metabase 同屏／分步取舍、CodexBar 理解反馈、CodexIsland 补丁与回滚；不再把首次窄比较列为待做。剩余缺口是同一任务连续操作和修改版实际使用的差异。下一步沿 [Codex Show and tell](https://github.com/openai/codex/discussions/categories/show-and-tell)或公开产品变更，找不同产品的原任务、固定前后产物、选择理由及使用者后续反馈；据此更新 [15](../15-task-playbooks.md)／[23](../23-browser-verification.md)的一条体验取舍。只有布局赞美、宣传截图或作者自评就停，不外推更好用，也不强制所有任务多方案设计。
- **M3：原型之后，继续自建、缩小范围还是替换？** 同一记录中的 Jules 已有删除常驻服务、改用现成能力的产物与成本自述，不能再声称没有替代动作；仍缺必要使用路径是否保住、后续支持负担怎样变化。下一步找迁移后的实际使用／接收记录，核同一组必要能力、权限和导出约束，落到 15／18。没有后续结果就保持条件判断，不把删文件当净收益；可换来源，不无限追一个作者。

### 二、强 Agent 还缺什么，额外能力怎样才值得（R15／R01／R05／R08／R02）

- **M3（R01／R05）：领域依据改善了哪项决定，完整 Skill 又多做了什么？** [领域契约记录](2026-10-13-domain-skill-contract.md)已完成 Cloudflare、原生文件对象、Next.js 三入口及 frontend-design 的拆分，05／15 与入口已同步。下一步仅找真实同任务的原始输入、可读资料、固定产物和使用反馈，比较原生资料、短依据、完整 Skill 的新增决定与投入；区分新知识、新操作、更明确目标和多一次自评。少量依据足够就收窄流程；只有指令文本时止于机制，不伪造三臂效果，也不重做已知修复盲测。落点为 [05](../05-skills-and-plugins.md)／15，非新增 Skill 名单。
- **M3：继续搜更好的算法，还是停在已正确的实现？** 同一记录的 [PerfAgent](2026-10-13-domain-skill-contract.md#性能续改观测层与候选选择)已核候选、最终报告、复制语义反例及运行身份差异，15 §7 已给续改／停止条件。剩余问题是竞争实现的全部尝试成本、未参与选择的输入表现和维护负担。先追能绑定同轮任务、补丁、筛选与最终验收的公开产物；[ShinkaEvolve 固定README](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/README.md)与[圆打包判定器](https://github.com/SakanaAI/ShinkaEvolve/blob/8adc053a2ce4511ad2ac310e004c530a73fb974a/examples/circle_packing/evaluate.py)保留为搜索策略比较入口：沿单一实现续改与保留竞争实现的同需求比较尚未完成；不因有搜索框架就推荐接入。缺成本或运行身份时只补窄机制；不得重做“中间版可优于末版”，不得把科学优化分数当生产软件收益。
- **M3（R08）：已有检索遗漏是否真的改变跨模块修改？** [上下文工具比较](2026-10-13-context-tool-choice.md)已核 repo map 缓存、clangd 内存／磁盘与 Context7 版本／刷新边界。仅在不同真实任务出现错对象、过期状态或漏引用时重开：读对应实现／测试及实际调用输入，判断原生搜索、语义工具或窄资料哪一种补齐缺口，修改 03／04。没有新任务证据，不再重述工具能力；省上下文不等于省钱或提高正确率。

### 三、怎样让第二次、第五次修改仍然可靠（R06／R03／R04）

- **M3（R06）：连续修改后，责任应留在本地还是交还上游？** [Pydantic AI／akgentic 连续链](2026-10-12-development-conditions.md#pydantic-ai取消契约改变不代表正常完成也应改变)已有保存、重放、取消、下游删除补偿与历史 CI，不再排为“找一个连续演化案例”。剩余是最低支持版本的完整验收、发布后旧导入迁移和真实恢复。下一步追同一下游 release note、公开消费者回执及恢复结果；证据表明上游已承担同一责任才撤掉 workaround，仍有不同责任则保留。合并和确定性 CI 不补作真实服务恢复或维护工时；无新交付结果就转别的维护链。
- **M3（R06）：下一次修改失败，是新退化还是继承了旧偏移？** 同一记录的 [CodeThread](2026-10-12-development-conditions.md#codethread下一次修改失败先查继承了什么行为)与 [SlopCodeBench](2026-10-13-slopcodebench.md)已给失败分类和判定器边界。继续归因需固定任务、规格、代码快照、逐测试前后结果，最好能核仅修复已识别偏移后的结果；没有 campaign 原始轨迹就换公开维护链。不能把 Regression 分类当曾通过，不能用局部夹具反例否定全榜。新模型对照只留预注册，不是继续资料调查的前提。

### 四、怎样把生成结果交给真实使用者与下一位维护者（R07／R15，结合 R10／R11）

- **M3：接收者首次重建、恢复或第二次修改，最小交付是什么？** [Immich 与接管实验](2026-10-13-immich-handover.md)、[oMLX](2026-10-13-omlx-postmerge.md)、[Handy](2026-10-13-handy-retest-adoption.md)已有接收修改、受控后续编辑或部分独立运行，不能再写成只有合并。缺口仍是具体接收者的环境／命令、修订后重试与主动投入。沿这些链或新项目找完整过程；根据真实阻塞选择补运行入口、行为解释、恢复操作或直接复用现有自动化，更新 18／15。日历等待不是审查工时，合法降级不是恢复性能目标，跨平台未验不能宣称就绪。
- **M3（R10）：本地／开源模型何时值得承担部署责任？** 只有成本、隐私或运行约束确实改变具体选择时启动。先找同时交代硬件、量化、任务、harness、日志和维护负担的原始报告，对照相同交付目标，落回 18／相关模型页。仅“能跑”或榜单不足以给硬件推荐；资料缺失就标未知，不下载模型补榜、不把它变成独立工具模块。

- **M3 · 候选，未认领：搜索赢家交给维护者后还值得保留吗？** 主线二／四。问题：在已正确的实现与搜索改进版之间，未参与筛选的需求修改、审阅或接管是否改变原性能赢家？沿[PerfAgent既有固定产物与身份限制](2026-10-13-domain-skill-contract.md#性能续改观测层与候选选择)、[ShinkaEvolve固定实现](https://github.com/SakanaAI/ShinkaEvolve/tree/8adc053a2ce4511ad2ac310e004c530a73fb974a)追后续公开补丁、完整尝试账本和接收者回执；框架说明本身不算效果证据。预期细化15 §7“继续搜索／保留候选”的停止与交付条件，必要时收窄额外搜索推荐。与上方搜索问题共用原记录：先找一条同时有筛选与接管结果的链；没有链就标缺口，不重做轻量搜索论文比较，不触碰dot已认领的Skill运行证据。

## GA · 资产管线

### 游戏开发方向

游戏基准仍是单人程序、无人工美术／音频修补，以优秀独立游戏质量为参照。许可清晰的现成、程序化与生成资源共同参与选择；先定玩法、目标设备和实际使用规格。WP0–13 已完成首轮理论交付，来源与反证留在对应记录；真实生产采用、成套二改、引擎结果和投入并未因此通过。GA–GE 继续公开调查，实验统一看 GF，不把“等待实测”当整个方向停止条件。

- **GA：动态许可／服务事实会不会改变现有分档？** 每月按各 [资产页](../../domains/game-dev/03-generative-ai-in-games.md)及 WP1–8 的事实表，到期或采用前核准确模型／权重／依赖／套餐和输出权利；编辑日期不能替代分项核实日期。优先解决会改变商用准入的缺口：TaoFlowForge 实际 DINO 来源／版本及适用许可链（权重仓 Apache-2.0 声明已补核）、Marble Standard 实际商用口径；[WP3](2026-10-14-game-wp3-3d-assets.md)已读 Marble 合同且 Pro 为受限候选，不能再写成整项合同未查。TRELLIS.2／LATO.2 默认依赖及 Hunyuan 输出已有明确限制，只有授权或依赖实质变化才重开，不反复读同版许可求放行。
- **GA：公开生产案例能否补齐“最好一件”以外的证据？** 从已有 WP2–8 来源追实际游戏制作记录，选择一个资源类型，核完整产物／淘汰样本、重生成、程序处理、第二次需求修改和主动工时，比较现成／程序化基线。静态与动画、刚体与变形角色、SFX与音乐／配音分别判断；维护者采用列表、demo和导出成功只作线索。若无法取得生产过程就保留未知，不再解析同一最终文件充作生产证据；落回对应资产页，不扩模型名单。
