# pi-trim：输入减少与费用增加的离线复核

> 核实时间：2026-10-10。评级：👀 评估。仅提取对 Codex/Claude 有用的成本与评估思想，不建议迁移 harness。

当前结论：不因提示更短就承诺省钱，也不据 Pi 结果改 Codex 配置；分别核对缓存、输出与任务结果。[研究]
证据：作者十对历史记录复算为总输入少 20.66%、估算费用多 5.51%；保存 fixture 为 540→274，锁定依赖重生成却为 562→274。[社区：原数据；经验：离线复核]
关键边界：缓存未受控、每题每条件仅一次，未重跑模型或独立重判成功，不能归因为裁剪破坏缓存。[研究：证据边界]

## 提示计数有两个不同结果

已提交 `benchmarks/before.txt` / `after.txt` 用项目的 gpt-tokenizer 重新计数得到 **540 → 274**，与已提交报告一致。但从锁定依赖 Pi 1.0.0 重新生成得到 **562 → 274**。差异定位到基线新增的一段 codemode 文档入口；输出 after 未变。因此“保存的 fixture 数字可复算”成立，“当前锁定环境生成完全相同的基线”不成立。不能把少了多少样板 token 当成包含工具定义的整轮输入收益。**[研究：离线复核]**

## 十题原始记录的账能对上，但没有因果识别

来源：[tasks-openai-codex-gpt-6-sol.json](https://github.com/zhexusun10/pi-trim/blob/ad496c0482fa8179acf4756e298f600fa95abf60/benchmarks/tasks-openai-codex-gpt-6-sol.json)，记录日期 2026-10-02。每题每条件一次；共十对。**[社区：作者记录；研究：本轮复算]**

| 聚合指标 | 原始提示 | 裁剪提示 |
|---|---:|---:|
| 未缓存输入 token | 25,759 | 30,091 |
| 缓存读取 token | 38,144 | 20,608 |
| 总输入 token | 63,903 | 50,699 |
| 输出 token | 3,115 | 3,097 |
| 记录中的估算费用（美元） | 0.0902968 | 0.0952736 |
| 成功标记 | 10/10 | 10/10 |

总输入少 **20.66%**，费用多 **5.51%**。20 条记录均可用每百万 token 的未缓存输入 2 美元、缓存读取 0.2 美元、输出 10 美元重建费用；这是还原作者估算口径，不是本轮核实的官方现价或订阅额度算法。差额为：`4332 × 2 / 1e6 - 17536 × 0.2 / 1e6 - 18 × 10 / 1e6 = 0.0049768` 美元。**[研究：离线复算]**

缓存状态未受控、每题只跑一次、模型后续行为可能不同；轮换执行顺序不足以消除这些因素。数据能解释为什么本组账面费用更高，不能证明“裁剪会破坏缓存”，也不能推出 Codex 原生客户端的额度变化。**[研究：证据分析]**

脚本所谓独立验证，是在新进程中重跑模型已经可见的同一份测试，并检查测试文件没有变化；不是隐藏测试。保存的 JSON 没有每次生成代码和完整轨迹，因此本轮不能独立重新判定十次成功。**[一手：scripts/benchmark-tasks.ts；研究：分析]**

## 对 Codex 使用的判断

✅ 采用其核算思路：遇到“更省 token”方案，同时看未缓存输入、缓存读取、输出、任务完成情况与耗时。👀 暂不采用其收益主张来调整 Codex 配置：它测试的是 Pi harness 配置，不是 Codex 客户端对照；模型供应商或模型名称相同，也不等于工作流相同。减少重复提示有合理性，但不要为省几百个样板 token 删掉真实项目约束。**[研究：采用判断]**
