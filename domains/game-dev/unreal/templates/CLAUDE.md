## Claude Code 专属

- **先按 AGENTS 核对已配置接口与验证入口，再选调用方式。** 已有 Epic 官方 MCP 及 `unreal-mcp` Skill 时，按 Skill 用 `describe_toolset` 确认工具签名，再用 `call_tool`；其他已配置 MCP 按其实际工具签名调用。没有 MCP 时沿用已有 Editor Python/项目脚本；没有安全的资产入口就停写并报告缺口，不自行安装。
- 开始不熟悉的工作前先读项目已有说明。仅在已配置 MCP 暴露 `AgentSkillToolset.ListSkills` 时查看引擎内注册的 Agent Skill，相关的才加载；没有该工具不阻塞现有脚本可完成的工作。
- **有依赖关系的资产、关卡、蓝图修改一律串行**，无论通过 MCP 还是 Editor Python；结果不明确先回读，不盲目重试。
- PIE 运行时许多编辑器工具的行为会变；结果不对时先检查 PIE 状态。
- **编译按改动类型选入口：** 只改 `.cpp` 函数体且已配置入口支持 Live Coding 时才用；MCP 不是其前提。否则沿用已有 UBT/构建脚本，必要时请我关闭编辑器。头文件、反射、新类/模块改动必须关闭编辑器后完整编译。已采用 `ue-build` / `ue-run-tests` 且前提满足时才使用这些 Skill；改完逻辑仍须跑现有相关测试，不能因缺少 Skill 跳过。
- 探索性的资产修改，项目已有 Sandbox 且适用时优先请我开启，确认后再合回项目；没有时遵守项目现有的备份、隔离和资产修改确认流程，不为此升级引擎或安装插件。
- 可独立的大范围检索交给 Explore；涉及引擎生命周期、资产或接口风险时可用 `ue-code-reviewer`，不为每项修改固定叠加评审。
- 不需要我参与的步骤继续做；只有没有我就无法继续（比如需要关闭或重启编辑器），或要做破坏性操作（批量修改资产、改 Config 或 `.uproject`、强推）之前才停下来问。
- 长时间运行结束时，用 **Blocked on me / Changed / Found** 三个标题总结。
- 压缩上下文时，保留已修改文件清单、是否需要重启编辑器，以及使用过的编译和测试命令。
