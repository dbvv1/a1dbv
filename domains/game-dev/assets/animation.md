# 动画与绑定：先固定动作契约，再补生成

> 核实时间：2026-10-14（UTC+8）。适用场景：单人程序员、不做人工美术修补。分档是具体任务的首试顺序，不是同题实测冠军；一手来源、固定源码、许可及反证见[WP4研究记录](../../../docs/research/2026-10-14-game-wp4-animation.md)。

## 先采用什么

**✅ 先固定角色骨架、完整动作组和位移方式，再补生成动作。** 人形角色优先已绑定的角色与成套idle、移动、启停、转向、攻击、受击、死亡动作；动作缺口由玩法决定，不由库里有多少片段决定。只缺少短表演时再比较视频动捕与文本生成；机械、悬浮、铰链与规则分节角色先用位置／旋转曲线和有限IK。[一手／经验]

这替代“输出FBX就进入战斗系统”的默认顺序。骨架、rest pose、蒙皮、动作、重定向与控制器分层保存；第二版只改外观时尽量复用已验收骨架，避免所有动作跟着重生。[研究／经验]

## 三档首试：完整资产优先，生成补缺

先满足[授权总表](../03-generative-ai-in-games.md#13-授权与商用门槛总表wp1)对应的具体版本、地区、输入和发行条件。质量优先指零手修下的交付可靠性，不是宣称某品牌绝对最好。[研究]

|任务|质量优先|性价比优先|本地／免费|
|---|---|---|---|
|**人形角色与动作**|✅ 已验收骨架＋完整现成动作组；缺短表演时🧪Uthana Text-to-Motion 3.0／Video-to-Motion 2.1等专项候选|✅ 地区可用时Mixamo现成动作；需要数值移动控制再🧪Uthana Locomotion；较多自录视频对照Rokoko Vision 3.0|✅ 已有许可动作＋引擎重定向／IK；🧪SkinTokens补绑定，不强凑本地动作生成冠军|
|**2D角色**|✅ 完整现成骨骼／逐帧角色包；Spine资产、编辑器及runtime分别清权|✅ 已正确分层和绑定的结构＋Unity 2D Animation，复用换装／参数|✅ 自有或已核许可逐帧包、Sprite动画与刚体部件曲线|
|**非人形／精确接触**|✅ 专用完整资产组；覆盖不到时修改角色或玩法|🧪 明确分节结构、程序步态与有限IK|👀 SkinTokens／MoCapAnything专项研究，先解决依赖和目标骨架问题|

**撤回条件：** 有限重新生成／录制与程序修正后，仍必须刷权重、补画肢体或逐帧摆姿才能过关，就换资产、缩小动作或改变玩法。若完整现成动作已满足需求，不为使用AI而重新生成。[经验]

**局限：本轮没有同题质量、零手修通过率或第二次修改成本实测；新版本和演示片不能证明完整发售管线。**[研究]

## 自动绑定：有骨架不等于变形正确

**🧪 规范人形输入比较Mixamo／AccuRIG，本地候选比较SkinTokens。** Mixamo限定二足人形，严重异形、大附肢／道具、非中性姿势、游离部件和脏网格可能失败；中国国家码账户不可用。AccuRIG是guided rigging，免费版不包含全部高级蒙皮／减骨能力，不能按“免费自动绑定”省略检查。[一手]

SkinTokens固定版本提供`--use_skeleton`保已有骨架、只生成skin，以及保纹理的`--use_transfer`。第二版只改外观时可优先比较这条路径，而不是重新预测骨架；作者的绑定指标仍不是游戏发布通过率。[一手／经验]

错误先分层：骨轴／rest映射错，修重定向；已明确识别的剑或硬壳被弯曲，修刚性部件权重；关节几何不足、缺面或部件粘连，不能承诺用平滑或“再加骨头”修好。权重总和为1只说明数值合法，不代表剑握得对。[一手／研究]

## 文本、视频和程序动画各补什么

- **文本动作：** 先用于背景idle、招呼和短表演。Uthana Text3.0不保证与场景接触或精确末姿；HY-Motion明确不支持seamless loop、in-place、多人和非人形。不能用提示词“无缝循环”代替能力契约。[一手]
- **可控移动：** Uthana Locomotion有方向、速度、步对数和风格控制，并区分root motion／in-place导出，比反复描述“快一点”更容易对应修改；它仍只是clip生成，不做寻路、碰撞和动态平衡。[一手／研究]
- **视频动捕：** 已能演出所需节奏且单人全身可见、镜头稳定时首试；遮挡、模糊与复杂肢体接触仍可能误判。滤波能减抖，不能把错误姿态变正确；不允许手修时应重录、换来源或撤回动作。[一手／经验]
- **程序动画：** 瞄准、后坐、门轴、悬浮及有限落脚补偿适合明确曲线／IK目标；IK仍需正确链、目标和接触相位，不负责创造自然表演。[一手／研究]

Rokoko Vision在2026-07并入Create，旧双机位和在线webcam已于8月退役；新Vision3.0不含手指追踪。Cascadeur2026.2的动画层仍为Alpha，工具更可编辑不等于零手修；Free非商用且不能导出FBX／DAE。[一手]

## Root motion、循环、接触是三份承诺

**✅ 位移只设一个权威。** 代码移动角色时使用in-place视觉动作，并匹配实际速度／步幅；root motion驱动时由动画位移进入碰撞／控制器处理，避免代码与动画双重平移。跳跃、冲刺和攀爬分别决定Y与XZ来源，不给全部剪辑统一Bake Into Pose。[一手／经验]

**✅ 循环同时检查首尾姿态、速度和接触相位。** 清零水平root只得到in-place；首尾姿态相同也不能证明脚不滑。Unity Loop Pose把首尾相对姿态差分摊整段，不会制造缺失的着地／离地阶段；一次性死亡和落地也不应强制循环。[一手／研究]

**✅ 接触按世界空间和真实道具检查。** 支撑脚阶段可用有限IK，腾空不能一直锁脚；手握持要检查实际武器。攻击命中、恢复、音效、脚步与可取消窗口单独记录。第二次要求“命中提前、恢复不变”时应局部重定时并重建事件，不能只全局加速。[研究／经验]

Shards of Stone作者提供游戏内单位展示，但固定开源重定向脚本直接复制局部姿态旋转，未见其文字承诺的完整rest基底转换和身高缩放；`--loop`只清零hips两个轴，没有首尾闭合。**🧪 借鉴刚体部件隔离和程序步态，⛔ 不原样采用为通用动画管线。** 作者也承认握剑滚转未修和总成本未可靠测量。[一手／研究]

## 重定向与2D路线：复用结构，不补不存在的内容

Unity Humanoid需有效Avatar才能跨角色复用动作；Generic和多足不能直接套用。Unreal IK Retargeter仍需链映射、Retarget Pose及root设置。自动对齐、IK与脚部修正是候选起点，不保证道具握持或缺失动作被补齐。[一手／研究]

**✅ 2D骨骼路线从已正确分层、关节遮盖完整的资产开始。** Unity官方流程仍含骨骼创建、网格细化、权重调整与姿态检查；Auto Geometry／Auto Weights不负责补画隐藏肢体或背面。Spine是成熟创作／运行时工具，不是AI自动绑定器；其完整资产包可减少起步工作，旧Unity示例工程仍需迁移。[一手／研究]

换色、同规格装备和速度尽量复用slot／sprite／骨架。转身、背面、大透视或形变需要相应替换图或完整逐帧动作；没有这些内容时，再评估整段生成或收窄动作。逐帧须保共同画布、pivot、身份与事件，详见[2D专题](2d.md)。[一手／经验]

## 授权与成本会改变自动化路线

- **Mixamo：** 可用于商业游戏，但不将原始动作作为素材包再分发，也不可用服务内容／输出训练、测试或改进AI模型。[一手]
- **Uthana：** 2026-08起新客户按量；Text3.0为US$0.10／秒，Video2.1为US$0.05／秒，Locomotion为US$0.02／秒，循环另计。付费输出与免费CC BY 4.0输出不同；GraphQL可用，默认数据改进条款仍须考虑。[一手]
- **Rokoko：** Basic月付US$12含600秒处理，年付折合US$10／月；免费30秒／月。条款禁止未另授权的脚本／自动化访问，不能因此搭无人值守网页批处理；自生内容和Motion Library资产许可也不同。[一手]
- **DeepMotion：** 免费非商用；付费期间生成的输出获永久商业许可，但不归用户独占所有，禁止独立素材再分发。逐帧纠错返积分需要人工劳动，不计作本基准的免费生产；网页自动化不默认允许，批量接入另核官方API授权。[一手／研究]
- **本地模型：** HY-Motion输出地域条件、GVHMR非商业限制沿用WP1；MoCapAnything V2主代码／权重MIT，但默认RMBG-1.4依赖免费仅非商业。先获许可或验证替代，不能只删下载步骤就放行。[一手／研究]
- **Spine：** runtime源码可读不等于MIT；购买角色包不自动免除runtime集成许可。Essential／Pro收入与投资融资合计门槛、Enterprise及资产包再分发规则分别核对。[一手]

总成本包含全部候选、淘汰、录制、算力和主动修复时间，再除以合格动作数／秒数；月套餐额度、单次生成价格和最终通过成本不是同一个数。免费本地路线也计硬件与维护。[研究]

## 第二次修改决定是否留下

1. 保存骨架／模型、clip命名、源动作、服务版本、root策略、重定向设置、事件与接触标签；原始动作与处理后动作分开。[经验]
2. 第一版通过最小完整动作组；第二版保持骨架换同规格装备，并做一次局部时序／移动速度修改，再增加一个确需新语义的动作。[研究]
3. 自动核骨架映射、clip非空、数值与时长、事件范围、根轨迹、接触漂移、首尾姿态／速度和旧引用；阈值按目标相机、角色与玩法定。[研究]
4. 在真实角色、道具和状态转换中判断动作是否可读、握持正确、风格一致；记录重生／重录次数、淘汰样本及第二改主动工时。[经验]

本轮完成资料、论文、源码和许可比较；真实引擎、目标设备及两轮修改试验待获准执行，不能把这些检查建议写成已经通过。[研究]
