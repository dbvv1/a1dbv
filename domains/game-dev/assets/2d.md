# 2D：先选可修改的表示，再选生成器

> 更新：2026-10-17（UTC+8）。适用场景：单人程序员、不做人工美术修补。以下分档是特定任务的首试顺序，不是同规格实测冠军；来源、许可、成本口径与反证见[WP2 研究记录](../../../docs/research/2026-10-14-game-wp2-2d-assets.md)。

## 30 秒结论

| 你现在要做什么 | 先选什么 | 第一条验收线 |
|---|---|---|
| 改 UI 文案、尺寸、状态 | ✅ 引擎原生控件；图标先找匹配源资产 | 第二次修改不重生整张 UI |
| 透明静态图精细改稿 | 🧪 Sunburst；Flare 同题对照 | 目标尺寸、透明边和局部改动一起过关 |
| 无 alpha 的背景／插图变体 | 🧪 Nano Banana 2.1 付费 API | 总成本包含参考输入、思考和拒绝图 |
| 32–128px 像素角色换装 | ✅ 先复用完整动作／可替换部件源；缺整套外观变体才 🧪 PixelLab | 整套换皮不等于自由配装；缺部件／隐藏面时换来源或缩组合 |
| 小批静态像素／瓦片 | 🧪 Retro Fast/Plus；需要多参考再 Pro | 新图接得回旧图组，逐帧动画另验 |
| 已有本地硬件、免模型许可费 | 🧪 klein-4B；指定 Qwen 旧版作对照 | 不能自动升到 9B/dev 或 Qwen 2.1 商用 |
| Unity 内快速占位／比较玩法 | 🧪 Unity 官方 Sprite Generator | 原型采用；正式零手修发行及引用稳定另验 |

以下均是资料支持的首试顺序；先过具体账户、地区、输入权利和许可门槛，再比较通过率。[研究]

## 先采用什么

**✅ UI 用原生控件，图标先找匹配源资产，瓦片先定连接规则；缺少的视觉内容才生成。** 按钮文字、价格、血量、布局与状态色留在引擎里，装饰底图与文字分开；第二版改文案或尺寸时，不必重画整张界面。

图标可先选 Game-icons、Kenney 等已核许可的匹配项；SVG 只有在内部有可操作部件时才算部件源，不能因后缀是 SVG 就承诺能独立改瓶盖、液面。[一手／研究]

Unity 的 RuleOverrideTile 能保留连接规则、映射另一套 Sprite，适合“草地换雪地”；新增岔路仍需新规则和对应图块。采用匹配引擎版本的官方包，不复制旧仓库代码；Tilemap Extras 并非整包 MIT。**局限：原生参数和现成组合不会补出不存在的轮廓、地形转角或动画帧。**[一手／经验]

## 生成的三档首试顺序

先满足[授权总表](../03-generative-ai-in-games.md#13-授权与商用门槛总表wp1)对应的地区、账户、输入权利和商业生产条件，再比较质量与费用。

| 场景优先级 | 推荐 | 采用理由与撤回条件 |
|---|---|---|
| **质量优先：精细局部改稿、透明静态角色／卡面／图标** | 🧪 GPT Image 2.5 Sunburst，固定 `gpt-image-2.5-sunburst-2026-09-08`；对照 `gpt-image-2.5-flare-2026-09-08` | 官方定位编辑精度；图像指南明确两型号都支持透明 PNG/WebP。若目标尺寸不清楚、局部改动持续串改，改用分层合成或现成资产；两者同 token 费率，若 Flare 同题够用，再按实际 usage、等待和淘汰成本选择 |
| **性价比：概念方案、背景、无 alpha 要求的插图变体** | 🧪 付费 API `gemini-nano-banana-2.1` | 2026-10-06 更新的多参考路线；当前 1K 输出 $0.0336，输入/思考另计。未核到原生 alpha 契约，抠图和淘汰成本可能抵消单价优势；透明切片优先另作对照 |
| **本地／免模型许可费：小批静态道具** | 🧪 FLUX.2-klein-4B；精细编辑可对照 Qwen-Image-Edit-2511，初图可用 Qwen-Image-2512 | 指定版本有已核商用许可路径；计入硬件、等待、挑选和维护。4B 不足时不能自动换免费 9B/dev 商用；无合适硬件时现成资源或 API 可能更划算 |

**⛔ Qwen-Image-2.1 不进入免费商用默认。** 其 2026-09-20 代码／权重许可限非商业研究评估，商业需另行授权；原生 RGBA 能力和旧版 Apache 许可都不能替新版清权。FLUX 3 Image 仅作布局专项对照。[一手／研究]

型号、价格、许可按 2026-10-14 分项核实，来源与复核触发见 [动态事实表](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#9-阶段-f-b图像动态事实表)。成本按全部生成、算力、后处理和主动工时除以合格资产数；每张标价不等于可用成本。

**局限：本轮未找到足以证明的公开证据支持上述最新模型可零手修完成几百件统一资产及第二次修改，本轮也没有测通过率。**[研究]

## 像素风专项：先用小画布和跨帧控制

| 需求与档次 | 首试选择 | 何时撤回 |
|---|---|---|
| **质量／控制性：32–128px 角色，同动作第二次换装** | 🧪 PixelLab 原生参考、调色板、批量 Edit Animation / Transfer Outfit；API 已列对应端点 | 换装导致接触帧、脚底或轮廓漂移，只能手画修补；长动作分组仍接不上 |
| **性价比：静态道具、瓦片候选** | 🧪 Retro Diffusion RD Fast/Plus；多参考不足再对照 RD Pro | 实际接受成本高于现成资产，或新瓦片接不回旧地形；动画另验，不由静态通过代替 |
| **本地／免费** | ✅ 匹配玩法且许可清楚的现成像素包；🧪 已有硬件再沿上文 klein-4B 路线 | 云服务试用额度不算本地免费；需要大量手修则缩小规格或换来源 |

PixelLab 条款允许合规商业输出，禁止未经许可用输出训练模型；部分教程仍写仅扩展，但当前 API 目录已列批改和换装，执行前按 schema 核对。[一手]

Retro 输出归生成者，但新条款允许平台用输出训练，免费样本可能公开；9 月 28 日前的账号要到 10 月 28 日才适用新版，不能提前套用其自动化许可。**局限：两者都未经过本仓的逐帧一致性、第二次修改和引擎验收，sprite sheet 也不等于可编辑骨架。**[一手／研究；许可、价格与接口于 2026-10-14 核实，矛盾及来源见 [像素补核](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#10-阶段-f-c像素专用服务补缺)]

**Unity 内占位可先用官方生成器。** Sprite Generator 把生成视频采样成精灵帧，减少原型接入步骤；官方的原型定位是质量和流程判断，不是商用禁令。Promote / Replace 操作本身也不能证明第二次生成后 GUID、fileID、pivot 和引用稳定。实际生产资格、beta 与输出条款按 [WP9 2026-10-14 补核](../../../docs/research/2026-10-14-game-wp9-engine-handoff.md#8-unity-原生生成器补核原型集成不等于发行管线)执行。[一手／研究]

## 风格锁定：母版、分层，再决定是否训练

1. **先由玩法定规格。** 定视角、最终占屏尺寸、轮廓区分、光向、线宽、色阶、padding 和锚点；[经验]
2. **建立少量已接受母版。** 角色身份、绘制风格、布局参考分工明确，每次从批准母版分叉，保存模型版本、参数、参考和源图；固定 seed 不能代替身份一致性。[一手／经验]
3. **只让模型改需要新像素的部分。** 换色、文字、角标、位置和状态尽量在引擎或脚本里改；主体、底板、阴影、标签分开。原生局部编辑的 mask 是引导，不是严格像素锁。[一手／研究]
4. **确需不变的区域不再经过模型。** 独立生成变更层，再确定性合成回母版。Qwen-Image-Layered 可评估将已有图分成 RGBA 层，但不是恢复真实原稿，也不保证遮挡后部件完整，不能直接当可绑定角色源。[一手／研究]
5. **有反复漂移再加 LoRA。** 同项目多类资产持续偏离、已有权利清楚的优质训练集且成本可摊薄时，才对照训练路线。不要默认先训 LoRA；也不要把官方 base-9B 训练示例直接套进免费商业流程。IP-Adapter 类适合已有兼容管线的专项控制，不是所有新模型通用插件。[一手／研究]

把同类资产放在实际背景、以目标尺寸一起看，判断尺度、光向、轮廓和功能辨识；统一调色板能减少颜色差异，修不了透视、姿态和轮廓错误。**局限：零手修仍需要人选样与验收，母版有错会被整套继承。**[经验]

## 静态、动画、瓦片分别决定

**静态资产：✅ 先母版＋参考编辑，🧪 再做分层与批量变体。** 原生 alpha 省去一次抠图，不代表边缘合格；大图缩小后仍须辨认物品功能。只需同轮廓换色时撤回重新生成；缺少的新轮廓才比较生成或下述代码母版，匹配的合法现成资产仍优先。[一手／经验]

**规则几何、固定视角的小道具：🧪 生成反复画错结构时，可比较代码绘制母版。** SOLREIGN 的历史制作记录把生成不合格的正面机柜改为矩形、线段与重复线圈绘制，再派生持握图；公开快照资源目录的三张 PNG 与制作产物的尺寸、字节数和哈希一致。这是换资产来源，不是修好生成图。**局限：仍要为该物体设计坐标、配色和比例，未证省时或完整零手修发行；**复杂角色、自然纹理或新视角不能沿用这个结论。目标尺寸下仍不清楚、或需人工绘补时，换源／缩需求，不继续堆绘图规则。来源、许可与成本缺口见 [WP2 规则几何小道具](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#15-规则几何小道具从重生成换到代码母版)。[一手／研究]

**逐帧动画：✅ 完整现成动作或正确分层结构优先；已有合格绑定的 3D 角色与动作、只需有限方向时，🧪 先用成熟渲染器从同一源批渲精灵。** 换装备或时序回源修改后重烘，缺合格源才评估受约束整段生成。Dead Cells 的收益在反复改稿，但专业美术参与且接受闪像素，不能证明零手修；必须逐像素清理才能达标就换风格／来源。方向、配装组合持续扩张时，像 Project Zomboid 一样比较保留实时 3D，别只扩图集；详见 [WP2 动画表示取舍](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#2-精灵动画控制身份不等于控制动作)。[一手／研究]

AnimatedTile 只是播放输入帧，视频抽帧和 sprite sheet 也只是帧来源／容器。开发者复盘有身份相似但轮廓抖动、脚底对齐仍不够的反例。[一手／研究]

验收动画要分别看“确有运动、动作正确、首尾及状态衔接”，并检查攻击接触时刻；高剪影相似度甚至可能奖励静止帧。若新动作只能反复整段重生，或必须手画 mask、补肢体／关节才能过关，就撤回该玩法下的零手修采用，换资产、结构或缩小动作范围。[研究／经验]

**瓦片：✅ 完整 terrain set＋连接规则优先。** 分开检查单块自平铺、不同图块允许邻接与转角、图集采样接缝；前两项是内容关系，后一项才是 padding／滤波等导入问题。[一手／经验]

单块对边 RGB 距离均值通过不能证明道路、悬崖和内角正确；新增地形后要复查旧连接与新过渡。缺图时补全图组或撤回该地形需求。[一手／研究]

**只增加中心装饰、连接轮廓不变时，✅ 复用边缘图组，只补中心变体；已有符合布局的合格源图时，🧪 再评估现成 autotile 转换。** Mindustry 的公开修改链把地板组合扩到静态墙，新增金属墙时只为中心增加变体，并在公开 Beta 采用；随后还修复了已有独立预览图时小地图颜色缺失。[一手] 二改同时验整组邻接、预览和派生颜色，不能只看代表图。**局限：组合器不会补出缺失的源像素或新连接形状，公开采用也未证明零手修与工时收益。** 具体处理链、许可与未验证项见 [WP2 瓦片生产链](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#13-瓦片生产链连接图组与中心变体分开修改)。[研究]

## 图集二改：保住源坐标，不必保留透明像素

**✅ 先复用能消费原画布／裁切偏移的导入器；只有 PNG 或消费者不读这些数据时，才保持共同画布／union bounds。** 图集中的紧裁矩形只决定从哪取像素，不能代替角色在源画布中的位置。TexturePacker 的 `Trim` 保原尺寸与位置；`CropKeepPos` 保位置但改变尺寸；`Crop` 会把原位置清零。动作对齐与 UI 布局同时依赖尺寸时，不能只验 pivot。[一手／研究]

Unity 已有 `.ase/.aseprite` 动画可用兼容官方包的 **Canvas pivot**，按源画布位置计算锚点；不要逐帧裁完再统一居中。已有 Paper 2D 图集路线应连同 `.paper2dsprites` 元数据重导入，单独更新 PNG 不能更新切片／pivot。无需为此改源格式或自建图集运行时。[一手／经验]

第二版把武器伸长或改变透明边时，先比较同一动作帧在源画布中的锚点，再检查旧 clip 的帧身份和接触时刻；合并重复像素不能丢掉每帧自己的位置。**局限：坐标保存只能避免导出／导入造成的位移，修不了生成内容本身的脚底或姿态漂移。** 消费者源码、公开 JSON 与历史修复反例见 [WP2 裁切契约（2026-10-15 补核）](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#11-图集二改裁切后保留的是位置还是尺寸)。[一手／研究]

## 压缩二改：先看整段，再决定是否换格式

**[研究] 源图清楚、打包后动画却闪噪，先查最终纹理编码，不急着重生素材。** ✅ 以目标尺寸播放同一动作，与相同条件的无压缩版本比较；只为受损的细描边、渐变或关键动画调整格式／分辨率，其他资产沿用合格压缩。[Ronimo 作者](https://joostdevblog.blogspot.com/2015/11/texture-formats-for-2d-games-part-3-dxt.html)曾弃用静态伪影更少却让动画更闪的编码器；[Factorio 作者](https://www.factorio.com/blog/post/fff-281)也说明提高源分辨率的补救不适合其画风。[一手] Unity 检查最终 Sprite Atlas的平台设置，UE 检查 Final 编码而非只看Fast 预览；先用现成原生选项，不自建压缩器。**局限：局部高保真例外可能增加占用，包体缩小也不等于GPU 内存下降。** 换装／添帧后重验整段；具体边界与成本见 [WP2 压缩取舍（2026-10-15 补核）](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#12-压缩二改静帧误差更小动画仍可能更闪)。

## 透明边二改：先核输入与混合约定

**✅ 合格源图在重导出、重导入或换 shader 后才出现黑／亮边，先核导出、颜色空间／导入与材质输入约定，再决定是否重生。** straight alpha（直通）与 premultiplied alpha（预乘，PMA）不是两档画质；输入已乘过 alpha 又被当直通处理，会重复压暗柔边。一次公开案例中，同一 Spine 图集在原 shader 正常，换 Unity Shader Graph 后出现黑边，维护者指出约定错配，使用者确认改导出后解决。[一手／研究]

Unity 要同时查 shader 是否在采样后预乘与实际 Blend，不能只凭“预乘混合”认定纹理也必须预乘；`Alpha Is Transparency` 是 RGB 扩边，不是通用修复开关。Unreal 则核实际材质的 `Translucent`／`AlphaComposite` 与送入的颜色，不能照搬 Unity 的导入勾选。**局限：这只能修管线错配，不能补坏 mask。** 来源、引擎版本和撤回条件见 [WP2 透明边交接](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#14-透明边交接输入纹理不等于混合输出)。[一手／研究]

**仅缩小后失真：✅ 按消费方式处理，再决定换源。** 二值裁切远处变稀，🧪 比较原生保覆盖 mip，参考阈值匹配材质裁切值；Unity Default 设置不保证最终 Sprite Atlas 沿用。串色先查图集版本、间距与实际 mip，固定 padding 不能保证任意缩小。软透明沿用上述混合约定；原分辨率且不缩放的 UI 可关 mip，像素风按实际缩放范围选择。**保覆盖不保证细轮廓；关键细轮廓仍丢失就换适合目标占屏尺寸的表示／来源。** [原生入口、图集回归与轮廓反例](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#缩小后变稀或串色先选处理位置)。[一手／研究；未运行引擎验证]

## 交付前做一次真实的第二次修改

- **换装预览先核身体完整：** 自制合成图显示衣物漂浮时，先确认头、躯干等必要部件确实加载；缺件就标为无法验收，不因图非空便重生衣服。SOLREIGN 项目记录曾因此撤回补物种变体的判断。**局限：身体完整仍不能排除坐标、层序或消费管线问题；确认源内容有缺陷后，再补源、换源或收窄需求。** [预览误判的证据与边界](../../../docs/research/2026-10-14-game-wp2-2d-assets.md#换装预览异常先排除观察工具缺件)。[一手：项目记录；研究：条件建议]
- **实际尺寸与 alpha：** 在深、浅、对比背景检查遗漏、洞和 halo；像素风可按规格硬化 alpha，柔边绘制不能一律二值化。透明边 RGB 扩展可缓解采样伪影，不能修坏 mask。[一手／经验]
- **pivot 与帧坐标：** 按上面的导入契约保存源位置；没有可消费的裁切元数据时采用共同画布／union bounds，并映射源 pivot。不要逐帧缩放后居中；挥剑和起跳本来就会改变包围盒，支撑脚与腾空阶段分别判断。[一手／经验]
- **第二次修改：** 静态道具增加一种功能；角色改衣色／同规格装备，再将攻击击中提前；瓦片在旧地图新增地形。记录淘汰、重生、主动工时，并检查旧引用、帧序和玩法事件是否仍正确。[经验]

格式、alpha、锚点和引用检查能筛规格错误，不能代替视觉与玩法判断。当前仅完成资料／源码比较；引擎导入、设备表现及两轮成本待获准验证，不等于发行验收通过。[研究]
