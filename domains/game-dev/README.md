## 1. 结合方式全景：游戏开发每个环节里 AI 做什么

| 环节 | AI 做什么 | 怎么接入 | 怎么验证 | 人做什么 | 详见 |
|---|---|---|---|---|---|
| **策划 → 规格** | 把玩法描述整理成规格：状态机、数值表、边界情况、验收标准 | 访谈式 Spec（`spec-interview` Skill） | 人审规格 | **定核心玩法和“好玩”的标准** | [07](../../docs/07-workflows.md#3-大功能访谈式-spec-) |
| **玩法和系统代码** | 写 C# / C++ 逻辑、补测试、重构 | Claude Code / Codex + 引擎 LSP | 编译与规则测试；涉及场景生命周期时补运行时验证 | 定架构和接口，按切片评审 | [unity/02](unity/02-large-project-guide.md)、[unreal/02](unreal/02-large-project-guide.md) |
| **编辑器和资产操作** | 搭场景、改 Prefab / 蓝图、批量设置导入参数 | 引擎 Editor API，按需通过 MCP / CLI 调用 | 检查保存结果与资产引用，保留恢复点 | 按格式与引用关系选择修改路径 | [01](01-engine-integration.md) |
| **运行时验证** | 复用测试、读取状态与动作结果，按问题分析输入、视听与帧时间 | 现有测试／调试入口；观察不足时才补窄接口 | 按待证事实选择规则、运行时、输入、视听与目标设备测试 | 从原型开始试玩，决定手感、乐趣与风格取舍 | [**02**](02-verification-and-playtesting.md) |
| **工具和管线** | 编辑器扩展、导入后处理、配置表解析、构建脚本 | 通用编码工作流 | 脚本测试 | — | [unity/02](unity/02-large-project-guide.md#9-哪些任务适合交给-ai) |
| **资产生成** | 调 3D / 2D / 音频生成 API，批量导入、规范化、记录来源 | API 或 MCP + 编辑器脚本 | 导入检查 | 程序员验收风格与可读性，选择、重生成或程序化调整 | [03](03-generative-ai-in-games.md#1-资产管线agent-负责搬运和规范) |
| **游戏内 AI** | NPC 对话、决策（新兴的决策模型） | 运行时推理（本地或云端） | 无头模拟、可替换接口 | 定设计目标 | [03](03-generative-ai-in-games.md#2-游戏运行时的-ai) |
| **构建和 CI** | 编译、测试、打包、分析失败日志 | 引擎命令行（`unity test`、`UnrealEditor-Cmd`、BuildCookRun） | 退出码 + 报告解析 | 审批发布 | 各引擎子目录 |

## 2. 和普通软件相比，游戏的三个特殊点

1. **源码与资产要分开处理**：C# / C++ 源码可按普通编码流程编辑；资产修改默认交给引擎 Editor API，不要求专用 Agent 接口。Unity 文本资产须维护 GUID / fileID 与 Prefab 关系，直接修改仅作经项目验证的受限例外；Unreal 的 `.uasset` / `.umap` 不做文本补丁。**[一手＋经验：格式与采用边界见 [01](01-engine-integration.md)]**
2. **验证要选对观察对象**：状态正确、输入可用、视听清楚与玩家愿意继续玩是不同的待证事实。先复用已有测试与调试入口，缺少关键观察才补窄接口，不默认改造成 Agent 可试玩；真人反馈从核心玩法原型开始。采用依据与边界见 [02](02-verification-and-playtesting.md)。**[研究]**
3. **内容侧有外部约束**：
   - GDC 2026 调查中 52% 的从业者认为生成式 AI 对行业有害（2024 年是 18%）；
   - Steam 要求披露 AI 生成内容；
   - Godot 贡献与 Asset Store 使用不同 AI 规则，见[渠道边界](../../docs/research/2026-10-13-godot-contribution-policy.md)。

   约束既涉及**玩家看得见的内容**，也涉及代码贡献、审阅和维护责任。**资产供给和工程接入需要一起判断**，不能以能生成或能编译代替可发布，见 [03](03-generative-ai-in-games.md#3-外部约束披露与玩家态度)。

## 3. 按引擎的起点

| 引擎 | 起点 |
|---|---|
| **Unity 6+** | [unity/](unity/README.md)：沿用已有编译／测试；场景与资产操作缺入口时再评估版本匹配的 CLI／Editor API／MCP，模板只合并所需部分 |
| **Unreal 5.8.1+** | [unreal/](unreal/README.md)：已有 C++ 构建／测试为基线，需要编辑器操作时才增最小 MCP 工具集或现成脚本 |
| Roblox | [01 第 2.3 节](01-engine-integration.md#23-roblox把-agent-能力直接做进编辑器)：Studio 内置 MCP，用好 `playtest` 子 Agent |
| Godot / 自研 / Web | 通用编码工作流 + 现有测试／调试入口；按 [02](02-verification-and-playtesting.md) 的待证事实补观察 |

引擎格局速览（VGI 对 Steam 2024 年的统计 **[一手：报告原文]**）：
- 新游戏中 Unity 占 51%、Unreal 占 28%、Godot 占 5%；
- 但百万销量以上的游戏里，自研引擎占 46%、Unreal 占 31%；
- AA、AAA 工作室越来越多地从自研引擎转向 UE5；独立游戏仍以 Unity 为主，Godot 增长最快。

引擎选择对 AI coding 的影响见 [01 第 3 节](01-engine-integration.md#3-引擎选择对-ai-coding-的影响)。
