# G1 资产管线总览：授权门槛、采用条件与外部约束

> 核实时间：2026-10-23（UTC+8）。本轮比较项目用途、资源供给、功能道具、NPC 与世界输出；资源型号和合同沿各节所列核查日期，不把历史条款当今天的全面放行。
> 基准：单人程序员、没有美术和音频人员，不靠人工修图、刷权重或补动画；按玩法和目标设备定规格。未试用生成平台，未运行模型、游戏或引擎；本文是条件选择，不是效果排行榜。按阶段进入见[独立游戏路线图](06-indie-roadmap.md)。

## 30 秒结论：先决定要验证什么，再决定是否需要资产管线

**只想验证一个玩法，可以先生成可玩小样，不必先搭资产管线；准备长期保留代码，才把二改与接管成本纳入选型。** 简单形状／程序化声音足够判断规则时先用它们；若验证的是角色辨识、氛围或反馈，仍需相应质量的资源。[研究]

| 这次要交付什么 | 当前首试与对照 | 什么时候换路 |
|---|---|---|
| 一次性玩法原型，允许扔掉代码 | 🧪 整包生成／托管试玩，与原生 Agent＋最小网页工程比较；浏览器能让目标试玩者验证玩法即可 | 多轮修复仍不能验证核心机制，或素材制作反而主导时间；不为未来可能接管先建完整管线 |
| 可长期接管的小工程 | 先用熟悉的原生 Agent＋最小工程／合适模板；🧪 整包平台只有在其二改与交付符合需要时采用 | 想改规则却只能重生成，或所需源码、依赖、资产不能接手；已知会离平台时尽早试实际导出 |
| 已有 Unity／Unreal 工程扩展 | 留在原工程，按缺口生产资产或复用窄能力；参考 [WP13原生入口／模板](../../docs/research/2026-10-14-game-wp13-agent-config.md#5-p32原生入口拆借模板还是整套游戏管线) | 新工具要求重搭原有行为／存档／资源引用且收益不明；网页整包不作为引擎迁移凭证 |
| 玩家生成就是玩法 | 先比预制部件＋参数，陌生形体表达确有价值再试运行时生成 | 生成没有增加玩家选择，等待／失配或旧对象二改破坏体验；见[玩家造车比较](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#p63玩家造车生成的是形体还是新玩法) |

这是四种用途，不是每个原型必须走完的四道关。以上平台路线均**未试用**；默认是用途判断，不是总质量／省时排名。下文资源、许可和[游戏02](02-verification-and-playtesting.md)的设计／实现／呈现分验继续适用于相应交付。[研究]

**候选怎样用：** 🧪 Phaser Game Agent已公开Web／桌面打包路径，Rosebud另声称可下载可编辑项目源码；两者均未试用，分发包不等于完整源码接管。Rosebud免费版不用于商业项目原型（包括内部使用），浏览器编辑、代码下载和商业权按不同套餐区分，多人还可能依赖外部服务。官方原文、作者导出修复、中文实践及成本边界见[WP13整包原型证据](../../docs/research/2026-10-14-game-wp13-agent-config.md#57-p93整包原型的交付与退出证据)。[一手／社区／研究，2026-10-22核]

## 1. 资产管线：Agent 负责搬运和规范

**采用起点**：先让 Coding Agent 编排规则明确的下载、导入、参数和来源记录；是否更快、更稳要按实际产物验证，有损几何处理不能当作普通规格设置。**[经验：采用建议]**

### 1.1 推荐流程（跨引擎）

**✅ 定玩法／设备规格 → 清权选源 → 保原件与配方 → 脚本接入 → 实际质量验收 → 批准入库。** 生成物先与正式资源隔离，同目录保存来源、版本、日期与许可；占位资源也要有替换计划。[研究]

命名、单位、导入参数可以批量设置；简化、补洞、删除小部件属有损处理，先保原网格再验最终画面。代码／UV缺陷先试程序修正，语义、姿态或蒙皮错误不能靠改格式修好。依据与细薄表面误删反例见[资产返工边界](../../docs/research/2026-10-13-game-asset-editing-boundary.md#生成资产返工先判断缺陷来自哪一层)。生成数量、费用设上限，仍把淘汰重试算入总成本。[一手／研究]

### 1.2 先按资产任务判断，不按品牌整体推荐

**🧪 静态、连续动作和完整供给分验，采用摘要见§1.4–1.10。** 当前质量／性价比／本地三档在各资源专题维护，不在这里另造品牌总榜。[研究]

Unity 原生生成器可作小批原型对照；正式生产仍核兼容包、Cloud／credits、点击条款与供应商，Promote 后重验旧引用。已核入口见[01 §6](01-engine-integration.md#6-unity-内生成器少量原型资产的候选入口)，内置不等于商业总放行。[一手／研究]

### 1.3 授权与商用门槛总表（WP1）

**✅ 先过商业生产门槛，再比较质量。** 对选中的具体版本分别核代码、权重、输入、输出和发布渠道；“开源”“付费”或“输出归用户”都不能单独放行整条管线。[研究]

| 你准备做什么 | 先取得什么证据 |
|---|---|
| 使用现成素材 | 具体包的商用、改造、嵌入发行与署名许可 |
| 本地运行模型 | 代码、指定权重及实际依赖均允许该生产用途 |
| 使用商业生成服务 | 实际账户、地区、计划、生成时间与正式导出符合合同 |
| 将资源装入游戏 | 输入、人物／声音及输出用途已清权，完成渠道披露 |
| 向玩家开放生成或分发模型 | 重新核服务提供、权重分发、终端用户与内容安全义务 |

以下是入口级筛选，详细许可、固定 SHA 和条款日期见 [WP1](../../docs/research/2026-10-14-game-wp1-licensing.md)维护。本节以离线生成后交付资产为主；许可准入仍不保证独占版权、无侵权或平台接收。[一手／研究]

### 1.4 2D采用结论：先可修改，再生成

**✅ UI 文字与布局留在引擎，图标／瓦片先找匹配现成资产。** 独特静态资产再🧪生成，先保批准母版、原生参考和独立图层。按透明精改、无 alpha 变体或本地小批任务选方案，具体三档见 [2D 专题](assets/2d.md)。[一手／研究：依据见 [WP2](../../docs/research/2026-10-14-game-wp2-2d-assets.md)]

自动 QA、透明通道和 sprite sheet 导出仍不能证明动作与瓦片连接正确；几百件成套资产及二改零手修没有充分公开证据。[研究]

### 1.5 3D采用结论：原生低模与可修改结构

**✅ 成套模块／角色优先，独特刚体再🧪原生低模T2.5并锁面数；旧合格T2配方保留，高细节近景对照7.1／Rodin2.5。** 不再默认密网格强减面，但目标面数不是硬上限，quad与自动绑定也不证明变形合格。场景保门、挂点和碰撞边界，角色保已知骨架。处理、二改、许可与成本见[3D专题](assets/3d.md)；零手修发售通过率未测。[一手／研究]

### 1.6 音频采用结论：离线资产，运行时调度

**✅ 短反馈先用成套CC0／jsfxr，保合格子集，缺口才换源或生成。** SFX按事件、配音按台词ID离线交付；音乐按出场密度选择相容曲目／段落。循环、切换、生命周期和持续补录一起验；局部repaint和下载商用权都不保证未来同声音供应。三档、版本与程序处理边界见[音频专题](assets/audio.md)。[一手／研究]

<a id="17-跨资源风格优先共享源资产生成只补缺口"></a>

### 1.7 跨资源风格：首版与下次扩展一起选供给

**✅ 先选能持续补齐的成套来源，再承诺风格；能复用形体就别为图标重生一遍。** 同源模型渲染图标，颜色、文字与角标改参数；新增身份、主题、体型或动作先查配套来源。SNKRX 的语义资源扩展与 Vampire Survivors 后续美术替换说明，两者不因首版包可用就自动解决后续供给。见[成套供应二改](../../docs/research/2026-10-14-game-wp8-style-consistency.md#成套供应二改先选扩展承诺再选生产路线)。[一手／研究]

| 扩展目标 | 采用与对照 | 撤回条件 |
|---|---|---|
| 同类增量，质量优先 | 保批准母版、共享形体和多参考／分件源，不从提示词重新造全套 | 局部修改持续串改身份、轮廓或挂点 |
| 性价比／快速本地 | 已有合法资源、同源参数变体；硬件合适才试已清权本地模型 | 重试、筛选、环境维护与二改总成本超过复用 |
| 新职业／体型 | 比新 rig 的旧装备／变身兼容与既有类别内扩能力；Wildermyth 采用过后者 | 必要组合不能程序补齐就缩范围；可复用持物图不必逐 rig 重做 |
| 高清／新版本 | 比完整供给＋局部 UI、高低规格混合与缩表现目标；OpenGFX2 Classic／High Def 是具体对照 | 低清回退破坏近看目标、辨识或风格，或目标版本玩法仍缺图 |

类别和完整供给反例见[WP8类别兼容](../../docs/research/2026-10-14-game-wp8-style-consistency.md#类别扩展补研新类别不只增加一件资产)与[OpenGFX2版本源](../../docs/research/2026-10-14-game-wp8-style-consistency.md#完整供给不等于高规格覆盖opengfx2的二改选择)。它们支持按扩展承诺选来源，不证明任意新内容零手修。[一手／研究]

**🧪 反复漂移且训练源清权、成本能摊销才加 LoRA。** 少量换色类有效，不推出人物、门、UI 同样有效；保留未训练类别与旧资产作比较。[经验]

**✅ 保配方和批准输出，换模型先旁路比较。** ComfyUI 保存输入／权重、节点依赖版本与执行参数，seed 或 PNG workflow 不能独立复原环境；配置变了重新判断缓存和 QA。最终画面混排新旧资产，由人验敌我、危险、稀有度等语义，Agent 列图标、声音、说明和引用差异；改武器长度同时重看持握、碰撞与图标。几百件跨资源及二改零手修仍未获充分公开证明。[一手／研究，固定源码与例外见[WP8](../../docs/research/2026-10-14-game-wp8-style-consistency.md)]

### 1.8 动画采用结论：骨架、位移、循环与接触分验

**✅ 已绑定角色与完整动作组优先；文本表演、视频动捕、数值控制移动按缺口选。** 固定骨架和位移权威；清零root不等于loop，首尾姿态相同不等于接触正确。自动rig、IK或FBX不能补缺失动作／蒙皮，仍需手修就换源或缩范围。三档与固定源码反例见[动画专题](assets/animation.md)。[一手／研究]

### 1.9 材质与特效采用结论：共同参数源与可控时间

**✅ 同风格材质／参数图优先，玩法特效先用原生粒子；贴图或视频只补缺口。** PBR各通道由共同结构驱动；蓄力、取消、命中留运行时，flipbook可承内部烟火，six-way需正确多方向源。三档、源码、实际采用与许可见[材质与特效专题](assets/materials.md)；CLI故障不外推工具全不可用，发售案例不证明零手修。[一手／研究]

### 1.10 视频采用结论：可编辑镜头先行，生成只补固定片段

**✅ 引擎镜头或静态图＋程序运动优先，无叙事收益就删；🧪生成补外观固定、少分支短镜头。** 按局部编辑、首尾控制和对白选路线，非目标画面不变仍需验。字幕、音轨与进度独立，结束／跳过／恢复走幂等出口；三档、成本、许可和二改见[视频专题](assets/video.md)。[一手／研究]

### 1.11 入库与推荐的最低记录

资产登记保留：具体模型/snapshot 与下载来源、代码和权重许可证版本、生成日期、当时套餐/商业许可凭据、输入/声音权利、官方许可下载状态、必要署名与披露、程序处理和筛查记录。换版本/提供商、进入新发行地区、跨营收门槛或转为运行时生成时先重查 WP1，未查清只作候选。**[经验：根据 WP1 条款差异制定]**

准入不等于质量通过；再按 WP2–8 比较可控性、成本与引擎可用性。

## 2. 游戏运行时的 AI

**固定叙事仍是默认起点。** Heaven’s Vault／Pendragon 的 ink 状态叙事与 Suck Up! 的开放说服分别支持不同玩法选择；这些案例没有证明生成对话普遍更好或更省。来源见 [运行时叙事研究](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#运行时叙事开放表达知识解锁与离线承诺)。[一手：开发者说明；研究：采用判断]

**先决定断网时保留什么玩法。** 可选闲聊可回到固定内容，核心开放说服则应定义暂停／恢复或另验本地版本。Vaudeville 的历史调整说明本地也有设备与语言支持成本，不能直接当免费兜底。[一手：开发者历史复盘；研究]

**台词生成和剧情提交分开。** 角色只收到当前可知信息；关键词可提议解锁，实际进度与权限由游戏核验。Vaudeville 编辑器提供此类配置参照，但提前泄题风险仍需自己的场景验收。[一手／研究]

### 功能道具：生成形体，复用已定义行为

**✅ 有限改装先用预制模块与参数；玩家创造本身是核心才试运行时生成。** Dream Racers 的三词造车提供近期实际采用参照；但同样的词语也可以映射到已批准部件和数值，先比较生成几何额外带来的表达价值。运行时路线不等于更省开发费。[一手：开发者访谈；研究]

**行为仍由游戏定义。** Roblox 指南将多部件生成与 retargetable scripts 分开；形状变了，驾驶、挂点与合法能力仍须接入和验收。Agent 可编排生成与检查，人决定功能、性能预算和体验。当前接口支持范围按项目核实，文档快照不足以承诺任意自定义对象。[一手／研究]

**二改要验旧作品，而不只验新生成。** Trailmakers 给旧铰链加模式仍保旧默认，随后热修又处理旧蓝图回归，说明预制路线也有兼容成本。给车增加能力时保对象身份、行为版本和旧默认；保存后重载、取消后迟到结果与失败回退一并验。批准车辆可保当前局可玩，但未必保住创造玩法。[一手／研究]

来源、三路成本取舍与未执行的接受设计见[同题研究](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#p63玩家造车生成的是形体还是新玩法)。原有授权、设备、人工质量与渠道披露检查继续适用；未证明 Roblox 产物可直接用于 Unity／Unreal。[研究]

### 受限动作：先问玩家因此能做什么

**✅ 已知状态足够决定行为，就保留规则。** 固定规则用脚本，连续需求用已有评分，任务组合与打断用已有行为树；仅需“跟随／等待”菜单时不增加模型。Factorio 的目标规则调整支持从具体玩法倒推行为，而非追求任意指令理解。[一手：开发者复盘；研究]

**👀 模型只提议高层动作和对象，既有逻辑负责执行。** Mantella 的 Follow 由游戏脚本落实，固定实现中缺参还可能回退为整场会话动作。因此执行边界须拒绝缺失／失效对象及过期请求，兼容路径不能扩大作用范围。[一手：固定源码；研究]

**⛔ 没有新增可感知选择，或模型说完成却未改变世界，就缩回菜单／规则。** 同场景对照实际对象状态、取消后迟到回复、延迟、费用及玩家理解；AI People 的公开开发记录也出现过说已交物却未交付的问题。详细固定链与后续预注册见 [受限动作研究](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#受限动作补研开放意图不等于更强战斗-ai)。[一手／研究]

**近期采用把“会说”推进到“能触发行动”，但尚无通用胜率。** Ubisoft Teammates 是语音队友的可玩研究；inZOI v0.10.0 已把位置／活动等上下文用于 Smart Zoi 行为并标记所选动作。玩家既报告自然反应，也报告行为理解与设备问题；采用时验真实状态与玩家能否理解，不拿一条好评替代菜单／规则对照。V2EX 的作者实践可借“合法候选→模型选择→schema与业务校验→执行”，其源码实现与许可未核，不作可复制底座。原文和范围见[本轮NPC证据](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#p97世界输出npc与整页供给选择)。[一手／社区／研究]

### 世界输出：可编辑场景、功能对象与交互视频分开

**🧪 需要三维空间，可把 Marble 与模块化场景作对照；需要可开门、可驾驶、可存档的世界，还要自己的对象语义与行为。** Marble 的 Chisel 用粗布局约束结构、提示控制风格，并支持编辑／扩展／组合；导出的 splat、粗 collider 和视觉 mesh 服务不同用途。场景几何可编辑不等于门与车辆已成为独立功能对象，Unity／Unreal 接入仍要验导出、碰撞、导航、材质与设备预算。[一手：2025-11发布；研究]

**👀 只验证新画面的探索，可评估 Project Genie；它的交互体验和视频导出不是可维护工程交付。** 2026-01 原型文档没有给出 Unity 场景／行为工程出口；当时的时长和地区限制不作为今天的统一限制。Atlas 2026-09 公告是未来 Marble／early access 能力，不冒充普遍可用版本。[一手／研究]

**👀 前沿研究值得借分层，不值得直接替换引擎。** WorldMind 把紧凑状态、NPC 决策、时序控制与视频生成分开；Orchestrated Reality 让模型提议 JSON 差异，经校验后提交世界状态。前者不交付 Unity NPC SDK，后者仍是小规模 WIP、玩家研究待做；schema 外叙述漂移、模型调用回放与并发费用仍有缺口。[研究]

**换一扇门，比重新生成更能说明能否采用。** 同一小房间先用现成模块／参数场景，再与生成场景比较：改门的位置或开门条件时，保住旧物件身份、可走区域、已存状态和非目标外观；如果只能整场景重生且破坏旧引用，退回模块场景或把生成限制为背景。视频探索组则验动作反馈、连续性与表达价值，不用它的画面质量判几何组失败。以上是接受设计，未执行；原文与源码阅读见[世界输出补研](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#p97世界输出npc与整页供给选择)。[研究]

### 完整成本与第二次修改：按交付承诺算账

**✅ 比“完成一次真实交付＋下一次变更”的总投入，不比单次生成价。** Agent 记录全部候选、失败、人工筛选和接入工时；人决定质量、创造收益和等待是否值得。[研究]

| 路线 | 首次与持续成本 | 第二次修改必须保住什么 |
|---|---|---|
| 现成／程序化／离线生成 | 采购或许可、调用、淘汰重试、处理、存储、接入与设备性能；程序化也有维护费 | 批准源、身份与引用；新旧资源混排、旧存档和目标设备；不因新模型可用全量重生 |
| 运行时对象／NPC | 每玩家全程调用与重试、上下文／语音、安全审核、等待；本地计最低设备和分发更新 | 行为与schema版本、合法能力、旧作品；取消后迟到结果、断网／停服的承诺 |
| 世界生成／托管原型 | 生成之外的编辑、几何接入、行为重建、托管与退出成本 | 已交付内容能否重开／继续编辑；仅视频下载不能当工程退出 |

模型调用放可替换接口后，测试可用固定回复；要复演就记录实际调用与状态结果，而非再采样同一提示。可选闲聊可回固定台词，核心开放说服／创造则须明确暂停、保作品或退出模式，不能宣称降级后玩法未损。规则可无头验，真实呈现与玩家选择沿[02验证选择](02-verification-and-playtesting.md#1-30-秒结论这次改动什么结果还没有证据)分验；运行时输出过滤、分级和披露见下一节。[研究]

本节未运行同题体验、二改或成本对照；候选的商业生产、导出和运行时服务权仍须按§1.3逐项准入。[研究]

## 3. 外部约束：披露与玩家态度

**✅ 生成许可与发布渠道分别检查。** 以下沿用 2026-10-14 官方规则核查；来源与未访问后台的边界见 [WP1 发布渠道](../../docs/research/2026-10-14-game-wp1-licensing.md#发布渠道不能被生成许可替代)。[一手／研究]

- **Steam**：Content Survey 重点是随游戏交付、玩家消费的 AI 内容，区分预生成与运行时生成；后者还须说明防止非法内容的措施。普通开发效率工具并非重点，披露也不豁免其他规则
- **Unity Asset Store**：AI 内容说明适用于资产销售提交，不是所有 Unity 游戏的统一发行条款
- **Fab**：Standard License 摘要允许商业整合、禁止独立再分发；购买时仍核完整 EULA 与具体商品许可
- **Godot**：引擎贡献与 Asset Store 按各自渠道规则判断

以下行业统计和历史争议保留原核实日期，不能单凭相关性决定某类资产一律采用或不用：

| 事实 | 来源 |
|---|---|

**对制作与交付的含义**：

| 用途 | 建议 |
|---|---|
| 代码、工具、管线、测试、本地化 | ✅ 优先探索工程用途；按项目／接收渠道政策使用并验证，不能把披露当作准入 |
| 配音、辅助文本 | 🧪 有授权、经人工审核、如实披露 |
| 正式美术（角色、主视觉、宣传图） | 🧪 先过 §1.3 授权与具体显示/一致性验收；不符合时选择重生成、程序处理或现成资源，不以人工修图兜底 |
| 向开源引擎或插件贡献代码 | 先读对方的贡献政策 |
| 商店披露 | 如实、具体地写明用途和人工审核环节 |
