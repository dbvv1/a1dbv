# G1 资产管线总览：授权门槛、采用条件与外部约束

> 核实时间：2026-10-14（UTC+8）补 WP1 授权总表与发布渠道；2026-10-13 的资产处理/静态与动画边界保留；运行时 AI、行业统计等其余易变事实仍为 2026-10-08 资料，未在本轮重新核验。
> 基准：单人程序员、没有美术和音频人员，不靠人工修图、刷权重或补动画。先按玩法和目标设备定规格，再从许可清晰的现成资源、程序化资源和生成资源中选；资源质量与成本分档由 WP2–8 继续补充。
> 本轮只回答“授权上能否继续评估”，不把商用候选写成质量推荐，也不表示已运行模型或引擎。

## 1. 资产管线：Agent 负责搬运和规范

**采用起点**：先让 Coding Agent 编排规则明确的下载、导入、参数和来源记录；是否更快、更稳要按实际产物验证，有损几何处理不能当作普通规格设置。**[经验：采用建议]**

### 1.1 推荐流程（跨引擎）

```
按玩法/设备定规格 → 核授权并选现成/程序化/生成来源 → 隔离原始资产 → 编辑器脚本批量导入并设置参数 → 记录来源 → 引擎内质量验收 → 重新生成／程序化调整或采用
```

1. **隔离**：AI 生成物统一放在单独目录（Unity：`Assets/_Generated/<来源>/`），和正式资源分开，方便替换和许可审计。
2. **记录来源**：同目录放 `SOURCES.md`，写明工具、版本、日期、提示词、许可。发售时的商店披露就从这里汇总。
3. **规格批量设置，有损处理单独验收**：命名、明确的单位换算与导入设置可交给脚本；简化、移除小部件、修复非流形边和补洞要保留原始网格，比较处理前后外观与最终面数，再决定采用。现有清理代码曾把细薄表面误删为碎屑，程序化修复可作为试验路线，不能视为自动提升质量；[固定源码与回归](../../docs/research/2026-10-13-game-asset-editing-boundary.md#生成网格有损后处理不等于规格设置)尚未证明真实游戏发布质量。**[一手：源码与测试阅读；经验：采用边界]**
   - **先定位缺陷，再选修补或重生成**：锁骨扭曲可能来自重定向代码，局部颜色可用区域 UV 脚本修补；有限修补仍无改善时再考虑重生成，避免为程序错误重复生成资产。一个已合并游戏案例提供了三类处理记录及可核验的最终动画，但原始／拒绝资产不完整，不能据此保证零手修发售质量或更低成本。见[产物与反证](../../docs/research/2026-10-13-game-asset-editing-boundary.md#生成资产返工先判断缺陷来自哪一层)。**[一手：项目记录与源码；研究：GLB 局部复算；经验：🧪 采用诊断顺序]**
4. **在脚本里设置数量和费用上限**：生成 API 按次计费。
5. **占位资源要有替换计划**：开发早期的 AI 占位贴图也可能在发售后引发争议（见第 3 节）。

### 1.3 授权与商用门槛总表（WP1）

**✅ 授权先于质量排名。** 分开判断：代码能否商业运行/分发，具体权重能否生产/修改/分发，输出能否装入游戏，以及平台是否接收。表中的“👀 候选”只表示可进入后续质量调查；“👀 有条件”须先满足条件；“⛔ 不默认”不进入默认商用方案。未见特别门槛不等于免除法律、输入素材、人物/声音或第三方依赖的权利要求。**[研究：采用门槛；一手原文、固定 SHA 与反证见 [WP1 记录](../../docs/research/2026-10-14-game-wp1-licensing.md)]**

“封闭服务／不授权重”不妨碍按服务合同使用输出，但不允许自行取得或分发后台模型。开放代码/权重的许可证也不自动变成输出的许可证；Apache-2.0/MIT 的许可、NOTICE/署名、修改及再分发义务按实际分发对象履行。本表以离线生产后交付资产为主，嵌入权重或向玩家提供运行时生成必须重新查整条链。**[研究：适用范围]**

### 1.4 2D采用结论：先可修改，再生成

**✅ UI文字与布局留在引擎，图标/瓦片先找匹配现成资产。🧪 透明静态精改优先评估Image2.5 Sunburst，无alpha插图变体对照Nano Banana2.1，本地小批静态保留klein4B；这是按接口、授权与成本条件选的首试顺序，未证明实测冠军。** 先用批准母版与原生多参考、独立图层合成；反复漂移且训练源与摊销条件成立时再加LoRA。最新Qwen2.1研究许可不允许默认免费商业升级。完整三档、静态/动画/瓦片的撤回条件见[2D专题](assets/2d.md)。**[一手／研究：依据与反证见[WP2](../../docs/research/2026-10-14-game-wp2-2d-assets.md)]**

最关键限制：现有公开证据不足以保证几百件成套资产及第二次修改均零手修；自动QA、透明通道和sprite sheet出口都不能代替动作/连接语义验收。

### 1.5 3D采用结论：原生低模与可修改结构

**✅ 现成同风格模块/角色优先，独特刚体道具再🧪原生低模T2；高细节近景保留7.1/Rodin2.5对照。** 当前原生低模已是商业接口，不能继续默认先密网格再强减面；但目标面数不是硬上限，quad和自动绑定都不证明变形可用。场景保留门、挂点和碰撞边界，角色优先已知骨架体系。分档、工具处理、成本与第二次修改见[3D专题](assets/3d.md)，新候选授权见[WP1增补](../../docs/research/2026-10-14-game-wp1-licensing.md#wp3追加现成3d资产与处理工具)。**[一手／研究]**

关键局限：已有来源和作者产物记录不构成零手修发售通过率；缺拓扑/权重的角色不能靠减面、改格式自动补齐。

## 2. 游戏运行时的 AI

| 方向 | 现状 | 评级 |
|---|---|---|
| **LLM 驱动的对话 NPC** | 已上线的例子：inZOI（NVIDIA ACE，端侧运行）、Suck Up!（玩法就是“骗 NPC 开门”）、堡垒之夜 UEFN 的 Conversations（2026-04 实验功能）**[二手]**。**成功的例子都把“NPC 不可完全控制”变成了玩法本身**，而不是拿 LLM 替代写好的对话树 | 👀（玩法以它为核心时 🧪） |
| **决策模型驱动 NPC 决策** | 2026-09 出现的新模型类别（Jev、Cloudflare Clef、Strands Decider 等）：只从预定义选项中选择并给出置信度，0.8B–2B 模型延迟几十毫秒（详见 [docs/02](../../docs/02-models-and-cost.md#21-新类别决策模型2026-09-起)）。游戏 AI 的多数决策本来就是“从有限选项中选一个”，**特性上很适合，但还没有游戏案例** **[经验：推断]** | 👀 值得做原型 |
| **世界模型** | Google Project Genie（基于 Genie 3，会话约 60 秒，没有持久状态）；World Labs 的 Marble（AMD 2026-09 宣布约 82 亿美元收购，主要方向是机器人仿真）**[二手]**。Take-Two 总裁：“不是游戏引擎” | 👀 概念探索；⛔ 替代引擎 |

**运行时 AI 的工程要点**（和 Coding Agent 的验证闭环直接相关）：
1. **LLM 调用放在可替换的接口后面**：测试和回放时用固定回复的假实现，正式运行再接真模型。否则确定性测试和 bug 复现都会失效。
2. **先用无头模拟评估**：比如“行为树”对比“行为树 + 决策模型”，看玩家可感知的差异是否值得增加的复杂度（见 [02 验证阶梯 L2](02-verification-and-playtesting.md#2-验证阶梯从便宜确定到昂贵主观)）。
3. **成本和延迟**：云端推理按玩家时长计费，和买断制冲突；所以已上线的作品多选端侧小模型（UE 可以用 NNE 运行 ONNX 模型 **[一手：UE 5.8 发布说明]**）。
4. **内容安全**：玩家一定会尝试越狱，要有输出过滤和分级合规方案。

## 3. 外部约束：披露与玩家态度

**✅ 生成许可与发布渠道分别检查。** Steam 当前 Content Survey 重点是随游戏交付、由玩家消费的 AI 内容，区分预生成与运行时生成；后者还须说明防止非法内容的措施。普通开发效率工具并非该问题的重点，披露也不豁免侵权或内容规则。Unity Asset Store 的 AI 内容说明针对资产销售提交，不是所有 Unity 游戏的统一发行条款；Fab 摘要允许把 Standard License 资产整合进商业项目，禁止单独再分发，购买仍须核完整 EULA 与具体商品许可。Godot 引擎贡献和 Asset Store 继续按不同渠道判断。**[一手：2026-10-14 官方规则；来源、例外及未访问后台的边界见 [WP1 发布渠道](../../docs/research/2026-10-14-game-wp1-licensing.md#发布渠道不能被生成许可替代)]**

以下行业统计和历史争议保留原核实日期，不能单凭相关性决定某类资产一律采用或不用：

| 事实 | 来源 |
|---|---|
| GDC 2026：36% 的从业者在工作中用生成式 AI（程序相关用途中“代码辅助”占 47%）；但 **52% 认为它对行业有害**（2025 年 30%，2024 年 18%），美术（64%）、策划（63%）、程序（59%）最负面 | GDC 官方摘要 **[一手]** |
