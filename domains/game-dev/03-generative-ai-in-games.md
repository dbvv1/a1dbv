## 30 秒结论：先定来源，再选模型

| 你的资源缺口 | 优先采用 | 何时撤回 |
|---|---|---|
| 图标、UI、重复道具 | 现成合法资源、引擎 UI、共享源和参数变体 | 实际显示下无法区分，或二改破坏整套 |
| 刚体 3D、材质、特效 | 成套资产与程序化处理，保源和身份 | 脚本达标却损失语义部件或玩法时序 |
| 角色动作、配音和音乐 | 完整动作体系、分段声音与明确的输出权利 | 必须手修、授权不清或后续无法补录 |
| 固定宣传镜头 | 静态／引擎镜头先行，独特片段再试生成 | 把生成展示误当真实玩法或状态可控 |
| 准备发行 | 逐项清权、渠道披露、真实设备与二改验收 | 理论材料不能替代成品证据 |

分档与动态事实见下文各专题；没有一个品牌能一次解决全部资源的许可、质量和迭代问题。[研究]

## 1. 资产管线：Agent 负责搬运和规范

**采用起点**：先让 Coding Agent 编排规则明确的下载、导入、参数和来源记录；是否更快、更稳要按实际产物验证，有损几何处理不能当作普通规格设置。**[经验：采用建议]**

### 1.1 推荐流程（跨引擎）

```
按玩法/设备定规格 → 核授权并选现成/程序化/生成来源 → 隔离原始资产 → 编辑器脚本批量导入并设置参数 → 记录来源 → 引擎内质量验收 → 重新生成／程序化调整或采用
```

1. **隔离**：AI 生成物统一放在单独目录（Unity：`Assets/_Generated/<来源>/`），和正式资源分开，方便替换和许可审计。
2. **记录来源**：同目录放 `SOURCES.md`，写明工具、版本、日期、提示词、许可。发售时的商店披露就从这里汇总。
3. **规格批量设置，有损处理单独验收**：命名、单位和导入设置交脚本；简化、补洞、删除小部件先保原网格，再比较外观与最终预算。已有清理代码误删细薄表面的反例，见[固定源码与回归](../../docs/research/2026-10-13-game-asset-editing-boundary.md#生成网格有损后处理不等于规格设置)。[一手／研究]
   - **先定位缺陷，再决定重生成**：重定向代码错误先改代码，局部 UV 问题先试程序修正。已有[产物与反证](../../docs/research/2026-10-13-game-asset-editing-boundary.md#生成资产返工先判断缺陷来自哪一层)支持这个诊断顺序，但案例缺少完整原始／拒绝资产，不能保证零手修发售或更低成本。[一手／研究]
4. **在脚本里设置数量和费用上限**：生成 API 按次计费。
5. **占位资源要有替换计划**：开发早期的 AI 占位贴图也可能在发售后引发争议（见第 3 节）。

### 1.2 先按资产任务判断，不按品牌整体推荐

**🧪 采用已有的局部判断，暂不排“最佳质量／性价比／本地免费”总榜。** 概念参考、静态可用和连续动画是不同验收目标；[角色回退与静态肖像留用案例](../../docs/research/2026-10-13-game-asset-editing-boundary.md#2d静态可用不推出角色动画可用)支持区分用途，不能证明完整零手修制作已经成功。**[一手：固定补丁；研究：采用条件]**

| 资产任务 | 当前可采取的建议 | 详细判断 |
|---|---|---|
| 2D：概念、精灵、图标、UI、瓦片 | 概念图只作参考；静态资产先验收实际尺寸、透明边缘、锚点和成套辨识，再改一次真实需求；UI 文字/布局优先交引擎绘制 | [WP2条件分档](assets/2d.md)；[WP8整套风格](#17-跨资源风格优先共享源资产生成只补缺口) |
| 3D 与动画 | 保留原始网格，区分静态/刚体和变形角色；先定位代码/UV/生成缺陷，再选程序修正、重生成或现成资源 | [WP3三档与结构](assets/3d.md)、[WP4绑定与动作](assets/animation.md)；分别验拓扑、UV、LOD、碰撞与动作衔接 |
| 材质与特效 | 共同结构源保持PBR通道对应；玩法时间留在原生运行时，flipbook承担内部细节 | [WP5三档与二次修改](assets/materials.md)；现成/参数化优先，生成只补明确缺口 |
| 音效、音乐、配音 | 分开查输出权利；短电子提示音可用 jsfxr 作候选基线，音乐与配音另验循环/状态/角色一致性 | [WP6三档与二次修改](assets/audio.md)；Udio 当前不作默认供应，Eleven Music 不套用 TTS 条款 |
| 视频与过场 | 无必要则删；已有资产优先引擎镜头，有限叙事用静态图＋程序运动；生成只补固定短镜头 | [WP7三档与二次修改](assets/video.md)；字幕/音轨/玩法状态分离，Sora历史服务不作新生产候选 |

完整质量／性价比／本地免费建议见各专题，均为条件首试而非同题实测冠军。Blender 程序处理见[3D 专题](assets/3d.md)；Roblox 等未清权方案仍只作调查候选。[研究]

**Unity 原生生成器：🧪 小批原型对照，👀 正式生产逐项准入。** 先核兼容包、Unity Cloud／credits、点击条款与实际供应商；Promote 后重验旧引用。已核版本与采用条件集中在 [01 §6](01-engine-integration.md#6-unity-内生成器少量原型资产的候选入口)及 [WP9](../../docs/research/2026-10-14-game-wp9-engine-handoff.md#8-unity-原生生成器补核原型集成不等于发行管线)，官方内置不等于商业总放行。[一手／研究]

### 1.3 授权与商用门槛总表（WP1）

**✅ 先过商业生产门槛，再比较质量。** 对选中的具体版本分别核代码、权重、输入、输出和发布渠道；“开源”“付费”或“输出归用户”都不能单独放行整条管线。[研究]

| 你准备做什么 | 先取得什么证据 |
|---|---|
| 使用现成素材 | 具体包的商用、改造、嵌入发行与署名许可 |
| 本地运行模型 | 代码、指定权重及实际依赖均允许该生产用途 |
| 使用商业生成服务 | 实际账户、地区、计划、生成时间与正式导出符合合同 |
| 将资源装入游戏 | 输入、人物／声音及输出用途已清权，完成渠道披露 |
| 向玩家开放生成或分发模型 | 重新核服务提供、权重分发、终端用户与内容安全义务 |

以下是入口级筛选，详细许可、固定 SHA 和条款日期见 [WP1](../../docs/research/2026-10-14-game-wp1-licensing.md)维护。本节以离线生成后交付资产为主；许可准入仍不保证独占版权、无侵权或平台接收。[一手／研究]

#### 图像：开放权重与商业服务分开

**✅ 本地按 checkpoint，云端按具体服务合同选择。** 已核的 Qwen-Image-2512／Edit-2511／Layered、FLUX.2-klein-4B／base-4B 可进入商用评估；新型号不能继承这些旧版本的许可。[一手／研究]

**⛔ Qwen-Image-2.1 研究版、FLUX.2-klein-9B／FLUX.2-dev 免费权重不作默认商业生产。** 后者允许部分输出商用，也不等于允许免费权重商业运行。[一手／研究]

商业图像服务先核地区、输入权利与实际模型，再看透明背景、参考编辑等能力。Firefly 自有与第三方模型、ChatGPT 与固定 API snapshot 分开记录；输出归属不提供独占保证。具体合同见 [图像基础证据](../../docs/research/2026-10-14-game-wp1-licensing.md#图像与视频精确版本服务入口和输出分开)及 [WP2 新型号](../../docs/research/2026-10-14-game-wp1-licensing.md#wp2追加近期图像型号与原生瓦片基线)，首试方案见 [2D 专题](assets/2d.md)。[一手／研究]

#### 3D、绑定与动作：主模型许可不能覆盖整套依赖

**✅ 成套角色／动作先核具体素材，再查处理工具与运行时。** 商业游戏嵌入权和原始 FBX、角色包再分发权分开；Mixamo、Spine、ActorCore 等各按实际内容与用途核查。[一手／研究]

| 容易误选的路线 | 入口判断 |
|---|---|
| TRELLIS.2 主模型 MIT | 👀 主模型候选；推荐安装含非商业 NVIDIA 依赖，解决许可或验证合法替代后再生产 |
| Hunyuan3D-2.1、HY-Motion-1.0／Lite | ⛔ 不默认全球商用；已核地域排除延伸至 Output |
| GVHMR、MoCapAnything V2 默认组合 | ⛔ 不默认免费商业生产；前者软件限非商用，后者有非商业依赖 |
| Meshy、Tripo、Rodin 等服务 | 👀 按生成时套餐、输出与正式导出条款逐项准入；升级不自动清除旧资产限制 |

Meshy 免费输出与公开 Community 内容须区分：免费输出适用 CC BY 4.0；Community 的 Customer Output 为 CC0，其余社区内容如上传参考图为 CC BY-NC 4.0。以具体资产身份判断，不能按“都是社区模型”一并清权。[一手／研究]

完整条件见 [3D／动作许可](../../docs/research/2026-10-14-game-wp1-licensing.md#3d绑定与动作主模型许可不是整条管线许可)、[现成 3D 与处理工具](../../docs/research/2026-10-14-game-wp1-licensing.md#wp3追加现成3d资产与处理工具)及 [WP4 授权记录](../../docs/research/2026-10-14-game-wp4-animation.md#4-授权边界与wp1对应项)。品牌合同只解决准入；入库仍保存实际模型 ID。[研究]

#### 音效、音乐与配音：同品牌也可能适用不同协议

**✅ 按 SFX、音乐、配音分别清权，优先能持续交付文件的路线。** 成套 CC0 声音或 jsfxr 是短反馈基线；声音克隆还需表演者及使用范围授权。[一手／研究]

| 关键门槛 | 采用判断 |
|---|---|
| Eleven TTS／SFX 与 Music | 分别核条款；Music 的 Indie 游戏收入和团队计划门槛不能套用 TTS 付费商用规则 |
| Suno | Pro／Premier 仍须官方允许的 Download；一般条款定义的平台 Remix 不默认商用，免费旧歌不自动追溯 |
| Udio | ⛔ 已核过渡期下载关闭且当前 ToS 未完整提取，暂不作新资产供应；不据此取消旧合法下载权利 |
| 本地音频 | 按指定权重与依赖核查；ACE-Step／Qwen 指定包、Stable Audio 的注册及收入条件各不相同，TangoFlux 不默认商用 |

Eleven Music 还要在发行增长后复核：已核 Indie 条件是单游戏累计净收入低于 US$50 万，开发／发行实体及关联方上一财年全部游戏净收入低于 US$100 万；Studio Game 需合格 Enterprise Music，Lite 不覆盖。套餐人数与下载规格另查 [计划、下载及升级／存续例外](../../docs/research/2026-10-14-game-wp1-licensing.md#核对后的采用判断)。[一手／研究]

各产品、计划与存续条款见 [音频许可](../../docs/research/2026-10-14-game-wp1-licensing.md#音频具体产品下载与生成时间决定授权)和 [现行型号／声音连续性](../../docs/research/2026-10-14-game-wp1-licensing.md#wp6追加现行音频型号与声音连续性)；质量和补录选择见 [音频专题](assets/audio.md)。[一手／研究]

#### 视频：先有制作必要性，再核商业生产路径

**✅ 先确认镜头值得做，再核正式导出与使用入口。** 商用成片许可、网页自动化权限和向玩家开放 API 是三项不同权利；程序化生产优先官方接口。[一手／研究]

- **本地**：已核 Wan2.2 三个指定权重可进入评估；LTX-2.5 的社区许可包含关联实体营收门槛、依赖与机器生成披露条件
- **云服务**：Runway 与 Google 付费 Developer API 按具体模式、地区和合同使用；Web 订阅不替代 API 访问与费用
- **交付**：保存合法导出的本地母版，临时结果链接不能作为游戏资源；Sora 历史服务不作新生产候选，旧输出另按生成时条款核查

以上保留原核实范围。版本与法律门槛见 [图像／视频基础证据](../../docs/research/2026-10-14-game-wp1-licensing.md#图像与视频精确版本服务入口和输出分开)及 [WP7 许可增量](../../docs/research/2026-10-14-game-wp1-licensing.md#wp7追加视频编辑正式导出与自动化入口)，镜头选择见 [视频专题](assets/video.md)。[一手／研究]

**✅ 可修改的现成资源和参数化工具是正式生产来源，不只是占位。** 先挑符合玩法与风格的具体包；软件开源许可不能替包内素材清权。[研究]

### 1.4 2D采用结论：先可修改，再生成

**✅ UI 文字与布局留在引擎，图标／瓦片先找匹配现成资产。** 独特静态资产再🧪生成，先保批准母版、原生参考和独立图层。按透明精改、无 alpha 变体或本地小批任务选方案，具体三档见 [2D 专题](assets/2d.md)。[一手／研究：依据见 [WP2](../../docs/research/2026-10-14-game-wp2-2d-assets.md)]

自动 QA、透明通道和 sprite sheet 导出仍不能证明动作与瓦片连接正确；几百件成套资产及二改零手修没有充分公开证据。[研究]

### 1.5 3D采用结论：原生低模与可修改结构

**✅ 现成同风格模块/角色优先，独特刚体新需求再🧪原生低模T2.5并显式锁面数；旧合格T2配方保留；高细节近景保留7.1/Rodin2.5对照。** 当前原生低模已是商业接口，不能继续默认先密网格再强减面；但目标面数不是硬上限，quad和自动绑定都不证明变形可用。场景保留门、挂点和碰撞边界，角色优先已知骨架体系。分档、工具处理、成本与第二次修改见[3D专题](assets/3d.md)，新候选授权见[WP1增补](../../docs/research/2026-10-14-game-wp1-licensing.md#wp3追加现成3d资产与处理工具)。**[一手／研究]**

关键局限：已有来源和作者产物记录不构成零手修发售通过率；缺拓扑/权重的角色不能靠减面、改格式自动补齐。

### 1.6 音频采用结论：离线资产，运行时调度

**✅ 短反馈先用成套 CC0 资源／jsfxr；独特声源、主题或角色才增加生成。** SFX 按事件、配音按台词 ID 交付，默认离线；音乐先选出场密度，再决定相容曲目或段落与切换。必要的循环／状态切换、生命周期验收和声音持续补录，比一次出声更重要。三档候选和当前型号见[音频专题](assets/audio.md)。**[一手／研究：来源与代码反证见[WP6](../../docs/research/2026-10-14-game-wp6-audio.md)]**

关键局限：参数化噪声也未必同参数位级复现；局部repaint、下载商用权和未来同voice_id供应是不同承诺，程序处理修不了错误表演或未授权声音。

### 1.7 跨资源风格：优先共享源资产，生成只补缺口

**✅ 按首版和下一次扩展一起选成套供应，再承诺风格与内容范围。** 同风格包、参数化材质和同一骨架体系优先；已有3D道具先从同模型渲染图标。换色、文字和角标改参数，新增身份／主题／动作先确认配套来源。[研究]

**能复用形体，就先补语义资源，不必全套重生。** 新机制仍可能需要图标、拾取声音、说明和对象预算；SNKRX同风格扩展沿这条路线，后续也付出了规则与供给上限的返工。[一手／研究]

**要保持独特风格又扩大内容，就先确认新增供给。** Vampire Survivors从现成包出发，后来靠画师替换与团队制作扩展，并非原包自动补齐。零手修项目若拿不到合格的新来源，应调整扩展范围或表示，而不是承诺以后由AI补完。两条独立制作链及成本边界见[成套供应二改](../../docs/research/2026-10-14-game-wp8-style-consistency.md#成套供应二改先选扩展承诺再选生产路线)。[一手／研究]

**AI负责列跨资源差异、接入与机械检查，人验新旧组合是否表达同一规则。** 重点防止只新增画面而漏图标、声音或说明；用一次实际扩展同时检查这些消费者，不以文件齐全当作质量通过。[研究]

**✅ 新增职业／体型前，先核旧内容的兼容范围，不只估一个新角色。** 职业若只是规则变化，不必新建外观体系；确需新rig时，先列必须继续支持的旧装备、变身和姿态，再比较在现有类别内扩能力／装备。Wildermyth明确因rig配套成本优先扩既有类别，后续也实际发布装备与变身扩展；但可通用的持物图不必逐rig重做。无法用合法源、参数或程序补齐必要组合时，缩支持范围或撤回新类别，不用手修兜底；不是禁止有核心价值的新类别。见[类别扩展与兼容代价](../../docs/research/2026-10-14-game-wp8-style-consistency.md#类别扩展补研新类别不只增加一件资产)。[一手／研究]

| 任务目标 | 首选路线 | 何时撤回 |
|---|---|---|
| 质量优先 | 成熟同风格源；缺口再用多参考、分件与保留图层的生成 | 局部修改持续串改身份、轮廓或挂点 |
| 性价比优先 | 同源颜色、材质、尺寸与布局变体 | 重试、筛选和二改总成本超过复用源 |
| 快速／本地 | 已有成套资源和程序化表示；硬件适合再用已清权本地模型 | 维护或通过率不合适，改现成资源／API |

**完整包与高规格覆盖分开选，界面放大不必带动全场景重做。** 先选覆盖目标版本玩法的完整基线，再按需要补字体／UI倍率；若近看车辆、建筑才是目标，低清回退不能算高清完成。OpenGFX2把完整Classic与未补齐的High Def分开，Classic仍独立处理多倍率界面；新版玩法缺图又可能迫使换供应。先比较现成完整版、允许混合回退的高规格版和缩小表现目标，不默认全量重生；回退破坏辨识或风格、维护超预算就撤回。[同作品版本、源码与发行反例](../../docs/research/2026-10-14-game-wp8-style-consistency.md#完整供给不等于高规格覆盖opengfx2的二改选择)；只证明既成包采用，不证明任意新内容零手修。[一手／研究]

**🧪 反复漂移且训练源清权、成本能摊销时才加 LoRA。** 少量换色源可能覆盖数百件道具；人物、门和 UI 却不能靠一个宝石训练集证明一致。保留未参与训练的类别与旧资产作比较。[经验]

**✅ 保存配方和批准输出，换模型先旁路比较。** ComfyUI 记录执行 JSON、输入／权重哈希、节点依赖版本、采样及裁切参数；seed 或 PNG 内嵌 workflow 不能独立复原全部环境。输入或配置改变后，缓存与 QA 结果应重新判定。[一手／研究]

**在最终画面混排新旧资产，验风格也验辨识度。** 调色板和自动相似度只能辅助筛查；敌我、危险、稀有度及关键部件仍须人工判断。改武器长度要重看持握、碰撞和图标，不能只验颜色。[研究／经验]

固定视角、有限换装和成熟骨架更可控，前提是玩法接受这些表现边界。几百件跨资源资产及二改全部零手修仍无充分公开证据；固定源码、批处理反例和风格比较见 [WP8](../../docs/research/2026-10-14-game-wp8-style-consistency.md)。[研究]

### 1.8 动画采用结论：骨架、位移、循环与接触分验

**✅ 已绑定角色和完整动作组优先；文本表演、视频动捕、数值控制移动分别补缺。** 先固定骨架与位移权威，改变外观尽量复用已验收动作；清零root不等于loop，首尾姿态相同不等于脚接触正确。当前商业/本地及2D三档见[动画专题](assets/animation.md)，固定源码反证见[WP4](../../docs/research/2026-10-14-game-wp4-animation.md)。**[一手／研究]**

关键局限：自动rig、IK或FBX出口不能制造缺失动作、正确蒙皮与隐藏肢体；仍需手画、刷权重或逐帧摆姿时，零手修路线应收窄或更换来源。

### 1.9 材质与特效采用结论：共同参数源与可控时间

**✅ 同风格现成材质／参数图优先，玩法相关特效先用原生粒子；生成贴图和视频只补明确缺口。** 材质的base color、normal／height、roughness与metallic由共同结构驱动，不能把四张独立生成图当同一表面；蓄力、取消和命中事件留在运行时，flipbook可以承担烟火内部动画，six-way需要正确的多方向源数据。商业、性价比、本地三档及撤回条件见[材质与特效专题](assets/materials.md)，固定源码、许可和真实采用反证见[WP5](../../docs/research/2026-10-14-game-wp5-material-effects.md)。**[一手／研究]**

关键局限：本轮没有同题资产、真实引擎性能及二次修改实测；Material Maker CLI故障不能外推整个工具不可用，现成工具发售案例也不证明全程零美术修补。

### 1.10 视频采用结论：可编辑镜头先行，生成只补固定片段

**✅ 引擎镜头或静态图＋程序运动优先，无叙事收益就删过场。** 🧪 生成只补外观固定、少分支的短镜头；按局部编辑、首尾控制、无对白等具体需要比较服务与本地路线。具体三档、成本与许可见 [视频专题](assets/video.md)及 [WP7](../../docs/research/2026-10-14-game-wp7-video.md)。[一手／研究]

字幕、音轨与玩法进度独立于影片，正常结束／跳过／恢复走幂等状态出口。局部编辑未保证非目标画面不变，成套过场仍待零手修与真实设备验收。[研究]

### 1.11 入库与推荐的最低记录

资产登记保留：具体模型/snapshot 与下载来源、代码和权重许可证版本、生成日期、当时套餐/商业许可凭据、输入/声音权利、官方许可下载状态、必要署名与披露、程序处理和筛查记录。换版本/提供商、进入新发行地区、跨营收门槛或转为运行时生成时先重查 WP1，未查清只作候选。**[经验：根据 WP1 条款差异制定]**

授权通过只让方案进入 WP2–8 的质量、可控性、成本与引擎可用性比较，不能证明输出可获版权、无侵权风险或平台必然接收。

## 2. 游戏运行时的 AI

| 玩法缺口 | 优先采用 | 增加生成的条件 |
|---|---|---|
| 记住选择、按进度切台词／线索 | ✅ authored／数据驱动叙事 | 自由措辞与说服策略本身构成挑战时才🧪生成对话 |
| 追击、撤退、需求与目标选择 | ✅ 脚本、效用评分或行为树 | 开放意图映射到有限高层动作本身有玩法收益时才👀LLM |
| 世界／场景背景 | 👀 [3D 资产候选](assets/3d.md) | 先核网格、碰撞、导出与许可，再评估玩法整合 |

**固定叙事仍是默认起点。** Heaven’s Vault／Pendragon 的 ink 状态叙事与 Suck Up! 的开放说服分别支持不同玩法选择；这些案例没有证明生成对话普遍更好或更省。来源见 [运行时叙事研究](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#运行时叙事开放表达知识解锁与离线承诺)。[一手：开发者说明；研究：采用判断]

**先决定断网时保留什么玩法。** 可选闲聊可回到固定内容，核心开放说服则应定义暂停／恢复或另验本地版本。Vaudeville 的历史调整说明本地也有设备与语言支持成本，不能直接当免费兜底。[一手：开发者历史复盘；研究]

**台词生成和剧情提交分开。** 角色只收到当前可知信息；关键词可提议解锁，实际进度与权限由游戏核验。Vaudeville 编辑器提供此类配置参照，但提前泄题风险仍需自己的场景验收。[一手／研究]

### 受限动作：先问玩家因此能做什么

**✅ 已知状态足够决定行为，就保留规则。** 固定规则用脚本，连续需求用已有评分，任务组合与打断用已有行为树；仅需“跟随／等待”菜单时不增加模型。Factorio 的目标规则调整支持从具体玩法倒推行为，而非追求任意指令理解。[一手：开发者复盘；研究]

**👀 模型只提议高层动作和对象，既有逻辑负责执行。** Mantella 的 Follow 由游戏脚本落实，固定实现中缺参还可能回退为整场会话动作。因此执行边界须拒绝缺失／失效对象及过期请求，兼容路径不能扩大作用范围。[一手：固定源码；研究]

**⛔ 没有新增可感知选择，或模型说完成却未改变世界，就缩回菜单／规则。** 同场景对照实际对象状态、取消后迟到回复、延迟、费用及玩家理解；AI People 的公开开发记录也出现过说已交物却未交付的问题。详细固定链与后续预注册见 [受限动作研究](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#受限动作补研开放意图不等于更强战斗-ai)。[一手／研究]

工程上保留四个边界：[经验]
1. 模型调用放在可替换接口后，测试和回放用固定回复
2. 规则结果可用无头模拟；实际呈现与玩家选择按 [02 验证选择](02-verification-and-playtesting.md#1-30-秒结论这次改动什么结果还没有证据)验收
3. 云端按玩家全程用量估成本，本地按最低设备、内存与更新预算取舍
4. 准备输出过滤与分级合规方案，并将运行时生成纳入渠道披露

本节为资料与固定实现阅读，没有运行游戏、模型或同题体验／成本对照。[研究]

## 3. 外部约束：披露与玩家态度

**✅ 生成许可与发布渠道分别检查。** 以下沿用 2026-10-14 官方规则核查；来源与未访问后台的边界见 [WP1 发布渠道](../../docs/research/2026-10-14-game-wp1-licensing.md#发布渠道不能被生成许可替代)。[一手／研究]

- **Steam**：Content Survey 重点是随游戏交付、玩家消费的 AI 内容，区分预生成与运行时生成；后者还须说明防止非法内容的措施。普通开发效率工具并非重点，披露也不豁免其他规则
- **Unity Asset Store**：AI 内容说明适用于资产销售提交，不是所有 Unity 游戏的统一发行条款
- **Fab**：Standard License 摘要允许商业整合、禁止独立再分发；购买时仍核完整 EULA 与具体商品许可
- **Godot**：引擎贡献与 Asset Store 按各自渠道规则判断

以下行业统计和历史争议保留原核实日期，不能单凭相关性决定某类资产一律采用或不用：

| 事实 | 来源 |
|---|---|
| GDC 2026：36% 的从业者在工作中用生成式 AI（程序相关用途中“代码辅助”占 47%）；但 **52% 认为它对行业有害**（2025 年 30%，2024 年 18%），美术（64%）、策划（63%）、程序（59%）最负面 | GDC 官方摘要 **[一手]** |
| Steam：原研究样本期内约 1/3 的新游戏声明使用 AI；它们取得小有成功（≥100 条评测）的概率只有非 AI 游戏的约 55%；**只用 AI 出美术的作品失败最集中**，而成功作品更多把 AI 用在本地化、配音等环节 | 该研究的 53,597 款游戏样本 **[社区：原文]** |
| 2025-12，《光与影：33 号远征队》因早期用过 AI 占位贴图（发售前已替换）被撤销 Indie Game Awards 年度游戏 | HN 讨论 **[社区]** |
