# Gameplay 架构：让第二次修改仍然可靠

> 编辑：2026-10-22（UTC+8）；补共享能力修复与旧项目版本的选择，缓冲所有权、时钟信任及其他证据日期见各节研究。

适用：单人独立游戏；Unity 为主、Unreal 对照。

**✅ 原生组件、可测试规则和局部状态机优先；明确状态所有者、结算点、退出清理再加框架。** HFSM／行为树／GAS／ECS 各解不同问题。[研究]

以下 AI 分工由本页契约与 [WP11](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md) 的失败机制推导，是委派建议，不是模型能力实测。验证方案待执行，手感／性能／维护收益未验证。[研究]

## 30 秒结论：先保状态，再选框架

| 问题 | 第一个选择；升级条件 |
|---|---|
| 少量阶段／技能 | 组件＋小状态机；共享退出逻辑多才用 HFSM |
| 组合优先级 | 行为树／StateTree；先确认复用与编辑收益 |
| 追击堵门 | 原生导航；区分通路、避让、停距与位移所有者 |
| 打断与重开 | 取消规则＋唯一结算；标签／效果／属性／预测反复出现再评估 GAS |
| CPU 超预算 | 先定位；Unity 局部 Jobs/Burst，测量支持才 ECS |
| 随机关卡 | 动作空间用房间组合，地形探索用受约束布局 |
| 整套关卡二改 | 保既有制作路径；二维重复批改才试语义源＋规则，不能免教学／进度返工 |
| 相机／关卡变化 | 原生相机、稳定 ID、可重置遭遇；按实际需求扩展 |
| 本地多人 | 同区且可读可共屏，自由分离比较分屏；核双方控制与楼层显隐 |
| 影子／回放 | 展示录姿态，复现原因重演输入，倒带续玩需可恢复状态 |

## 当前最高水平：强 Agent 是否改变架构默认？

<!-- frontier: status=已比较 gap=2 gen=2026-09 checked=2026-10-21 -->

**最高水平仍未知；保留原生组件＋可测试规则＋局部状态机。** 2026 年的 Codex 作者实践和公开二改产物支持沿既有结构拆规则、修状态边界；尚无当前模型在同一玩法二改中，GAS／ECS／HFSM 对照基线的维护总成本证据。这是可行默认，不是最佳架构排名。[一手／研究]

本轮比较了离线收益的本地时钟与服务器锚定，以及沙盒模拟的逐帧分配与局部缓冲复用；真正改变验收的是信任和寿命边界，不是框架名称。模型、人工审查与后续补丁归因分别见 [WP11 近期二改](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#近期-coding-agent-二改缓冲寿命与时钟信任)。[研究]

## 1. 先选够用的结构

**反复出现的玩法能力，先复用窄接口模块，让 Agent 做组合。** Phaser Studio 的近期实践将碰撞／对象池等难点封装，能力模块携带配置与已验证的陷阱，避免每加一种玩法都扩张框架接口。可借模块边界和试玩反馈回流，不据此迁移 Unity／UE；见 [WP11 专业候选](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#近期-coding-agent-二改缓冲寿命与时钟信任)。[一手／研究]

**共享能力修好了，旧游戏也要确认是否接收。** Phaser Studio 2026-09 将反复出错的方向计算与鼠标视角收进 AE 能力，但既有游戏保留原模型／引擎版本。Agent 先核当前项目能力，再比较局部修复与升级；人验证左右、上下与鼠标捕获的实际操作，迁移引入回归时退回已验证版本。AE 与开源 Phaser 4 是不同引擎，只借设计模式，不照搬 API；详见 [版本化能力补查](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#p53补查共享能力修复怎样进入旧游戏)。[一手／研究；厂商报告，未实测迁移成本]

⛔ 省通用循环、字符串总线、几招先建 DSL、小关卡先建大世界。👀 商业图需长期编辑收益；依赖升级时重评，许可见第 10 节。[研究]

## 2. 游戏循环：一局结束要真的结束

**✅ Session／Run 拥有本局运行状态与资源。** 启动／前端／加载／游玩／暂停／结算按需保留；重开新局，常驻设置／存档另管。[研究]

**AI 分工：** 可补 Session 装配、取消与回归用例；典型风险是旧局回调写入新局；连续重开后触发旧回调，核新局状态不变、订阅与任务回到基线。[研究]

- **原生基线**：Unity 沿 Update／FixedUpdate，各模块明定时钟；UE GameInstance 跨关卡、GameMode 随关卡、Pawn／Controller 分工，常驻服务不留旧世界引用。[一手／研究]
见 [WP11 游戏循环](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#1-游戏循环把一局结束做成真正的生命周期边界)。[一手／研究]

**承诺离线收益才补算。** 顺序影响购买／解锁时分批逐步；容许误差才粗步，规则允许才聚合结算。粗步可能减少按步触发的自动化次数，不能据此称无损加速；跨边界重算，同一状态不由补算与在线同时推进。见 [WP11 离线收益](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#离线收益补研等待精度与结算边界)。[研究]

**离线收益先定是否允许玩家改钟。** 需要可信经济时，再比较服务器锚定与单调计时；纯本地单机可以选择容许改钟，不为防作弊强加在线依赖。Agent 可实现时钟与结算，人决定信任政策并试玩改钟、恢复和重复结算。近期作者的失败修复及未公开成本见 [WP11](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#近期-coding-agent-二改缓冲寿命与时钟信任)。[一手／研究]

## 3. 状态机与行为树：先定义打断关系

**✅ 每个状态声明入口、出口、结束条件、打断优先级和清理动作。** Idle／Pursue／Attack／Dead 用小状态机；共享父层规则／退出等待明显增加才用 HFSM，多目标优先级与复用子树确有收益才用行为树。[研究]

**AI 分工：** 可实现状态转换、打断与清理；典型风险是状态退出后异步任务仍写入；在任务未完成时切换状态，核旧任务失效、新状态继续执行。[研究]

**按实际版本核生命周期。** Unity Behavior 1.0.16／UnityHFSM 2.3 的修订及 UE BT／StateTree 的并发、打断差异见研究，不能把图节点的退出当成所有任务结束。[一手]

退出须停止旧任务写入；简单敌人省图编辑器／多套决策。见 [WP11 状态机](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#2-状态机行为树与-statetree先问什么会打断什么)。[研究]

### 感知与搜索：持有目标不等于知道当前位置

**✅ 躲避属于玩法时，分开目标身份、已知位置和感知。** 搜索仅用获准线索，不因持有对象就读实时坐标；有意直接追踪可保留。[研究]

**AI 分工：** 可实现线索更新与搜索状态；典型风险是失去感知后仍读玩家实时坐标；遮断感知再移动玩家，核搜索只消费获准线索。[研究]

- **Unity**：选择位置而非目标输入后，仍须查上游是否每帧刷新玩家坐标。[一手／研究]
- **UE**：当前感知、已知目标与刺激年龄不同；目标跟踪会继续读 Actor，搜索可切位置键。自动遗忘还须核系统与刺激寿命配置，不能只换移动节点。[一手／研究]

角色感知不限制全局导演调度；SPD 群体智能也允许传位置。无须另建记忆框架。见 [WP11 感知](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#感知补研角色知道什么与导演调度什么)。[一手／研究]

### 追击与让路：有路径不等于走得自然

**✅ 原生导航分清通路、避让、停距和位移所有者。** 近邻用避让，堵路更新通行区域；近战定停距／侧移／卡位。跟随先沿组件契约，测得成本才节流。[研究]

**AI 分工：** 可配置导航过滤、停距及开门动作衔接；典型风险是选中角色无权通过的门；对照可开／不可开的角色切换门状态，核选路与实际通行一致。[研究]

- **Unity AI Navigation 2.0.16**：避让不保证绕堵；静止可推箱可用 carving。位移只留一个所有者；更新延迟、刚体／动画及 Agent／Obstacle 并用限制见研究。[一手]
- **UE**：RVO／Detour Crowd 择一；前者可能越出 NavMesh，需走廊约束才评估后者，并核 Agent 上限。[一手]

**可开门的角色别把所有关门都当绝路。** 按能力／门状态选通路，再由已有交互动作开门与通行；不能通过就排除该路线，抬高成本只改变偏好。Unity 可用区域过滤／链接表达适合的规则，仍需项目同步门状态与权限。OpenMW 的历史开门修订与选锁门问题并存，动作正确不保证选路正确；具体契约见 [WP11 导航](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#导航补研通路局部让路与停止位置)。[一手／研究]

Factorio 取消同类硬碰撞，Overgrowth 组合停距／侧移／排斥；需身体卡位时保留碰撞。见 [WP11 导航](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#导航补研通路局部让路与停止位置)。[一手／研究]

## 4. 数据驱动：定义、实例、存档分开

**✅ 定义放稳定 ID／参数／资产，实例放活状态，存档放快照／schemaVersion。** 沿 SO／DataAsset／表格，校验 ID、引用、范围。[研究]

**AI 分工：** 可生成定义／实例映射、校验与迁移代码；典型风险是旧档能加载却无法继续执行；用含旧队列的存档升级、继续执行并重载，核结果符合迁移约定。[研究]

Chop Chop 的血量重置修复反证：同一类型也可能有不同寿命。见 [WP11 数据](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#3-数据驱动配置静态定义活实例存档不能同一个对象)。[一手／研究]

改名保引用，ID 不用序号。定配置即时／下次生成／新局生效；省 ORM／热更新。[研究]

**改定义也核已保存的实例结构与待执行工作。** 旧实例可能缺新配方队列，待执行调用也可能误用同 ID 的新逻辑。比较迁移、保留旧解释或退役旧定义另建 ID；迁移须可继续执行，明确损失和恢复条件；退回配置不等于恢复旧状态。见 [WP11 定义二改](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#定义二改能加载不代表旧实例仍匹配)。[一手／研究]

**加耐久／强化先定可互换性。** 材料用栈，装备单件状态或使用前拆件；跨操作追踪才加身份，耐久不必逐件 ID。[研究]

OpenMW 拆分曾丢实例数据，见 [WP11 物品](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#物品补研数量栈单件状态与转移身份)。[一手／研究]

## 5. 组件与 ECS：迁移热点，不迁移口号

**✅ 引擎组件管对象，普通类／函数管可测规则；CPU 预算失败后再迁热点。** 大群同构计算可比较局部 Jobs/Burst／ECS，渲染、蒙皮、碰撞、寻路先分别定位。此具体路线仅属 Unity，UE 共用定位成本的原则。[研究]

**AI 分工：** 可拆纯规则、局部批处理与测量脚手架；典型风险是只测 ECB 录制就误判收益；同玩法与设备计入同步、playback 和后续系统，比较整段帧成本。[研究]

**比较整段成本，而非样例局部计时。** 结构变更、同步与查询都有成本；ECB／enableable 及样例强制 Complete 的测量陷阱见研究。[一手]

V Rising 也记录适应成本，非单人全 ECS 依据。同玩法／设备比较总成本与二改工时，无对象数阈值。见 [WP11 ECS](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#4-组件jobsburstecs先用数据规模和预算选不用对象数口号选)。[一手／研究]

**加缓冲复用时，同改持久历史的所有权。** 逐帧返回的对象若会被下一步覆盖，撤销／存档不能只留引用。让 Agent 补独立快照与恢复清理，再继续模拟后撤销／重做，核历史未变；复制成本和历史上限也计入收益。必要时退回逐帧分配，保留已修正确性规则。见 [WP11 二改源码](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#近期-coding-agent-二改缓冲寿命与时钟信任)。[一手／研究]

## 6. 事件：命令有负责人，事实才广播

**✅ 局部调用，多观察者才用类型化事件。** 命令有负责人／结果，DamageApplied／EnemyDied 在提交后广播；明确时序、重入、丢弃政策。[研究]

**AI 分工：** 可实现类型化通知、订退阅及防重入；典型风险是回调重入导致重复奖励；让死亡回调再次触发同一结算，核奖励仍只提交一次。[研究]

晚加入 UI 读快照，必要时用操作身份拒绝旧事件。SO 通道属项目资产，换场景仍须退订；省字符串总线／完整事件溯源。见 [WP11 事件](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#5-事件用于传播已发生事实别把一次命令拆成无人负责的广播)。[一手／研究]

**区域任务需要响应对象进出时，保留任务持续期间的范围重选；只要指定对象时才展开固定队列。** 多单位分派仍须保住追加／替换、能力过滤与空筛选的语义，不能只统一手势。BAR 未合并候选的复测仍报吞命令／误派友军；这是单款 RTS 的取舍，不指定 Unity／UE 实现。见 [WP11 区域命令](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#区域命令补研持续任务还是固定对象队列)。[一手／社区／研究]

**连锁先防重入。** 检查合法后、重入前登记资格，失败按规则释放；明确派生伤害能否再反射。同步破坏未完成操作才延后到整次操作之后。[研究]

DCSS 的延后爆炸与 SPD／OpenRA 同步路线并存；排队不防环或保证顺序。见 [WP11 连锁](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#事件连锁补研排队不代替防重入与操作边界)。[一手／研究]

**预览按模式无副作用地查询规则，提交重验；连锁不精确就标估计。** 建造纠错先选撤回／反向订单，完整试演才评估回滚。反向订单可能等待重建，世界时间不退；副作用补偿不全就收窄撤销范围。恢复世界也抹不掉玩家已知信息。设置／连线撤销与补偿、信息边界见 [WP11 预览与撤销](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#命令预览补研提示清楚还要规则一致)。[一手／研究]

**需复现玩法序列时，纯表现随机单独拥有状态。** 沿生成器／RandomStream 分离表现与战斗；影响命中／障碍的仍属玩法。OpenRA／BrogueCE 支持分流，不保证跨版本／平台、物理或网络确定性，也不必每对象一流。见 [WP11 随机](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#随机所有权补研装饰二改是否改变玩法序列)。[一手／研究]

**回放先定用途。** 路线影子可用带时间的姿态与必要表现事件，不重做原物理／奖励；调试复演另核初始状态、输入时序和首次状态分歧；倒带续玩需足以恢复玩法的状态。旧轨迹能播不代表缺失字段成为真实历史，也不保证改图／改规则后仍有效。旧格式补零、改图失效及输入／状态取舍见 [WP11 回放](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#回放用途先分影子展示输入复演与状态倒带)。[一手／研究]

**AI 分工：** 可按用途实现姿态录制、输入复演或状态恢复；典型风险是把能播放当成恢复完整；影子核不改玩法状态，复演定位首次分歧，倒带后核可继续操作。[研究]

## 7. 战斗与技能：先统一结算，再决定 GAS

**✅ 请求→检查→启动／成本承诺→命中→伤害／效果提交→结束或取消，每步唯一结算所有者。** 动画可开命中窗口，取消／死亡／卸载后晚事件失效；表现不再扣血。Unity 沿定义＋实例＋组件，优先复用合规模块。[研究]

**AI 分工：** 可按阶段实现技能结算与取消清理；典型风险是旧动画出口释放新招的锁；打断后立即再施放并触发旧回调，核锁、标签与结算仍归正确执行实例。[研究]

**🧪 UE 的效果、属性、标签、费用／冷却或预测反复出现时评估 GAS。** 复杂单机也可适合；技能数／联网非门槛。[研究]

GAS 的 CommitAbility、取消、EndAbility 分开；未结束能力会继续阻挡动作，Per-Actor 复用须清成员。退款、冷却、已提交效果按玩法定；借效果核条件／消耗／目标，见 [构筑取舍](../../docs/research/2026-10-14-game-wp12-indie-roadmap.md#构筑补研同一效果的触发代价)。[一手／研究]

**控制权、阶段退出、再次攻击资格分别决定。** 响应差先试局部解锁移动／恢复段退出，保必要承诺。有网络需求才验预测。[研究]

**蓄力攻击先分按法识别、技能进度与释放。** 原生 Hold 的时长／触发规则满足玩法就继续用；攻速、耗能或局部慢动作需影响蓄力时，由既有技能状态计量，输入提供按住／松开意图。满蓄持有、自动释放、松开发射按招式选，动画沿约定窗口衔接。Hades II 历史更新与 Veloren 固定实现支持这些不同规则，不要求新框架。[一手／研究]

Unity Input System 1.17／UE 5.8 的触发与时间缩放限制见研究。UI 显示所承诺的进度，释放仍检查技能资格，不能只凭满格提交；系统取消也不能当松手发射。规则改变后原生识别不再吻合，才拆开计量。证据与未试玩范围见 [WP11 蓄力](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#蓄力技能补研按法识别技能进度与释放)。[一手／研究]

**淡出后不能出招，先查回调与占用。** 回调不一定覆盖所有退出，旧状态只释放自己的占用；UE 5.8／Unity 6.3 的具体版本契约与动画开关见研究。[一手]

全片完成、淡出交权、串接下一阶段须分别处理，片段退出不等于技能结束。Lyra 就绪／移除可借，多人底座不必整搬。见 [WP11 战斗](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#6-战斗与技能先统一结算权再谈-gas)。[一手／研究]

### 多来源效果：先定合并规则，再增加框架

**✅ 多来源退出只撤自己的授予。** 单来源且不重叠可用布尔值／计时器，严格配对用计数，需辨重复退出／来源才用句柄。离开可撤光环，已命中毒可独立持续；施放结束／来源死亡不自动终止目标效果。[研究]

**AI 分工：** 可实现来源句柄、叠加与属性重算；典型风险是一个来源退出撤掉其他来源效果；叠加两来源后撤一个，核剩余强度、期限与属性符合规则。[研究]

**合并另定**：取较长、刷新、延长、叠强度或独立计时，再定上限／驱散；显示表达实际规则；来源撤销与合并是不同语义。[一手／研究]

Unity 用角色自己的活效果集合，共享 SO 仅作定义；UE 已采用 GAS 就沿 StackingType 与到期策略配置，None 不等于“同类只留一个”。OpenRA／SPD 为 GPL-3.0-or-later，闭源勿默认复制。见 [WP11 叠加](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#效果叠加补研来源所有权不等于合并规则)。[一手／研究]

**持续效果定单位、首末跳、到期显示。** 回合沿行动调度，“几次攻击”消费有效行动，即时用模拟时间；输入次数不等于调度时间。效果调度与菜单暂停分别配置。[一手／研究]

只有设计要求冻结才暂停计时，恢复不补被冻结区间；菜单中继续冒险则继续推进。沿既有调度，变速后仍核到期与显示。见 [WP11 时钟](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#效果时钟补研调度时间行动次数与到期显示)。[研究]

**可撤销属性从基础值／有效集合重算，已发生 HP 变化另存。** 明定取值、加减／护甲、取整／限幅次序，初算重算一致，不反向加减恢复；最大 HP 对当前值影响另定。Wesnoth 重算曾改最大 HP；重算须保无关结果，明确顺序仍不保证任意组合。见 [WP11 重算](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#属性修饰补研计算顺序与重算)。[一手／研究]

**持续收益绑定当前装备／维持代价时动态读取；已承诺攻击或有意奖励窗口的字段保留快照。** 刷新时长／强度另定，需比较收益就显示旧强化。PoE 1.2.0 修订换装快照仍保生成等级；快照绕代价就收窄，动态读取破坏承诺则恢复该部分快照。见 [WP11 读取时点](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#效果读取时点持续代价与一次承诺)。[一手／研究]

### 选敌：先保意图，再调辅助

**✅ 持续攻击需定候选、保持、失效、改选。** 手动可选位置，自动候选可更窄，但保直接选择；最近／持续重选本是玩法则保留。[研究]

**AI 分工：** 可实现候选过滤、保持与主动切换；典型风险是自动重选覆盖玩家选择；让候选远近互换并主动改选，核目标保持和切换均符合输入意图。[研究]

目标保持、候选范围与手动瞄准均独立于自动开火。误选先修候选／保持。[一手／研究]

保持若阻碍主动改选就收窄；模式切回仍保合法选择。见 [WP11 选敌](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#选敌补研候选保持与主动切换)。[研究]

### 战斗质量：让玩家读懂承诺、接触与下一步

**✅ 先做好一招的前摇、接触、恢复，再增加招式。** 前摇交代方向，接触范围可信，恢复让下一步可预测；重武器可慢且不可随意取消，轻武器不靠每击长停顿装重量。[研究]

**AI 分工：** 可编排动作窗口、反馈与攻击许可并记录时序；典型风险是多敌叠招抹掉应对窗口；对照单敌与多敌回放核预告和危险重叠，再由人试玩判断是否仍有可用反制。[研究]

单人无美术修补时选可分段／重定时／程序化动作；缺起手／接触姿态就替换或简化，拖尾补不出姿态。依据见 [WP11 战斗质量](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#战斗质量补研动作节奏与遭遇可读性一起设计)。[一手／研究]

- **承诺可学习**：定转向／移动／闪避／连击窗口、命中与落空差异；动画未完可移动可能是设计，勿误删既有取消。[一手／研究]
- **组合可读**：轮廓、声、轨迹指同一危险，接触后看见下一威胁；场地／敌人组合已无解先减数量或改空间，必要时放弃复杂敌人。[一手／研究]
- **沿原生编排**：Unity 分开退出时点、混合与中断；UE 沿 Montage／Notify State 管区间，精确分支才评估 Branching Point。挥动声随动作，命中声／VFX 随确认结果；长混合可能淹没接触姿态。[一手／研究]

**围攻叠招才补共享许可，不默认轮流打。** 单招可读而叠加无反制时，先比较减敌、冷却错峰；需保留包围与选敌才限制特定攻击的并发。站位、积极参战与本次出招分开，冷却错峰不保证上限；许可声明占用区间和退出，退出归还，仍核飞行中弹体。排队空等或破坏群压价值就收窄／撤回。相反生产取舍见 [群体攻击比较](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#群体攻击协调资格站位与冷却分开)。[一手／研究；未运行验证]

**意图预告只承诺能确定的结果。** 计算攻防的玩法可显示下一步；会随玩家动作变化则显示条件结果并更新／撤销。排序／推移曾破坏预告，必要时缩承诺或简化规则；可有意保未知，错误显示却不是悬念。无决策需要不建完整模拟器。见 [WP11 意图](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#意图预告补研确定结果条件变化与有意未知)。[一手／研究]

**屏外威胁先判断缺信息还是缺应对时间。** 可获知的屏外目标可加标记；来不及躲就改入场／预告／弹速。反制需看起手时才限屏外起手，已发攻击另定；表现裁剪不意外改结算。见 [WP11 屏外](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#屏外威胁补研补信息还是改攻击)。[一手／研究]

**命中也负责阻止威胁时，先保住读招后的两条路径：抢断，或避开再反击。** [研究]

| 失败 | 优先改 | 保留的取舍 |
|---|---|---|
| 位移后辅助转向违背意图 | 收窄该情境候选／转向 | 保留主动换敌路径 |
| 打中却没打断，玩家误以为安全 | 核护甲／阶段规则、提示与结算 | 有意不可硬直的阶段保留 |
| 应对正确却接不上约定动作 | 核承诺和衔接出口 | 取消破坏风险收益就收回 |

高辅助挤占选择时核命中／对手应对／脱离风险，勿只减伤增重复。Overgrowth 同调辅助与 AI，无法分离贡献；玩家又报告窄场地挫败，故先核应对空间。辅助仍服务目标人群时保留。见 [WP11 组合取舍](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#组合取舍先修辅助规则还是动作出口)。[一手／社区／研究]

## 8. 相机：先让玩家看懂并控得住，再增加镜头语言

**✅ 先定信息与控制目标，再用固定镜头／简单跟随保落点、威胁和路线。** Unity 优先匹配版本的 Cinemachine，UE 优先原生相机，按目标补具体规则。[研究]

**AI 分工：** 可接原生相机、实现模式切换并记录轨迹；典型风险是重生后沿旧历史追镜头；重生并改变帧率，核立即取景与后续跟随符合约定，人判舒适度。[研究]

**高速穿行先定玩家需要看见与发现什么，再选导演构图或行进方向追随。** 地标／捷径的展示次序重要时保留受控构图；路线前方判断更重要时比较追随视角，不只加前瞻／阻尼。换视角会牵涉路线与场景内容，超出维护预算就缩范围或保留原构图。Lonely Mountains 同团队两部作品的取舍与返工见 [WP11 镜头](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#镜头质量补研从跟得上到看得懂控得住)。[一手／研究]

Unity Cinemachine 选择：[研究]

| 玩法 | 默认构图 | 何时调整／撤回 |
|---|---|---|
| 精确平台 | 固定房间或 Position Composer＋死区／边界；横纵分调 | 冲刺看不清再有界前瞻，落点不可见再下视；小跳不拖全背景，预测不绑抖动骨骼 |
| 俯视战斗 | 固定朝向、稳定尺度、有限跟随 | Boss／双目标试 Target Group＋Group Framing，限缩放；角色／预告过小就退回尺度或改遭遇 |
| 越肩／3D | Third Person Follow；瞄准需要时加 Third Person Aim | 窄角落先调层、半径与碰撞响应，无可用视线再改空间／遮挡；避免自动绕行替玩家瞄准 |

前瞻放噪声，平滑增滞后；Unity 6.0 渠道核实为 3.1.7，勿计入 3.1.8-pre.2 修复。见 [WP11 镜头](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#镜头质量补研从跟得上到看得懂控得住)。[一手／研究]

**Unity 遮挡分防穿墙与恢复视线。** 有可行视点且不夺瞄准时有限拉近／移位；固定朝向树冠可试局部显隐。Cinemachine 的碰撞／视线组件与材质显隐各有职责，排除遮挡判断不使材质透明，具体入口见研究。[一手／研究]

显隐保碰撞、掩体／落地边界、预告与退出恢复，轮廓只定位角色。无可行视点／材质例外过多就改几何；Project Zomboid 持续修 cutaway 是成本反证。见 [WP11 遮挡](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#2-三种玩法的不同默认不共享一套最佳参数)。[一手／研究]

### 本地多人：共享视图还是分屏

**✅ 先定独立活动与可读尺度，再选合分屏。** PixelWheels 改共屏后仍受大赛道缩小限制；BG3 后续因跨层地面淡出增加分屏条件。全员入镜不等于双方看得懂、控得住；缩小场地破坏玩法或动态切换反复干扰，就换路线／保固定分屏。取舍和二改验收见 [WP11 多人视图](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#本地多人视图独立活动与双方可读性先于自动合屏)。[一手／研究；未实测]

**AI 分工：** 可实现合分屏条件与每视口状态；典型风险是合屏后另一玩家的地面被隐藏；两人分处上下层再靠近，逐视口核地面、威胁与各自控制权。[研究]

### 建造／策略视图：先选支点，再调平滑

**✅ 缩放／旋转偏离建筑，先查支点与输入入口。** 鼠标可用光标，按钮用视口中心，选中对象另定；Tiny Glade 按设备区分支点。单点常误选才试区域推断，阻尼不修错目标。[一手／研究]

**AI 分工：** 可实现拾取、缩放／旋转支点与输入分流；典型风险是把滚轮支点套给按钮；同一建筑分别用滚轮和按钮操作，核支点符合各入口约定。[研究]

OpenRCT2 分别修多余高度拾取和按钮路径。加高塔／换视口与输入后验支点；滚轮不能代验按钮，二维修复不等于3D旋转算法。见 [WP11 支点](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#建造镜头补研旋转缩放支点与输入入口)。[一手／研究]

### Unreal：同样的可读性目标，不同的职责边界

**✅ UE 分开视点、防穿透、最终混合与控制／瞄准。** 相机朝向与控制朝向可不同，勿反写；SpringArm 防穿透不等于恢复视线。具体原生职责见下列研究。[一手／研究]

- **越肩**：肩位不得绕过碰撞探测。视点选目标，真实枪口核射线／弹体体积／弹道；受阻须显示并按规则结算，不能从相机发射穿掩体。[研究]
- **俯视**：保朝向、尺度、落地参照，可借 Top Down Strategy 屋顶开口；项目管对象／恢复，不复制受限 Unity 实现。[一手／研究]
- **新系统**：核实的 UE 5.8 Gameplay Cameras 仍为 Experimental，多套 rig／导演／过渡确能省编排时才试；Occlusion Material 节点不保证枪口合法或材质适配。[一手／研究]

契约与模板范围见 [WP11 UE 相机](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#unreal-相机补研同一遮挡问题的原生职责与新系统边界)。

### 两引擎共用的体验契约

**持续输入跨切镜仍可预测。** Celeste64 攀爬保留按住方向、松开重算，地面不必照搬；鼠标位移／摇杆速率分开，避免重复乘帧时间。[一手／研究]

**准星可见与枪口可达分别核。** Third Person Aim 的视差处理不替代枪口／弹道；装饰震动可与瞄准分离，有意后坐力是否影响瞄准另定。输入与瞄准来源见 [WP11 镜头](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#镜头质量补研从跟得上到看得懂控得住)。[一手／研究]

**切镜、可选效果和默认值分别决定。** 谜题可缓动，重生需立即取景时用切镜；战斗混合保落点与瞄准。震动、摆动、模糊、非必要回正应可减弱／关闭，视野和灵敏度按玩法开放，无通用舒适参数。[研究]

不适反馈下考虑稳定缺省＋易找开关；Endless Sky 保功能／旧设置而撤默认开：可关闭不等于宜默认开。见 [WP11 默认值](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#endless-sky非平台游戏的动感镜头与默认值取舍)。[一手／研究]

**历史先于阻尼。** 同目标平移可迁移历史保趋势，重生需立即取景则清历史，混合另选切镜／过渡。换目标、旋转及扩展不能套用位置迁移；Unity 版本限定 API 见历史与时钟研究。[研究]

**借出视图仍可维护历史。** 同目标移动时，SuperTuxKart 选择后台推进而非回切重建；只更新必要状态，失效／不值成本就重建。联网先查重演污染，再局部增减／停用平滑，保直接旋转响应。见 [WP11 借出历史](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#镜头借出控制持续更新历史与当前视点分开)。[一手／研究]

**每视口一个输出者，时钟匹配目标运动。** 模式定优先级／历史／退出，技能只请求效果。查插值叠平滑滞后；同冻保历史，菜单运镜另定时钟，IgnoreTimeScale 不制造固定更新。[研究]

指数阻尼／substepping 不保证跟随帧率无关。变帧率／步长、暂停、重生／取消验屏幕位置与滞后；柱／树冠验瞄准、落点、恢复。AI 记轨迹，人判舒适；旧 UE 问题未作当前复测。见 [WP11 历史与时钟](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#跟随历史补研瞬移换目标与变帧率)。[一手／研究]

## 9. 关卡：先能重置遭遇，再扩成大世界

**✅ 关卡定义管稳定内容，Encounter 管本次遭遇与一次奖励，存档管跨关完成。** ready 区别于加载完成，退出须清理。[研究]

**AI 分工：** 可实现遭遇重置、任务条件与布局校验；典型风险是重进或重放完成事件重复发奖；从已完成检查点重进并重放事件，核任务可继续且奖励只发一次，教学与遭遇节奏由人试玩。[研究]

保存数据而非运行实例，seed 须伴生成器版本；小房间省大世界分区／编辑器。见 [WP11 关卡基线](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#8-关卡先做可重置的遭遇再做大世界)。[研究]

**整套二改先保可维护源，不先换编辑器。** 二维批改可试 LDtk／Tiled 语义源＋规则；新能力可能迫使重做旧布局，铺砖自动化不替教学与进度设计。AI查跨关依赖／派生同步，人验节奏；特例手补过多就缩小覆盖。见 [WP11 整套二改](../../docs/research/wp11-camera.md#整套关卡二改可编辑源不替代战役设计)。[研究；未实测]

**任务分历史与当前条件。** 交付／解锁可永久，携物／位置／目标查现状；先探索后接取须认可已有成果。Flare 入仓后补查持有是反例；持续携物／占领保可逆条件。见 [WP11 任务](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#任务推进补研历史事实与当前条件)。[一手／研究]

**空间按玩法选。** 稳定动作空间用有用途、许可清晰的房间；地形／绕行／逃生是玩法则用受约束布局。连通后仍核压力／喘息、资源与应对空间，自动通过不证明好玩。[一手／研究]

每局都清无挑战残敌时，先查完成后离开是否损失必需成长，再加房间。可借 Rogue Legacy 成长时机／Into the Breach 胜利条件；清场有趣则保留，新条件只拖时间／跳好战斗就撤回。见 [WP11 组合](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#关卡组合补研连通之后还要选择什么)。[一手／研究]

**教学验主动使用，而不只验按提示完成。** 复杂组合可借 Factorio 情境推荐／回查，自主探索借 Outer Wilds 可选练习。按真实误解／熟悉度教学，必需知识给机会，谜题答案留探索。[一手／研究]

改用途后验无逐步指令下的主动选择；行为次数只减打扰，不证明掌握。见 [WP11 学习](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#学习迁移补研按提示完成之后会不会主动使用)。[研究]

**高频失败先减无意义等待／重走，再降难度。** 只为回看已获线索而重走，可先保留可回看材料。查死亡演出／重建／交权成本，检查点给反馈，沿原生命周期重试。Celeste64 仍重建 World，局部重置须有成本依据；永久死亡／资源消耗／整局承诺是玩法时保留代价。见 [WP11 重试](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#失败与重试补研回到刚才的决策点)。[一手／研究]

**辅助按受阻环节与目标选。** 已有信号可达表达沿[客户端设置](04-client-modules.md#信号取舍减掉演出后仍看得懂下一步)，揭露未知信息属于规则选择。单项负担用局部调整，协调资源／探索压力用整局预设，全局降速也可有意提供。[一手／研究]

明确当局／下局生效、关闭恢复什么、进度／计分怎样处理。Dead Cells 关闭后的子项残留反证须验恢复；较易不证明掌握标准模式或各区域等比例变易。见 [WP11 辅助](../../docs/research/2026-10-14-game-wp11-gameplay-architecture.md#辅助取舍补研局部调整整局预设与切回规则)。[一手／研究]

## 11. 给 AI 第二次修改的最小契约

提供代码、包版本、资产／节点、回归夹具与六点契约：[研究]

1. 定义与运行实例分离，谁创建、复用和销毁
2. 状态属于项目、存档、Session、场景、角色还是一次施放；使用哪个时钟
3. 谁提交伤害、奖励、库存；谁只观察；事件同步还是排队
4. 正常结束、取消、死亡、卸载、池回收分别清理什么
5. 内容 ID、序列化字段和旧存档怎样保持或迁移
6. 项目改造了哪些依赖，哪些时序必须保留

**统一二改验收：冲刺攻击加蓄力、受击中断、按承诺扣资源、检查点重开。** 在正常、取消、死亡、卸载、池回收与重开后，核实例隔离、一次结算、旧回调失效和资源清理；再核存档迁移及目标设备成本。镜头与关卡须保可读性和控制权。各节 WP11 链接保留具体测试情境；记改动、工时与失败，AI 测契约／记轨迹，人判手感与舒适度。[研究]

释放／存档／预算见[客户端模块](04-client-modules.md)，试玩方法见[验证页](02-verification-and-playtesting.md)。
